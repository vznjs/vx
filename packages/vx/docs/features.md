# Every feature

Every user-facing feature of vx, one line each, grouped by what it is
for. Each line names its surface (verb, flag, config key, plugin).

It links the feature's docs page when it has one, and its blog post, or
says "no post".

**Rule:** a change that adds or changes a user-facing feature updates
this file, and its post, in the same commit (`CLAUDE.md`).
`tests/features-inventory.unsafe.test.ts` fails when a CLI verb, a flag, a
config key or an environment variable is missing here.

## Run

- **Run a task** (`vx run`) — run a task in the cwd's project, `pkg#task` directly, or several at once. [docs](https://vznjs.github.io/vx/quickstart/) · post: [The basics, done carefully](https://vznjs.github.io/vx/blog/the-basics/)
- **Every project** (`--all`) — run the task in every project that declares it. [docs](https://vznjs.github.io/vx/quickstart/) · post: [The basics, done carefully](https://vznjs.github.io/vx/blog/the-basics/)
- **pnpm-style filters** (`--filter`) — select projects by name, glob, path, dependencies (`foo...`), dependents (`...foo`), negation or a git range. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Affected only** (`--affected`, `baseBranch`, `VX_BASE_BRANCH`, `VX_AFFECTED_BASE`) — run what a change reaches, following the task edges keys fold (`inputs.tasks`) from a git base: `VX_AFFECTED_BASE`, else a plugin's base commit, else the merge base with the base branch; none on it. A shallow clone fetches only the base and the commits down to the merge base, no blobs. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [Run only what a change reaches](https://vznjs.github.io/vx/blog/affected/)
- **Concurrency** (`--concurrency`, `run.concurrency`, `VX_RUN_CONCURRENCY`) — a count or a share of the CPUs this process may use (`50%`). [docs](https://vznjs.github.io/vx/cli/run/#flags) · post: [One failure, and exactly what it takes down](https://vznjs.github.io/vx/blog/when-a-build-fails/)
- **Skip dependencies** (`--exclude-dependencies`) — skip all `dependsOn` edges, or named ones. [docs](https://vznjs.github.io/vx/cli/run/) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Fail fast** (`--fail-fast`, `run.failFast`, `VX_RUN_FAIL_FAST`) — the first failure kills the running tasks and stops the run; without it a failure skips only its dependents. [docs](https://vznjs.github.io/vx/cli/output/) · post: [One failure, and exactly what it takes down](https://vznjs.github.io/vx/blog/when-a-build-fails/)
- **Every skip names its blocker** — a task skipped behind a failure says which failure blocked it; a platform skip names the platform it needs. [docs](https://vznjs.github.io/vx/cli/output/) · post: [One failure, and exactly what it takes down](https://vznjs.github.io/vx/blog/when-a-build-fails/)
- **Retries** (`--retries`, `exec.retries`, `run.retries`, `VX_RUN_RETRIES`) — re-run a failed task; a pass after a failure marks it flaky, and a task known flaky gets one retry with none set. [docs](https://vznjs.github.io/vx/cli/info/) · post: [Only declared inputs can prove a task flaky](https://vznjs.github.io/vx/blog/flaky-tasks/)
- **Timeouts** (`--timeout`, `exec.timeout`, `run.timeout`, `VX_RUN_TIMEOUT`) — kill and fail a runaway task. [docs](https://vznjs.github.io/vx/schema/) · post: [When a task misbehaves](https://vznjs.github.io/vx/blog/tasks-that-misbehave/)
- **Kill grace and plugin timeout** (`run.killGrace`, `run.pluginTimeout`; `VX_RUN_KILL_GRACE`, `VX_RUN_PLUGIN_TIMEOUT`) — how long a process gets after SIGTERM before SIGKILL, for a timeout, Ctrl-C or a dev server's stop (default `'2s'`), and how long one plugin's end-of-run flush or teardown may take (`'3s'`). no post
- **Output kept** (`run.logs.captureHead`, `run.logs.captureTail`, `run.logs.failedHead`, `run.logs.failedTail`, `run.secrets.minLength`; `VX_RUN_LOGS_CAPTURE_HEAD`, `VX_RUN_LOGS_CAPTURE_TAIL`, `VX_RUN_LOGS_FAILED_HEAD`, `VX_RUN_LOGS_FAILED_TAIL`, `VX_RUN_SECRETS_MIN_LENGTH`) — how much of a task's output vx keeps with its cache entry (`'8MiB'` of the start and of the end) and with a stored failure (`'8KiB'`, `'56KiB'`), and the shortest env value it masks as a secret (6). no post
- **Watch timing and history retention** (`watch.debounce`, `watch.pollInterval`, `history.retention`; `VX_WATCH_DEBOUNCE`, `VX_WATCH_POLL_INTERVAL`, `VX_HISTORY_RETENTION`) — how long `vx watch` waits after the last change (`'150ms'`), how often a polling watch re-walks (`'250ms'`), and how much run history `vx cache clean` keeps (`'30d'`). no post
- **Argument forwarding** (`--`) — args after `--` reach one task's command (one task in one project: refused with `--affected`, several tasks, or a `--all` / `--filter` run that asks for the task in several projects) and go into its key. [docs](https://vznjs.github.io/vx/cli/run/) · post: [When a task misbehaves](https://vznjs.github.io/vx/blog/tasks-that-misbehave/)
- **Task picker** — `vx run` with no task in a terminal lists tasks to pick. [docs](https://vznjs.github.io/vx/cli/run/) · post: [The small things](https://vznjs.github.io/vx/blog/the-small-things/)
- **Typo hints** — an unknown task, project or filter suggests the nearest name. [docs](https://vznjs.github.io/vx/cli/run/#filter-dsl---filter) · post: [The small things](https://vznjs.github.io/vx/blog/the-small-things/)
- **Ctrl-C leaves nothing running** — the whole process tree stops, then teardown runs. [docs](https://vznjs.github.io/vx/execution/) · post: [Ctrl-C leaves nothing running](https://vznjs.github.io/vx/blog/ctrl-c/)
- **Longest path first** — the scheduler starts the critical path first; `@vzn/vx-history` learns it from past runs. [docs](https://vznjs.github.io/vx/docs/writing-plugins/#keys-and-order) · post: [Bitsets, popcount, and a scheduler tick](https://vznjs.github.io/vx/blog/bitsets-and-the-scheduler/)
- **Schedule strategy** (`--schedule`, `run.schedule`, `VX_RUN_SCHEDULE`) — pick the order with no timings: most work waiting (default), longest path, most direct dependents, or ready order; plugins still lead. [docs](https://vznjs.github.io/vx/docs/writing-plugins/#keys-and-order) · post: [Which task runs first?](https://vznjs.github.io/vx/blog/scheduling-strategies/#pick-the-guess)
- **No daemon** — every run starts cold and still answers in milliseconds. [docs](https://vznjs.github.io/vx/concepts/why-vx-is-fast/) · post: [No daemon, on purpose](https://vznjs.github.io/vx/blog/no-daemon/)
- **Group tasks** (`dependsOn` with no `exec`) — a task that only runs its dependencies; `dependsOn: []` is a named no-op. [docs](https://vznjs.github.io/vx/docs/workspace/) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Keyed groups** (`inputs` with no `exec`) — a key its dependants include: it re-runs on those inputs, and nothing spawns or counts for the group. [docs](https://vznjs.github.io/vx/docs/workspace/) · post: [A key with nothing to run](https://vznjs.github.io/vx/blog/keyed-groups/)
- **Implicit keyed `build`** — a project with no `build` gets a `^build` group keyed on its files, so source-only packages still move their dependants' keys. [docs](https://vznjs.github.io/vx/caching/) · post: [The basics, done carefully](https://vznjs.github.io/vx/blog/the-basics/)
- **dependsOn syntax** (`^name`, `pkg#name`, `name.*`, `^name.*`) — upstream, cross-project and pattern edges; `^` follows the project edges a plugin supplies, and with none is refused naming the fix. [docs](https://vznjs.github.io/vx/schema/) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Every name must resolve** — `vx run lint test e2e` refuses to start if one name matches no project. [docs](https://vznjs.github.io/vx/cli/run/) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Tag filters** (`--filter tag:<pattern>`) — select projects by their config `tags`. [docs](https://vznjs.github.io/vx/cli/run/#filter-dsl---filter) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Directory and root filters** (`./<dir>`, `{<dir>}`, `<pattern>{<dir>}`, `.`, `//`) — select projects by path, a name within a path, or the root project. [docs](https://vznjs.github.io/vx/cli/run/#filter-dsl---filter) · post: [Say exactly which tasks to run](https://vznjs.github.io/vx/blog/pick-your-tasks/)
- **Executor pools** (executor `capacity`) — a remote pool is scheduled against its own width, not the laptop's cores. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [Remote execution without moving the scheduler](https://vznjs.github.io/vx/blog/remote-execution/)
- **Runs take turns** — two vx runs on one workspace wait on a lock and name who they wait for. [docs](https://vznjs.github.io/vx/execution/) · post: [When a task misbehaves](https://vznjs.github.io/vx/blog/tasks-that-misbehave/)

## Output

- **Framed output** — each task's log in its own frame, never interleaved. [docs](https://vznjs.github.io/vx/cli/output/) · post: [A run you can read](https://vznjs.github.io/vx/blog/a-run-you-can-read/)
- **Output modes** (`--output-logs`, `VX_RUN_OUTPUT_LOGS`) — full, errors-only, hash-only or none; the default follows the flow. [docs](https://vznjs.github.io/vx/cli/run/) · post: [Output that fits the run](https://vznjs.github.io/vx/blog/output-that-fits-the-run/)
- **Run summary** — one block: projects, tasks, cache (with the bytes each remote hit pulled and each upload pushed), the run id `vx last` opens, time; nothing prints below it. [docs](https://vznjs.github.io/vx/cli/output/) · post: [A run you can read](https://vznjs.github.io/vx/blog/a-run-you-can-read/)
- **Per-task table** (`--verbosity`) — a per-task summary after the run. [docs](https://vznjs.github.io/vx/cli/run/) · post: [One failure, and exactly what it takes down](https://vznjs.github.io/vx/blog/when-a-build-fails/)
- **Failed output kept for agents** — a failure's full log is saved and pointed to. [docs](https://vznjs.github.io/vx/cli/last/) · post: [Built for the agent at the keyboard](https://vznjs.github.io/vx/blog/built-for-agents/)
- **Trace profile** (`--profile`) — Chrome-trace JSON of the run, with each executor's own events (`@vzn/vx-dte`: every worker's tasks on their own lanes). [docs](https://vznjs.github.io/vx/cli/run/#run-artifacts---profile) · post: [Output that fits the run](https://vznjs.github.io/vx/blog/output-that-fits-the-run/)
- **Run branch** (`--branch`, `VX_RUN_BRANCH`) — name the branch a run records in its history and forecasts from; unset, git's branch, then the CI provider's. no post
- **Stage timing** (`VX_DEBUG_TIMING`) — vx's own stage table, for performance work. [docs](https://vznjs.github.io/vx/benchmarks/) · post: [See inside a run](https://vznjs.github.io/vx/blog/see-inside-a-run/)
- **Output flows** — what is printed follows the run's intent (focused, broad or CI); any CI variable on (`CI`, `GITHUB_ACTIONS`, `JENKINS_URL`…) wins. [docs](https://vznjs.github.io/vx/cli/run/) · post: [Output that fits the run](https://vznjs.github.io/vx/blog/output-that-fits-the-run/)
- **Status and cache words** — each task line starts with its status word, coloured by outcome (success, failed, skipped, running, aborted, not run), then its cache word (miss, no-cache, fresh, local, remote). [docs](https://vznjs.github.io/vx/cli/run/) · post: [Output that fits the run](https://vznjs.github.io/vx/blog/output-that-fits-the-run/)
- **GitHub Actions log groups** — on Actions, with full output (`--output-logs full`), each task's block collapses in a `::group::` with its outcome and time. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [The basics, done carefully](https://vznjs.github.io/vx/blog/the-basics/)
- **One UI kit** (`ui` from `@vzn/vx`) — every line vx and its plugins print is built from one fixed set of components: panels (an underlined title line and its lines, no box) stacked like a TUI but written into the scrollback, coloured the same on CI. [docs](https://vznjs.github.io/vx/cli/output/) · no post
- **Colors** (`NO_COLOR`, `FORCE_COLOR`) — truecolor output, forced on or off by env; on any CI the piped log is coloured too; `TERM=dumb` prints plain, with no live region. [docs](https://vznjs.github.io/vx/cli/run/) · post: [The basics, done carefully](https://vznjs.github.io/vx/blog/the-basics/)
- **Signal-named exits** — a failure reads `exit 137, 128 + SIGKILL`. [docs](https://vznjs.github.io/vx/docs/tasks/#5-handle-failures-and-hangs) · post: [When a task misbehaves](https://vznjs.github.io/vx/blog/tasks-that-misbehave/)
- **vx's own steps as rows** — on a terminal, what vx does around the tasks (`vx:uploads`, `<plugin>:teardown`) shows as a running row once it passes 150 ms, then a list row marked `internal`, only when the run waits on it (`vx:prefetch` runs beside the tasks and is listed by `vx last` alone); never counted as a task. no post
- **Plain output off a TTY** — no live region, and a missing task lists tasks instead of opening the picker. [docs](https://vznjs.github.io/vx/cli/run/) · post: [The basics, done carefully](https://vznjs.github.io/vx/blog/the-basics/)

## Cache

- **Opt-in, explicit inputs** (`inputs.files`) — a task is keyed on the inputs it names, cached or not; one with none has no key, so every task behind it misses. A gitignored path named outright (`.env.local`, `dist/**`) is an input, hashed from disk and never stored; broad globs still skip ignored files, and `vx lock` and a miss name an ignored file a glob's last segment matches (`.env*` over `.env.production.local`); `vx lock` also names a cached task's `passThrough` name a bundler inlines (`VITE_API_URL`) that `inputs.env` leaves out. [docs](https://vznjs.github.io/vx/caching/) · post: [Explicit over magical](https://vznjs.github.io/vx/blog/explicit-over-magical/)
- **Inputs** (`inputs.env`, `inputs.runtime`, `inputs.tasks`, `inputs.workspaceFiles`, `inputs.workspaceRuntime`) — env vars, tool versions, upstream tasks and workspace files in the key. [docs](https://vznjs.github.io/vx/caching/) · post: [What goes into a key, and what comes back](https://vznjs.github.io/vx/blog/inside-a-cache-hit/)
- **Outputs** (`outputs.files`, `outputs.workspaceFiles`) — what a hit restores; every literal output path is required and a task must write at least one output, so a run that misses either after exit 0 fails and nothing is cached, while a wildcard may match nothing beside one that matched; an uncached task declares them too, for what its dependants read. [docs](https://vznjs.github.io/vx/caching/) · post: [What goes into a key, and what comes back](https://vznjs.github.io/vx/blog/inside-a-cache-hit/)
- **Input stability** (`inputs.stability`, workspace `inputs.stability`, `VX_INPUTS_STABILITY_STRATEGY`, `VX_INPUTS_STABILITY_SEVERITY`) — an input written while the command runs withholds the save, on CI too, and the saves of every task that ran over its outputs; `strategy: 'mutable'` accepts a task's identical rewrite of its own input, `'unchecked'` skips the check; `severity: 'error'` fails the run instead of warning. no post
- **Keep outputs on a miss** (`outputs.clean`, workspace `outputs.clean`) — `false` leaves a task's outputs in place for a tool that reads its last output (tsc's `.tsbuildinfo`) and caches everything the outputs then hold, leftovers included (an opt-out of the clean-tree guarantee). no post
- **Outputs are exactly the snapshot** (`run.rules.exclusiveOutputs`, `VX_RUN_RULES_EXCLUSIVE_OUTPUTS`) — a hit leaves the tree as the run did; two tasks may not own one output without an edge. [docs](https://vznjs.github.io/vx/caching/) · post: [The tree is exactly the snapshot](https://vznjs.github.io/vx/blog/strict-output-ownership/)
- **Keys from git's index** — tracked clean files hash by their blob id, no read. [docs](https://vznjs.github.io/vx/concepts/why-vx-is-fast/) · post: [Your cache key is already in git's index](https://vznjs.github.io/vx/blog/keys-from-git/)
- **Config keyed as evaluated** — the key sees the resolved config object. [docs](https://vznjs.github.io/vx/docs/workspace/) · post: [Configs are programs](https://vznjs.github.io/vx/blog/resolved-config-hashing/)
- **Cascade through inputs** — a task's key includes its upstream input keys, never outputs. [docs](https://vznjs.github.io/vx/caching/) · post: [Cascade through dependencies](https://vznjs.github.io/vx/blog/cascade-through-inputs/)
- **Lockfile-aware keys** (`@vzn/vx-lockfile`: `bun()`, `pnpm()`, `npm()`, `yarn()`) — a bump re-keys only the projects whose closure changed; each also adds every member with a manifest (`package.json`; under `pnpm()` also `package.json5` or `package.yaml`) as a project named by its `name`, gives vx the project edges the lockfile records (core reads no `package.json`), keys each package's manifest as an input and adds its manager's install settings (`.npmrc`, `bunfig.toml`, `pnpm-workspace.yaml`, `.yarnrc.yml`, `.yarnrc`) into every task. Core keys no package file, so without one an install re-keys nothing; `npm()` reads `npm-shrinkwrap.json` first, `bun()` refuses a lone `bun.lockb`, a run refuses while `node_modules` is not the install the lockfile names (a `git pull` with no install), naming the package and the install that fixes it (`bun install`), and `vx lock` refuses a lockfile older than the manifests (a workspace or a workspace dependency it does not list yet, or a dependency on a workspace no longer on disk), and under `pnpm()` a lockfile per package (`sharedWorkspaceLockfile: false`), naming the setting. [docs](https://vznjs.github.io/vx/docs/lockfiles/) · post: [A lockfile bump should re-key two tasks](https://vznjs.github.io/vx/blog/lockfile-aware-keys/)
- **Upfront keys** (`vx lock`, no opt-out) — refuses an input glob another task's outputs could match, so every key is known before anything runs; only a dependency the key does not include (left out of `inputs.tasks`) may be read, its bytes hashed after it ran. [docs](https://vznjs.github.io/vx/schema/) · post: [Cascade through dependencies by folding input keys, never outputs](https://vznjs.github.io/vx/blog/cascade-through-inputs/)
- **Dependency rules** (`run.rules.dependencies`) — `vx lock` refuses a project depending on one a tag or name rule denies or does not allow, every broken edge named (`VX_E_DEPENDENCY_RULE`). [schema](https://vznjs.github.io/vx/schema/) · post: [Say which projects may depend on which](https://vznjs.github.io/vx/blog/dependency-rules/)
- **Cache controls** (`--no-cache`, `--force`, `--cache-policy`, `--cache-policy`, `VX_CACHE_POLICY`, `cache.policy`) — off, re-run past it, or per-layer read/write. [docs](https://vznjs.github.io/vx/cli/run/) · post: [The cache on your terms](https://vznjs.github.io/vx/blog/the-cache-on-your-terms/)
- **Cache location** (`--cache-dir`, `cache.dir`, `VX_CACHE_DIR`) — where the cache lives; one this user cannot write still serves its hits. [docs](https://vznjs.github.io/vx/cli/run/) · post: [The cache on your terms](https://vznjs.github.io/vx/blog/the-cache-on-your-terms/)
- **Branch cache scope** (`VX_CACHE_SCOPE`) — the scope plugins key their own entries under (`ctx.cache`, run records), `<owner>/<repo>:<branch>`, named by a plugin or derived from `.git`; task keys never carry it and the local cache never knows it. [docs](https://vznjs.github.io/vx/docs/remote-cache/#cache-scopes-and-tokens) · post: [Branch caches a server enforces](https://vznjs.github.io/vx/blog/branch-caches-a-server-enforces/)
- **Cache pruning** (`vx cache clean`, `--older-than`, `--max-size`, `--global`, `--dry`) — evict by age or size, LRU, only when asked: no run evicts; with no bound, clear this workspace's store (shared by its checkouts) and run history; `--global` clears every workspace's store. [docs](https://vznjs.github.io/vx/cli/cache/) · post: [One command to know your workspace](https://vznjs.github.io/vx/blog/know-your-workspace/)
- **Remote outputs** (`--cache-download`, `cache.download`, `VX_CACHE_DOWNLOAD`) — all, top-level only, or none. [docs](https://vznjs.github.io/vx/cli/run/) · post: [A remote server you can trust in production](https://vznjs.github.io/vx/blog/reapi-in-production/)
- **Cache transfer limits** (`cache.concurrency.download`, `cache.concurrency.upload`, `cache.concurrency.restore`; `--cache-concurrency-download`, `--cache-concurrency-upload`, `--cache-concurrency-restore`; `VX_CACHE_CONCURRENCY_DOWNLOAD`, `VX_CACHE_CONCURRENCY_UPLOAD`, `VX_CACHE_CONCURRENCY_RESTORE`) — remote downloads, uploads per remote and local restores at once. no post

## Correctness

- **Sandboxed tasks** (`exec.sandbox`: `allow`, `deny`, `hermetic`, `ignore`, `weakerNetworkIsolation`, `weakerWhenNested`) — a task reads and writes only what it declares; `allow` names `read`, `write`, `network`, `unixSockets`, `localBinding`, `pty`, `systemInfo`, `gitConfig`, `machLookup`; `network: ['localhost:4173']` reaches a server on this machine (an e2e's dependency). [docs](https://vznjs.github.io/vx/docs/sandboxing/) · post: [The sandbox](https://vznjs.github.io/vx/blog/the-sandbox/)
- **Env isolation** (`exec.env`: `define`, `passThrough`, `secret`, `VX_DEBUG_DUMPABLE`) — a task sees only the env it names; secrets are masked; vx hides its own env from tasks (Linux and macOS). [docs](https://vznjs.github.io/vx/schema/) · post: [A task sees only the env it names](https://vznjs.github.io/vx/blog/env-isolation/)
- **vx lock** (`vx lock`, `--check`, `--format json`, `lock.reviewFiles`, `VX_LOCK_REVIEW_FILES`) — find the projects (every directory holding a `vx.config`), freeze what their configs evaluate to, and what a plugin's `project` stage (`turbo()`, `nx()`) maps them to, and check the graph rules once; only `vx lock` evaluates configs or maps: runs, `vx show` and `vx info` read the lock and never write it, and a config file edited since this machine's `vx lock` refuses them with "run `vx lock`"; a pretty `vx.lock.json` beside each config shows reviewers what it resolves to; `.vx/dependencies.lock` records each project's edges and lockfile digests: runs key from them, checked against the lockfile through a memo (digests that moved since refuse until `vx lock`), and `--affected` reads the base's; both locks give each name a line of its own and projects.lock names each task by a hash of its config, so git merges branches that changed different projects, the same configs lock to the same text, and a clash refuses runs until `vx lock` rewrites both. [docs](https://vznjs.github.io/vx/cli/lock/) · post: [vx lock: freezing what the key sees](https://vznjs.github.io/vx/blog/lock-and-frozen/)
- **Flaky detection** — a task whose key fails after it passed is reported flaky, judged on every worktree's record of the workspace, or every CI machine's through a history server, and retried once when it fails. [docs](https://vznjs.github.io/vx/cli/info/) · post: [Only declared inputs can prove a task flaky](https://vznjs.github.io/vx/blog/flaky-tasks/)
- **Project boundaries** — globs never cross into another project. [docs](https://vznjs.github.io/vx/caching/) · post: [What goes into a key, and what comes back](https://vznjs.github.io/vx/blog/inside-a-cache-hit/)
- **Artifact integrity checks** — a CRC-32, a key match and an outputs-only check on every artifact; damage is a miss. [docs](https://vznjs.github.io/vx/caching/) · post: [What goes into a key, and what comes back](https://vznjs.github.io/vx/blog/inside-a-cache-hit/)
- **Read what you depend on** — a sandboxed task reads the declared outputs of the tasks its key folds through `dependsOn`, in any project, never their sources: one `tools` project serves a toolchain to every other. [page](https://vznjs.github.io/vx/docs/sandboxing/)
- **Sandbox names what to grant** — a refused write is named beside the failed task with the path to allow. [docs](https://vznjs.github.io/vx/docs/sandboxing/) · post: [Guard rails that tell you the fix](https://vznjs.github.io/vx/blog/guard-rails/)
- **Refused reads reported with no tracer** (`VX_DEBUG_STRACE`) — on Linux vx's own observer, a seccomp listener in the binary, reports what the sandbox refused: no `strace` to install, no ptrace stop per call; `VX_DEBUG_STRACE=1` reports with strace instead, as a kernel before 5.5 does. [page](https://vznjs.github.io/vx/docs/sandboxing/)
- **Strict numeric flags** — `0x10`, `1e3` and `2.7` are refused, never reinterpreted. [docs](https://vznjs.github.io/vx/cli/run/) · post: [An upgrade you can trust](https://vznjs.github.io/vx/blog/upgrade-you-can-trust/)
- **Verified releases** — binaries carry provenance, `vx upgrade` checks npm's registry signature and the SHA-512, read from the registry your `.npmrc` or bunfig names, npm publishes with provenance. [docs](https://vznjs.github.io/vx/docs/upgrading/) · post: [An upgrade you can trust](https://vznjs.github.io/vx/blog/upgrade-you-can-trust/)

- **REAPI verified downloads and deadlines** — a corrupt blob or a wedged server degrades to a miss, never a hang. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [A remote server you can trust in production](https://vznjs.github.io/vx/blog/reapi-in-production/)
- **Install as a remote action** (`exec.remote: 'only'`) — `node_modules` is built by an action, so stateless workers have it. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [Remote execution without moving the scheduler](https://vznjs.github.io/vx/blog/remote-execution/)
- **OTel live export** (`otel({ live })`) — spans and metrics stream as tasks end, so a dashboard follows a CI run live. [docs](https://vznjs.github.io/vx/docs/ci/) · post: [Watch a CI run while it runs](https://vznjs.github.io/vx/blog/otel-live/)
- **Memory-aware admission** (`@vzn/vx-history`) — tasks are packed by the peak memory learned from past runs. [docs](https://vznjs.github.io/vx/docs/plugins/) · post: [A scheduler that learns from your runs](https://vznjs.github.io/vx/blog/a-scheduler-that-learns/)
- **CI timings file** (`@vzn/vx-history`, `file`) — one JSON file of learned task times a CI cache carries between runners, so a fresh runner orders by real times. [docs](https://vznjs.github.io/vx/docs/writing-plugins/#keys-and-order) · post: [Carry the scheduler's memory between CI runners](https://vznjs.github.io/vx/blog/ci-timings-file/)
- **Plugin entries** (`ctx.cache`) — a plugin keeps its own small entries in the workspace's caches, local and remote, a branch's under its scope. no post
