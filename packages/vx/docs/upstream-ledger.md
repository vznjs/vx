# Upstream bug ledger

Real Turborepo and Nx bug reports in vx's scope, each checked against vx
and held by a test. The survey (2026-09-24) read the two trackers for
stale cache hits, key instability, restore and save faults, graph and
filter errors, signal and teardown bugs, watch and output faults, and
remote-cache failures, then asked of each: does vx have it, and would a
test notice if it came back? Where no test would, one was written
(item 744); where vx had the bug, it was fixed and the fix's tests are
cited here.

A row is one upstream report, or a few that report one fault. Its
verdict is one of:

- **covered**: the cited tests would fail if vx had the bug. Rows the
  survey found untested say "written for this ledger".
- **n/a**: the bug cannot occur in vx; the note says why. A test is
  cited where one pins the reason.
- **fixed-in-item-N**: vx had the bug; STATUS item N fixed it, and its
  tests are cited. A fix pinned only by a template-titled loop, which
  the law cannot cite, names the loop in the note.
- **open (id)**: vx has the bug and the fix is not in yet; the id names
  it: `new:` for a fault writing the ledger found, `limit:` for a
  documented limit and what blocks its fix.
- **untested**: vx behaves correctly but no test holds it; the note
  says why none was written.

Every citation is `file › "title"`, the file relative to the repository
root and the title exactly as written in the test.
`tests/upstream-ledger.unsafe.test.ts` parses both tables and fails when
a cited title is not an `it(…)` or `test(…)` title in that file, or when
a covered row cites nothing, so a renamed or deleted test cannot leave a
row claiming a pin it lost.
