Cache your first task in two minutes, in a repo you already have.

<Aside title="What you need">
  Git, and macOS or Linux with glibc (not Alpine's musl). On Windows, use WSL2.
</Aside>

<Steps>

1. **Set up vx**

   Run this at the root of your git repository:

   <Tabs syncKey="pm">
     <TabItem label="npm">
       ```sh
       npx @vzn/vx init
       ```
     </TabItem>
     <TabItem label="Bun">
       ```sh
       bunx @vzn/vx init
       ```
     </TabItem>
   </Tabs>

   `init` installs `vx` on your machine and in the repo, and writes an
   empty `vx.config.ts` at the root. A Turborepo or Nx repo gets its tasks
   from `turbo.json` or the Nx graph instead.

2. **Add a task**

   Give `vx.config.ts` a `build` task: its command, the files it reads,
   and the files it writes.

   ```ts title="vx.config.ts" ins={5-9}
   import { defineProject } from '@vzn/vx'

   export default defineProject({
     tasks: {
       build: {
         exec: { command: 'npm run build' },
         inputs: { files: ['src/**'] },
         cache: { outputs: { files: ['dist/**'] } },
       },
     },
   })
   ```

   Then save the change for every run to read:

   ```sh
   vx lock
   ```

3. **Run it twice**

   ```sh
   vx run build
   vx run build
   ```

   The first run builds and stores the result. The second finds nothing
   changed and skips the work:

   ```text frame="terminal" title="second run"
   └─ //#build ── (2ms) up-to-date
   ```

4. **Change a file and ask why**

   Edit a file in `src/`, run again, and ask vx what changed:

   ```sh
   vx run build
   vx why build
   ```

   ```text frame="terminal"
     verdict    cache key changed: file src/index.ts
   ```

</Steps>

## Try it in your browser

This is vx's own planner, running on four small packages. Edit a file or a
config, press **Run**, and see which tasks would run and why.
