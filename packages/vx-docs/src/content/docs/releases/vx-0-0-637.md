vx 0.0.637 shipped on 2026-10-15. Core no longer reads `package.json`:
a project is any directory with a `vx.config`, and what JavaScript needs
comes from the `@vzn/vx-lockfile` plugins. This release has many
breaking changes; the list is at the end.

## A core that knows no language

A project is a directory with a `vx.config`. It is named by its config's
`name`, else by a plugin, else by its path (`//` for the root). Core
folds no `package.json` into a key and draws no edge from one. In a
JavaScript repo, `pnpm()`, `bun()`, `npm()` or `yarn()` from
`@vzn/vx-lockfile` add the members, the edges exactly as the lockfile
installed them, and `package.json` as an input. `vx init` writes that
plugin for you; in a repo with no `package.json` it writes a workspace
with one project, the root.

```sh frame="terminal"
$ vx init
vx init: no package.json, so no scripts to map: a workspace with one project, the root.
wrote .vx/workspace.ts, vx.config.ts, .vx/.gitignore, .vx/.gitattributes.

vx lock: locked 1 project config → .vx/projects.lock.json
$ vx run build
└─ //#build ── (14ms) restored-local
```

A `^build` with no edge source is refused, so dropping the plugin fails
loudly instead of replaying stale bytes.

## Runs read only the lock

`vx lock` evaluates every config and writes `.vx/projects.lock.json`.
Every run, `vx show` and `vx info` read their configs from it and
evaluate none; with no lock a run stops and names `vx lock`. Graph rules
are checked in `vx lock` only, and beside each `vx.config` it writes a
readable `vx.lock.json` for review. Run `vx lock` after you edit a config,
update dependencies or change a file a config imports; on CI,
`vx lock --check` fails a stale lock first.

```sh frame="terminal"
$ vx lock --check
$ vx run ci --all
```

## Everything vx keeps lives in .vx

`.vx/workspace.ts` is the workspace config, and the file marks the
workspace root: every verb but `vx init` needs one. The lock sits beside
it, and local state under `.vx/cache`, kept out of git by a committed
`.vx/.gitignore`. A global `vx` hands off to the project's own
`@vzn/vx`, and `vx upgrade` checks npm's signature before it installs.

```sh frame="terminal"
$ ls -a .vx
.gitattributes  .gitignore  projects.lock.json  workspace.ts
```

PRs [#3464](https://github.com/vznjs/vx/pull/3464),
[#3453](https://github.com/vznjs/vx/pull/3453),
[#3475](https://github.com/vznjs/vx/pull/3475),
[#3529](https://github.com/vznjs/vx/pull/3529).

## Cache scopes read the default key first

A named scope reads the default key, then its own, and writes only its
own, locally and remotely. On GitHub Actions `github()` from `@vzn/vx-ci`
sets `pr-<n>` on a pull request, so main fills the default keys and a pull
request reads them. Off CI a run reads the remote and writes none. A
cache plugin now provides only the remote; core owns the local cache,
the order and the policy.

```sh frame="terminal"
$ vx run ci --affected=origin/main
```

PRs [#3450](https://github.com/vznjs/vx/pull/3450),
[#3481](https://github.com/vznjs/vx/pull/3481),
[#3516](https://github.com/vznjs/vx/pull/3516). Guide:
[Cache scopes and tokens](../../guides/ci/#cache-scopes-and-tokens)

## vx cache clean

`vx cache clean` clears this repo's cache, `--older-than` and
`--max-size` trim it, `--global` clears every repo's, and `--dry-run`
says what it would remove. It never touches your config or lock.

```sh frame="terminal"
$ vx cache clean --older-than 30d --dry-run
```

PRs [#3537](https://github.com/vznjs/vx/pull/3537),
[#3544](https://github.com/vznjs/vx/pull/3544),
[#3548](https://github.com/vznjs/vx/pull/3548).

## vx keeps its env from your tasks

A task no longer sees vx's own environment, on Linux and macOS, and
`ps eww` on macOS no longer shows it. A security pass closed four more
leaks.

```sh frame="terminal"
$ vx run build --all
```

PRs [#3445](https://github.com/vznjs/vx/pull/3445),
[#3454](https://github.com/vznjs/vx/pull/3454),
[#3460](https://github.com/vznjs/vx/pull/3460). Deep dive:

## Forecasts per branch

The run's time forecast comes from task timings recorded per branch,
and `vx last --stats --branch <name>` shows the p50 it forecasts from.
`@vzn/vx-mcp` is retired: the agent skill and `--format json` cover it.

```sh frame="terminal"
$ vx last --stats --branch main
```

PRs [#3527](https://github.com/vznjs/vx/pull/3527),
[#3565](https://github.com/vznjs/vx/pull/3565),
[#3568](https://github.com/vznjs/vx/pull/3568).

## Keep outputs on a miss

`cache.outputs.clean: false` keeps a task's outputs on a miss instead of
wiping them, for a tool that updates its own output in place. A
committed file under an output is never deleted.

```ts
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    build: {
      exec: { command: 'tsc -b' },
      cache: {
        inputs: { files: ['src/**', 'tsconfig.json'] },
        outputs: { files: ['dist/**'], clean: false },
      },
    },
  },
})
```

PRs [#3514](https://github.com/vznjs/vx/pull/3514),
[#3577](https://github.com/vznjs/vx/pull/3577).

## Breaking changes

Until 1.0 an old name simply stops working, with no alias or notice.

- `package.json` members are projects only with a `vx.config` or a
  lockfile plugin; package edges and `package.json` keys come only from
  `pnpm()`, `bun()`, `npm()` or `yarn()` in `@vzn/vx-lockfile`. A `^task`
  with no edge source is refused. `NamedProject` → `DiscoveredProject`
  ([#3551](https://github.com/vznjs/vx/pull/3551),
  [#3558](https://github.com/vznjs/vx/pull/3558),
  [#3562](https://github.com/vznjs/vx/pull/3562),
  [#3567](https://github.com/vznjs/vx/pull/3567)).
- `vx init` hands any repo with a `package.json`, `turbo.json` or
  `nx.json` to `@vzn/vx-migrate`
  ([#3573](https://github.com/vznjs/vx/pull/3573)).
- `vx.workspace.ts` → `.vx/workspace.ts` (relative imports gain a
  `../`); `vx-lock.json` → `.vx/projects.lock.json`, minified, with a
  `vx.lock.json` beside each config. Re-run `vx lock`
  ([#3475](https://github.com/vznjs/vx/pull/3475),
  [#3529](https://github.com/vznjs/vx/pull/3529),
  [#3532](https://github.com/vznjs/vx/pull/3532),
  [#3536](https://github.com/vznjs/vx/pull/3536)).
- `--frozen`, `--no-frozen`, `run.frozen` and `VX_RUN_FROZEN` → removed:
  every run reads the lock. Graph rules → checked by `vx lock` only
  ([#3530](https://github.com/vznjs/vx/pull/3530),
  [#3536](https://github.com/vznjs/vx/pull/3536)).
- `vx cache prune` → `vx cache clean`; `vx prune` → removed
  ([#3537](https://github.com/vznjs/vx/pull/3537),
  [#3539](https://github.com/vznjs/vx/pull/3539)).
- Workspace keys, `VX_*` variables and some flags follow one path per
  setting; `cacheScope` → `cache.scope`; `--cache` → `--cache-policy`;
  `--download` → `--cache-download`; `vx migrate` →
  `bunx @vzn/vx-migrate`; `vx stats` → `vx info`
  ([#3450](https://github.com/vznjs/vx/pull/3450),
  [#3465](https://github.com/vznjs/vx/pull/3465),
  [#3520](https://github.com/vznjs/vx/pull/3520)).
- Cache scopes `'trusted'` and `'read-only'` → plain names; use
  `cache.policy` `'remote:r'` for a read-only run. A cache plugin returns
  only a remote layer. Every cached task misses once (`vx-cache-v43`)
  ([#3481](https://github.com/vznjs/vx/pull/3481),
  [#3516](https://github.com/vznjs/vx/pull/3516)).
- `@vzn/vx-mcp` and `vx mcp` → the agent skill
  (`npx skills add vznjs/vx/packages/vx/skills/vx`) and `vx last --stats`
  ([#3527](https://github.com/vznjs/vx/pull/3527)).
- Plugins gain an `output` stage (15 hooks); the config eval cache is
  gone (index `v35`)
  ([#3499](https://github.com/vznjs/vx/pull/3499),
  [#3545](https://github.com/vznjs/vx/pull/3545)).

Every entry with what to do: [Upgrading](../../guides/upgrading/).

## How to update

```sh frame="terminal"
npm install -D @vzn/vx@latest
npx @vzn/vx lock
```

A standalone binary updates itself with `vx upgrade`.
