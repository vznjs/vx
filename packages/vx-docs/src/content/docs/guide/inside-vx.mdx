Teams want different things. One wants a shared cache on one server,
another on a different one. One wants traces, another wants none. A tool
that adds a special case for each grows slow and fragile.

## Every run passes the same stages

<Diagram {...P.pipeline} />

Every run does the same steps in the same order. It reads the config,
builds the graph, computes keys, then runs, stores and reports. vx names
each step a stage.

## A plugin fills one stage

<Diagram {...P.plugins} />

A [plugin](../../glossary/#seam-and-plugin) is a small piece of code
that makes the choice at one stage. vx adds no plugin unless you list it.

Pick a stage below to see the code a plugin writes there.

<PipelineExplorer />

## With no plugins, vx still runs and caches

<Diagram {...P.floor} />

Running on this machine and caching on this machine are built in. They sit
under every plugin. A plugin that says no to a task hands it back to this
machine.

## A whole plugin fits in 20 lines

<Code code={summaryLine} lang="ts" title="plugins/summary-line.ts" />

This plugin prints one line after every run. It only watches, so it cannot
break a run.

## In vx

List the plugin in `vx.workspace.ts`:

```ts
// vx.workspace.ts
import { defineWorkspace } from '@vzn/vx'
import { summaryLine } from './plugins/summary-line.ts'

export default defineWorkspace({ plugins: [summaryLine()] })
```
