You run `app#build` first. It fails.

## Build ui before app

<Diagram {...P.order} />

`app` imports `ui`, so `ui#build` must finish first. That is a
[dependency](../../glossary/#task-dependency): one task waits for
another.

## Two rules draw every arrow

<Diagram {...P.rules} />

`^build` means "first, the build of every package I use". Plain `build`
means "first, my own package's build". Your `package.json` files already
say who uses whom. So you never list the arrows by hand.

## The rules draw the whole graph

Here are both rules applied to all four packages:

This is the [task graph](../../glossary/#task-graph). Each row is a

## A loop has no first task

<Diagram {...P.cycle} />

Say `utils` starts importing `app`. Now every task in the loop waits for
another, so none can start. vx stops and names the loop:

```
Cycle detected in task graph: api#build -> utils#build -> app#build -> api#build
```

## In vx

In vx, the two rules are two `dependsOn` lines:

```ts
import { defineProject } from '@vzn/vx'

export default defineProject({
  tasks: {
    build: { dependsOn: ['^build'], exec: { command: 'tsc -b' } },
    test: { dependsOn: ['build'], exec: { command: 'bun test' } },
  },
})
```

<details>
<summary>How we know this is true</summary>

- [`^build` and `build` mean what this page says](../../schema/#dependson-optional)
- [vx reads who uses whom from `package.json`](https://github.com/vznjs/vx/blob/main/packages/vx/tests/package-graph.test.ts 'reads all four dependency fields: a workspace peer orders a build too')
- [A package from npm adds no arrow](https://github.com/vznjs/vx/blob/main/packages/vx/tests/package-graph.test.ts 'records direct workspace deps only when the dep is in the workspace')
- [vx refuses a loop](https://github.com/vznjs/vx/blob/main/packages/vx/tests/task-graph.test.ts 'a task cycle through every project is refused')

</details>
