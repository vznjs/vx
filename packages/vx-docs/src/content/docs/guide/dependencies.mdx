## Build ui before app

<Diagram {...ORDER}>Same two tasks, different order.</Diagram>

`app` imports `ui`, so `ui#build` must finish first. That is a
[dependency](../../learn/glossary/#task-dependency): one task waits for
another.

## Two rules draw every arrow

<Diagram {...RULES}>An arrow means "must finish first".</Diagram>

`^build` means "first, the build of every package I use". Plain `build`
means "first, my own package's build". Your `package.json` files already
say who uses whom. So you never list the arrows by hand.

## A loop has no first task

<Diagram {...CYCLE}>Every task waits for another.</Diagram>

Say `utils` starts importing `app`. Now every task in the loop waits for
another, so none can start. vx stops and names the loop:

```
Cycle detected in task graph: api#build -> utils#build -> app#build -> api#build
```

## In vx

In vx, the two rules are two `dependsOn` lines:

```ts
import { defineProject } from '@vzn/vx'

export default defineProject({
  tasks: {
    build: { dependsOn: ['^build'], exec: { command: 'tsc -b' } },
    test: { dependsOn: ['build'], exec: { command: 'bun test' } },
  },
})
```

<details>
<summary>How we know this is true</summary>

- `^build` and `build` mean what this page says: [`dependsOn`](../../schema/#dependson-optional)
- vx reads who uses whom from `package.json`: [the row "reads all four dependency fields: a workspace peer orders a build too"](https://github.com/vznjs/vx/blob/main/packages/vx/tests/package-graph.test.ts)
- A package from npm adds no arrow: [the row "records direct workspace deps only when the dep is in the workspace"](https://github.com/vznjs/vx/blob/main/packages/vx/tests/package-graph.test.ts)
- vx refuses a loop: [the row "a task cycle through every project is refused"](https://github.com/vznjs/vx/blob/main/packages/vx/tests/task-graph.test.ts)

</details>
