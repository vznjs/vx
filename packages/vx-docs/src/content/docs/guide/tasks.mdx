The loop runs `npm run build`. But what does that actually run?

## A script can hide three jobs

<Diagram {...P.script} />

`ui`'s build script checks types, bundles the code and copies images. To
the loop, that is one line. It runs all of it, or none of it.

## A task is one command in one package

<Diagram {...P.taskName} />

A [task](../../learn/glossary/#task) is one command, run in one package.
Its name joins the two with `#`. So the build of `api` is `api#build`, and
the tests of `ui` are `ui#test`. Four packages with `build` and `test`
make eight tasks.

## A task reads inputs and writes outputs

<Diagram {...P.readsWrites} />

What a task reads are its [inputs](../../learn/glossary/#inputs): files,
settings, environment variables. What it writes are its
[outputs](../../learn/glossary/#outputs). If the inputs did not change,
the outputs will not change either. Later chapters use that to skip work.

## One command per task lets you skip the rest

<Diagram {...P.split} />

Change one image. As one task, all three jobs run again. As three tasks,
only the copy does. A tool can only skip what it sees as its own task.

## In vx

In vx, a task is a command in the package's `vx.config.ts`:

```ts
import { defineProject } from '@vzn/vx'

export default defineProject({
  tasks: {
    build: {
      exec: { command: 'tsc -b' },
    },
  },
})
```

<details>
<summary>How we know this is true</summary>

- [In `packages/utils`, this task is `utils#build`](../../schema/#project-config)
- [The command runs in the package's own folder](../../schema/#exec-optional--required-for-non-group-tasks)
- [A chain with `&&` is one task](../../execution/#one-command-per-task)
- [vx never guesses a task's input files](https://github.com/vznjs/vx/blob/main/packages/vx/tests/config.test.ts 'requires cache.inputs.files — the one declaration vx will not infer')

</details>
