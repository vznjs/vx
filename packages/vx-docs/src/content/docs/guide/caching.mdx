You fix a typo in `app` and run the build again. All eight tasks run.

<Rerun />

Six of them read nothing that changed. They did the same work twice.

## Same inputs give the same result

<SameInputs />

A task's inputs are everything it reads: its files, its command and its
settings. If none of them changed, the result will not change either. So
vx keeps the result and hands it back next time.

## A short key tells vx if anything changed

<Key />

vx turns all of a task's inputs into one short code, the
[cache key](../../learn/glossary/#cache-key). Change any input and the key
changes. If vx has seen the key before, that is a hit: it puts the saved
files back and shows the saved log. The task does not run.

## A change in utils changes every key above it

<Cascade />

`ui#build` uses what `utils#build` made. So `ui#build`'s key includes
`utils#build`'s key. Change `utils`, and every key above it changes. Change
`app`, and only `app`'s keys change.

Try each change in the calculator below.

## In vx

Add a `cache` block that lists the files a task reads and the files it
writes.

```ts
import { defineProject } from '@vzn/vx'

export default defineProject({
  tasks: {
    build: {
      dependsOn: ['^build'],
      exec: { command: 'tsc -b' },
      cache: {
        inputs: { files: ['src/**', 'tsconfig.json'] },
        outputs: { files: ['dist/**'] },
      },
    },
  },
})
```
