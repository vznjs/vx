In five minutes your build runs once, then skips itself until your code changes.

<Aside title="What you need">
  macOS or Linux with glibc (not Alpine's musl), Git, and [Node.js](https://nodejs.org) 20.19 or later,
  which vite runs on. Step 0 installs Bun.
</Aside>

```sh
bunx @vzn/vx init
```

## 0. Make an app

Have a workspace already? Skip to step 1. Otherwise install [Bun](https://bun.com) and make a small Vite app in a git repository:

```sh
curl -fsSL https://bun.sh/install | bash
```

Open a new terminal so it finds `bun`, then make the app:

```sh
bun create vite my-app --template vanilla
cd my-app && bun install && git init
```

This page grows one package, `my-app`. The chapters after it grow a workspace of many.

<Takeaway>go from an empty machine to an app with a build.</Takeaway>

## 1. Set up vx

Run `vx init` inside your git checkout. It installs the `vx` command and writes your first files:

```ansi title="vx init"
[2m$[0m bunx @vzn/vx init

[4m[58;2;110;118;129m  [1m[38;2;167;139;250mvx init 0.0.661[0m[4m[58;2;110;118;129m                                                       [0m
  [2mfrom     [0m  [38;2;203;213;225mno turbo.json or nx.json[0m
  [2mfiles    [0m  [38;2;203;213;225m.vx/workspace.ts[0m
             [38;2;203;213;225mvx.config.ts[0m
             [38;2;203;213;225m.vx/.gitignore[0m
             [38;2;203;213;225m.vx/.gitattributes[0m
  [2minstalled[0m  [38;2;203;213;225mbun add -g @vzn/vx@0.0.661[0m
             [38;2;203;213;225mbun add @vzn/vx@0.0.661 @vzn/vx-lockfile@0.0.661 --dev[0m
  [2mlock     [0m  [38;2;203;213;225m1 project config → .vx/projects.lock, .vx/dependencies.lock[0m

  [2mnext     [0m  [1mbunx @vzn/vx-migrate@0.0.661 to make package.json scripts[0m
             [1mtasks, or declare a task in vx.config.ts, then vx lock &&[0m
             [1mvx run <task>[0m
```

Look at **files**. Two of them matter today:

| File | What it is |
| --- | --- |
| `.vx/workspace.ts` | marks the root of your **workspace** and lists its plugins |
| `vx.config.ts` | your tasks. It starts empty |

<Concept term="Workspace">
  The folder vx works in: your git checkout. `.vx/workspace.ts` marks its root. Each project in it
  can keep its tasks in its own `vx.config.ts`.
</Concept>

<Deeper level="details" title="Everything vx init writes and installs">

| Line | What it means |
| --- | --- |
| `from` | no `turbo.json` or `nx.json` here. With one, init converts it ([Migrate](../docs/migrate/)) |
| `.vx/workspace.ts` | names one plugin, `bun()`, which reads `bun.lock` |
| `vx.config.ts` | your project's tasks: none yet |
| `.vx/.gitignore` | keeps `.vx/cache` and `.vx/tmp` out of git |
| `.vx/.gitattributes` | GitHub hides the locks in a diff |
| `installed` | `vx` for your shell, then `@vzn/vx` and `@vzn/vx-lockfile` as dev dependencies |
| `lock` | the two lock files every run reads (step 2) |

The workspace file `vx init` writes for a Bun workspace:

```ts title=".vx/workspace.ts"
import type { WorkspaceConfig } from '@vzn/vx/config'
import { bun } from '@vzn/vx-lockfile'

export default { plugins: [bun()] } satisfies WorkspaceConfig
```

With pnpm, npm or Yarn, it names `pnpm()`, `npm()` or `yarn()` instead. See [Lockfiles](../docs/lockfiles/).

</Deeper>

<Takeaway>set up vx in any workspace with one command.</Takeaway>

## 2. Teach vx your build

<Concept term="Task">
  One command vx runs for a project, plus the files it reads and the files it writes.
</Concept>

Paste this into `vx.config.ts`. It turns `vite build` into a task named `build`:

```ts title="vx.config.ts" ins={5-10}
import type { ProjectConfig } from '@vzn/vx/config'

export default {
  tasks: {
    build: {
      exec: { command: 'vite build' },
      inputs: { files: ['src/**', 'public/**', 'index.html'] },
      outputs: { files: ['dist/**'] },
      cache: true,
    },
  },
} satisfies ProjectConfig
```

Each line answers one question vx asks:

| Field | Question | Here |
| --- | --- | --- |
| `exec.command` | What do I run? | `vite build` |
| `inputs.files` | Which files does it read? | the source, `public/`, the page |
| `outputs.files` | Which files does it write? | everything in `dist/` |
| `cache` | May I skip it when nothing changed? | yes |

Now save the config to the lock. Every run reads the lock, not your config, so run this after each config change:

```ansi title="vx lock"
[2m$[0m vx lock

[38;2;34;197;94m✓[0m [1mvx lock[0m  [38;2;203;213;225m1 project config → .vx/projects.lock, .vx/dependencies.lock[0m
```

<Aside type="tip">
  `vx lock` also writes `vx.lock.json` beside your config. Commit it with `.vx/` and `vx.config.ts`:
  a teammate who pulls gets the same tasks.
</Aside>

<Deeper level="patterns" title="Add tests and lint the same way">

The same four fields turn any command into a task. A task that writes no file says so with an empty list:

```ts title="vx.config.ts" ins={11-22}
import type { ProjectConfig } from '@vzn/vx/config'

export default {
  tasks: {
    build: {
      exec: { command: 'vite build' },
      inputs: { files: ['src/**', 'public/**', 'index.html'] },
      outputs: { files: ['dist/**'] },
      cache: true,
    },
    test: {
      exec: { command: 'vitest run --passWithNoTests' },
      inputs: { files: ['src/**'] },
      outputs: { files: [] },
      cache: true,
    },
    lint: {
      exec: { command: 'oxlint' },
      inputs: { files: ['src/**'] },
      outputs: { files: [] },
      cache: true,
    },
  },
} satisfies ProjectConfig
```

Install the two tools, then run `vx lock` and `vx run test` or `vx run lint`:

```sh
bun add -d vitest oxlint
vx lock
vx run lint
```

 A cached test run that passed is skipped until `src/` changes.

</Deeper>

<Deeper level="details" title="What each field accepts">

- `exec.command` is one shell line. It calls the tool itself (`vite build`), never a package script.
- `inputs.files` and `outputs.files` are globs, relative to the project. A leading `!` leaves files out: `'!src/**/*.test.ts'`.
- A file outside `inputs.files` never makes the task run again. A file outside `outputs.files` is not saved.
- `cache` is `false` when left out: the task runs every time.

Every other field a task can have, from `dependsOn` to `env`, is on [Tasks](../docs/tasks/) and in the [config reference](../schema/).

</Deeper>

<Takeaway>turn any command into a task vx can skip.</Takeaway>

<Deeper level="details" title="Where the cache lives">

`vx info` prints it. The workspace's run history sits in `.vx/cache`.

Once the repository has a commit, the saved outputs sit in `~/.vx/<workspace id>/cache`, shared by every checkout of this workspace. Before that, they sit in `.vx/cache` too.

To share the cache with CI and your team, see [Remote cache](../docs/remote-cache/).

</Deeper>

<Takeaway>get any output back without building it again.</Takeaway>

<Deeper level="details" title="How vx decides">

Before it runs a task, vx hashes what the task reads: its input files, its config and the tasks it depends on. That hash is the **cache key**. A key vx has seen is a hit; a new key runs the task.

[Caching](../docs/caching/) shows the key step by step, and [Why a task missed](../docs/caching/why-a-task-missed/) reads every line of `vx why`.

</Deeper>

<Takeaway>predict what runs, and ask vx when you are not sure.</Takeaway>
