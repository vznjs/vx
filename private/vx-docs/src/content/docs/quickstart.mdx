Cache your first task in two minutes, in a repo you already have.

<Aside title="What you need">
  Git, and macOS or Linux with glibc (not Alpine's musl). On Windows, use WSL2.
</Aside>

<Steps>

1. **Set up vx**

   Run this at the root of your git repository:

   ```sh
   bunx @vzn/vx init
   ```

   `init` installs `vx`, writes an empty `vx.config.ts` at the root, and
   declares your lockfile's plugin (`bun()` beside `bun.lock`) in
   `.vx/workspace.ts`.

2. **Add a task**

   Give `vx.config.ts` a `build` task: the tool it runs, the files it
   reads, and the files it writes. vx runs the tool itself, with no
   package script in between.

   ```ts title="vx.config.ts" ins={5-9}
   import type { ProjectConfig } from '@vzn/vx/config'

   export default {
     tasks: {
       build: {
         exec: { command: 'tsc' },
         inputs: { files: ['src/**', 'tsconfig.json'] },
         outputs: { files: ['dist/**'] },
         cache: true,
       },
     },
   } satisfies ProjectConfig
   ```

   In a monorepo, give each package its own `vx.config.ts` beside its
   `package.json`, and add `dependsOn: ['^build']` to build a package's
   dependencies first. `vx show` lists every project vx found.

   Then save the change for every run to read:

   ```sh
   vx lock
   ```

3. **Run it twice**

   ```sh
   vx run build
   vx run build
   ```

   The first run builds and stores the result. The second finds nothing
   changed and skips the work (`up-to-date`). `my-app` is the `name` in
   your `package.json`:

   ```ansi title="second run"
   [2m┌─[0m [1m[38;2;232;121;249mmy-app[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m>[0m $ tsc
   [2m└─[0m [1m[38;2;232;121;249mmy-app[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m──[0m [2m(3ms)[0m [2mup-to-date[0m
   ```

4. **Change a file and ask why**

   Edit a file in `src/`, run again, and ask vx what changed. `verdict`
   names the file you edited:

   ```sh
   vx run build
   vx why build
   ```

