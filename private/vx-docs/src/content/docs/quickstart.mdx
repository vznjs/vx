Cache your first task in two minutes, in a workspace you already have.

<Aside title="What you need">
  [Bun](https://bun.com) 1.4.4 or later, Git, and macOS or Linux with glibc (not
  Alpine's musl). On Windows, use WSL2.
</Aside>

<Steps>

1. **Set up vx**

   Run this at the root of your workspace, inside a git checkout:

   ```sh
   bunx @vzn/vx init
   ```

   It installs the `vx` command and writes your first files. Look at
   `files`: `.vx/workspace.ts` marks the workspace root, and
   `vx.config.ts` is where your tasks go.

   ```ansi
   [4m[58;2;110;118;129m  [1m[38;2;167;139;250mvx init 0.0.659[0m[4m[58;2;110;118;129m      [0m
     [2mfrom     [0m  [38;2;203;213;225mno turbo.json or nx.json[0m
     [2mfiles    [0m  [38;2;203;213;225m.vx/workspace.ts[0m
                [38;2;203;213;225mvx.config.ts[0m
                [38;2;203;213;225m.vx/.gitignore[0m
                [38;2;203;213;225m.vx/.gitattributes[0m
     [2minstalled[0m  [38;2;203;213;225mbun add -g @vzn/vx@0.0.659[0m
                [38;2;203;213;225mbun add @vzn/vx@0.0.659 @vzn/vx-lockfile@0.0.659 --dev[0m
     [2mlock     [0m  [38;2;203;213;225m1 project config → .vx/projects.lock, .vx/dependencies.lock[0m

     [2mnext     [0m  [1mdeclare a task in vx.config.ts, then vx lock && vx run <task>[0m
   ```

2. **Add a task**

   A task is one command, the files it reads and the files it writes.
   `cache: true` lets vx skip it when nothing changed.

   ```ts title="vx.config.ts" ins={5-10}
   import type { ProjectConfig } from '@vzn/vx/config'

   export default {
     tasks: {
       build: {
         exec: { command: 'vite build' },
         inputs: { files: ['src/**', 'index.html', 'vite.config.ts'] },
         outputs: { files: ['dist/**'] },
         cache: true,
       },
     },
   } satisfies ProjectConfig
   ```

   Save the config to the lock. Every run reads the lock, so run this
   after each config change:

   ```sh
   vx lock
   ```

   ```ansi
   [38;2;34;197;94m✓[0m [1mvx lock[0m  [38;2;203;213;225m1 project config → .vx/projects.lock, .vx/dependencies.lock[0m
   ```

   Commit `.vx/`, `vx.config.ts` and the `vx.lock.json` beside it with
   the rest of your code.

   ```sh
   vx run build
   vx run build
   ```

4. **Get a cache hit**

   Delete the output and run again. vx puts `dist/` back from its cache
   instead of running vite:

   ```sh
   rm -rf dist
   vx run build
   ```

   ```ansi
   [2m┌─[0m [1m[38;2;232;121;249mmy-app[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m>[0m $ vite build
   [36mvite v7.3.8 [32mbuilding client environment for production...[36m[39m
   transforming...
   [32m✓[39m 3 modules transformed.
   rendering chunks...
   computing gzip size...
   [2mdist/[22m[32mindex.html                [39m[1m[2m0.08 kB[22m[1m[22m[2m │ gzip: 0.09 kB[22m
   [2mdist/[22m[2massets/[22m[36mindex-CAtcZSpD.js  [39m[1m[2m0.74 kB[22m[1m[22m[2m │ gzip: 0.42 kB[22m
   [32m✓ built in 90ms[39m
   [2m└─[0m [1m[38;2;232;121;249mmy-app[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m──[0m [2m(25ms)[0m [2mrestored-local[0m

     [2mcache   [0m  [38;2;56;189;248m▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰▰[0m
               [2mlocal[0m [38;2;56;189;248m1↓[0m
   ```

   Look for `restored-local` and `local 1↓`: the files came from the cache.

5. **Change a file and ask why**

   Edit a file in `src/` and run again: the task runs, because an input
   changed. `vx why` names the file on its `verdict` line:

   ```sh
   vx run build
   vx why build
   ```

   ```ansi
   [4m[58;2;110;118;129m  [1m[38;2;167;139;250mWhy[0m[4m[58;2;110;118;129m [2mmy-app#build[0m[4m[58;2;110;118;129m      [0m
   ```

</Steps>

You now have a cached task. In a monorepo, give each package its own
`vx.config.ts`, and build them all from the root with `vx run build --all`.
