title: Servers
description: The three servers vx's plugins talk to, which you host, and the CI token rules they share.

vx runs and caches on one machine with no server at all. Three servers
add what one machine cannot. You host each one yourself, on Cloudflare
Workers, Bun or Docker. You need only the ones you use.

| Server | What it gives you | Plugin |
| --- | --- | --- |
| [Cache server](cache/) | every machine reuses what another one built | `vxCache()` from `@vzn/vx-cache` |
| [History server](history/) | a fresh CI runner knows how long each task takes, so it starts the long ones first | `vxHistory()` from `@vzn/vx-history` |
| [DTE server](dte/) | one run spread over many CI runners | `dte()` from `@vzn/vx-dte` |

None of them stores a password or a token. Each request carries the CI
job's own OIDC token, which GitHub Actions or GitLab CI hands the job,
and the server checks it. A laptop has no such token, so off CI the
plugins work locally.

## `TRUST`: who reads and who writes

The cache and history servers read one setting, `TRUST`: a list of
rules. A rule names a repository and says which CI runs may write its
protected branches. This rule lets every GitHub Actions run of
`acme/app` in, and lets only a push to `main` write `main`:

```json
[
  {
    "iss": "https://token.actions.githubusercontent.com",
    "repository": "acme/app",
    "event_name": "push",
    "ref": "refs/heads/main"
  }
]
```

What that gives each run:

- **A run of `acme/app`** reads its own branch, then the branch it merges
  into, then `main`.
- **A run on another branch**, such as a pull request from `feat-x`,
  writes `feat-x` only.
- **A run on `main` that does not match the rule**, such as a manual
  run, reads `main` and writes nothing.
- **A run of any other repository** is refused. With `TRUST` empty,
  every request is refused: `the server trusts no CI: set TRUST`.

Each field of a rule is a claim of the CI token. A value is a string,
where `*` matches anything, or a list of strings:

| Field | GitHub Actions | GitLab CI |
| --- | --- | --- |
| issuer | `"iss": "https://token.actions.githubusercontent.com"` | `"iss": "https://gitlab.com"`, or your GitLab's URL |
| repository | `"repository": "acme/app"` | `"project_path": "acme/web"` |
| protected branches | `"ref": "refs/heads/main"` | `"ref_path": "refs/heads/main"` |
| which runs | `"event_name": "push"` | `"pipeline_source": "push"` |

Add any other claim the writing run must hold, such as
`"ref_protected": "true"`. A GitLab rule:

```json
[
  {
    "iss": "https://gitlab.com",
    "project_path": "acme/web",
    "ref_path": "refs/heads/main",
    "ref_protected": "true",
    "pipeline_source": ["push", "schedule"]
  }
]
```

<details>
<summary>Why name `event_name`, and what a merge queue writes</summary>

`pull_request_target` and `issue_comment` runs carry `main`'s `ref`
while they run a pull request's code. A rule without `event_name` would
let them write `main`.

A GitHub merge queue run, on `refs/heads/gh-readonly-queue/main/pr-<n>-<sha>`,
writes `main` before its code lands, when its rule lists `merge_group`
and the queue's ref. Code you queue is code you trust, so run security
checks on the pull request, before it is queued.

</details>

<details>
<summary>What the server sees</summary>

Every request names its issuer and repository, as `vxCache({ issuer,
repository })` and `vxHistory({ issuer, repository })` declare them,
hashed. A token of another repository is refused. A branch travels as
the first 128 bits of its SHA-256 in hex, so the server never sees a
branch name. A renamed repository starts with an empty cache.

`AUDIENCE` is the `aud` a token must name. By default it is the URL the
server is reached at, which is what the plugins ask the CI for.

`READ_ACCESS=public` lets a request with no token, such as a laptop's,
read a repository `TRUST` names. It writes nothing.

</details>

The DTE server has its own, shorter list, `ALLOW`
([DTE server](dte/#settings)).

## All three with Docker Compose

Run the three side by side with this `compose.yaml`:

```yaml title="compose.yaml"
services:
  dte:
    image: ghcr.io/vznjs/vx-dte-server
    command: [--allow, '${DTE_ALLOW:-}', --audience, '${DTE_AUDIENCE:-}']
    ports: ['${DTE_PORT:-8080}:8080']
    restart: unless-stopped
  cache:
    image: ghcr.io/vznjs/vx-cache-server
    environment: [TRUST, AUDIENCE, READ_ACCESS, S3_BUCKET, S3_ENDPOINT, S3_REGION, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY, MAX_CHECK_HASHES, MAX_UPLOAD_BYTES]
    ports: ['${CACHE_PORT:-8081}:8080']
    restart: unless-stopped
  history:
    image: ghcr.io/vznjs/vx-history-server
    environment: [TRUST, AUDIENCE, READ_ACCESS, TIMING_DAYS]
    volumes: ['history:/data']
    ports: ['${HISTORY_PORT:-8082}:8080']
    restart: unless-stopped
volumes:
  history:
```

```sh
docker compose up -d                 # all three
docker compose up -d cache history   # only the ones you need
```

| Service | Port | Settings it reads |
| --- | --- | --- |
| `dte` | 8080 (`DTE_PORT`) | `DTE_ALLOW`, `DTE_AUDIENCE` |
| `cache` | 8081 (`CACHE_PORT`) | `TRUST`, `AUDIENCE`, `READ_ACCESS`, `S3_*`, `MAX_*` |
| `history` | 8082 (`HISTORY_PORT`) | `TRUST`, `AUDIENCE`, `READ_ACCESS`, `TIMING_DAYS` |

Settings come from your shell or a `.env` file next to `compose.yaml`.
The history server keeps its SQLite file in the `history` volume. Put
HTTPS in front of each server: a CI token is a bearer token.
