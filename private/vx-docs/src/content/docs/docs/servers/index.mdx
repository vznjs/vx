---
title: Servers
description: The three servers vx's plugins talk to, which you host, and the CI token rules they share.
---

vx runs and caches on one machine with no server at all. Three servers
add what one machine cannot. You host each one yourself, on Cloudflare
Workers, Bun or Docker. You need only the ones you use.

| Server | What it gives you | Plugin |
| --- | --- | --- |
| [Cache server](cache/) | every machine reuses what another one built | `vxCache()` from `@vzn/vx-cache` |
| [History server](history/) | a fresh CI runner knows how long each task takes, so it starts the long ones first | `vxHistory()` from `@vzn/vx-history` |
| [DTE server](dte/) | one run spread over many CI runners | `dte()` from `@vzn/vx-dte` |

None of them stores a password or a token. Each request carries the CI
job's own OIDC token, which GitHub Actions or GitLab CI hands the job,
and the server checks it. A laptop has no such token, so off CI the
plugins work locally.

## `ALLOW`: who takes part

The cache and history servers read one setting, `ALLOW`: who may take
part, space separated, each `issuer:owner/repo:workflow`. This lets
every run of `acme/app`'s `ci.yml` workflow on GitHub Actions in:

```sh
ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml'
```

What that gives each run of `ci.yml`:

- **A run of `acme/app`** reads its own branch, then the branch it merges
  into, then `main`; a pull request first its merge ref, `refs/pull/<n>/merge`.
- **A push to a branch**, such as `main`, writes that branch.
- **A pull request from `feat-x`** writes its merge ref only, never a
  branch: a fork names its own head branch, and could name `release`.
- **A `pull_request_target` run** reads and writes nothing: it runs on
  the base branch for a fork's code.
- **A run of another workflow or repository** is refused. With `ALLOW`
  empty, every request is refused: `the server admits no CI: set ALLOW`.

On GitLab, the workflow is the CI file:
`https://gitlab.com:acme/web:.gitlab-ci.yml`. A merge request pipeline
writes its source branch only when the token's `source_project_path`
(GitLab 19.5+) names the project itself: a fork's merge request, run in
your project, writes nothing.

A CI file kept in another project is named as GitLab names it:
`.gitlab-ci.yml@acme/ci`.

<details>
<summary>What a merge queue writes</summary>

A GitHub merge queue run (`merge_group`), on `refs/heads/gh-readonly-queue/main/pr-<n>-<sha>`,
writes `main` before its code lands. A push to a branch of that name
writes only that branch. Code you queue is code you trust,
so run security checks on the pull request, before it is queued.

</details>

<details>
<summary>What the server sees</summary>

Every request names its issuer and repository, as `vxCache({ issuer,
repository })` and `vxHistory({ issuer, repository })` declare them,
hashed. A token of another repository is refused. A branch travels as
the first 128 bits of its SHA-256 in hex, so the server never sees a
branch name. A renamed repository starts with an empty cache.

`AUDIENCE` is the `aud` a token must name. By default it is the URL the
server is reached at, which is what the plugins ask the CI for.

`READ_ACCESS=public` lets a request with no token, such as a laptop's,
read a repository `ALLOW` names. It writes nothing.

</details>

The DTE server has its own, shorter list, `ALLOW`
([DTE server](dte/#settings)).

## All three with Docker Compose

Run the three side by side with this `compose.yaml`:

```yaml title="compose.yaml"
services:
  dte:
    image: ghcr.io/vznjs/vx-dte-server
    command: [--allow, '${DTE_ALLOW:-}', --audience, '${DTE_AUDIENCE:-}']
    ports: ['${DTE_PORT:-8080}:8080']
    restart: unless-stopped
  cache:
    image: ghcr.io/vznjs/vx-cache-server
    environment: [ALLOW, AUDIENCE, READ_ACCESS, S3_BUCKET, S3_ENDPOINT, S3_REGION, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY, MAX_CHECK_HASHES, MAX_UPLOAD_BYTES]
    ports: ['${CACHE_PORT:-8081}:8080']
    restart: unless-stopped
  history:
    image: ghcr.io/vznjs/vx-history-server
    environment: [ALLOW, AUDIENCE, READ_ACCESS, TIMING_DAYS]
    volumes: ['history:/data']
    ports: ['${HISTORY_PORT:-8082}:8080']
    restart: unless-stopped
volumes:
  history:
```

```sh
docker compose up -d                 # all three
docker compose up -d cache history   # only the ones you need
```

| Service | Port | Settings it reads |
| --- | --- | --- |
| `dte` | 8080 (`DTE_PORT`) | `DTE_ALLOW`, `DTE_AUDIENCE` |
| `cache` | 8081 (`CACHE_PORT`) | `ALLOW`, `AUDIENCE`, `READ_ACCESS`, `S3_*`, `MAX_*` |
| `history` | 8082 (`HISTORY_PORT`) | `ALLOW`, `AUDIENCE`, `READ_ACCESS`, `TIMING_DAYS` |

Settings come from your shell or a `.env` file next to `compose.yaml`.
The history server keeps its SQLite file in the `history` volume. Put
HTTPS in front of each server: a CI token is a bearer token.
