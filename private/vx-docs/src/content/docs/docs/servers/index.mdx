vx needs no server. Three servers you host add what one machine cannot. Start all three in one line:

```sh
docker compose up -d
```

<Concept term="OIDC token">
  A short-lived pass your CI hands each job: "I am `ci.yml` of `acme/app`, on `main`". The servers
  check it, so you store no password anywhere.
</Concept>

## Pick the servers you need

Each server pairs with one plugin. Skip the ones you do not use.

| Server | You get | Plugin |
| --- | --- | --- |
| [Cache server](cache/) | every CI machine reuses what another one built | `vxCache()` from `@vzn/vx-cache` |
| [History server](history/) | a fresh runner starts the long tasks first | `vxHistory()` from `@vzn/vx-history` |
| [Distributed task execution server](dte/) | [Distributed task execution](../distributed-task-execution/): one run over many machines | `dte()` from `@vzn/vx-dte` |

Each runs on **Cloudflare Workers**, **Bun** or **Docker**, from one package.

<Takeaway>choose the servers your workspace needs, and know which plugin talks to each.</Takeaway>

## Say who takes part: `ALLOW`

Every server reads one setting, `ALLOW`: the CI workflows it serves. One entry is `issuer:owner/repo:workflow`:

```sh
ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml'
```

That entry lets in `ci.yml` of `acme/app` on GitHub Actions. The servers read GitHub Actions and GitLab tokens only (gitlab.com or your own instance). A Buildkite, CircleCI or Jenkins job has no token they take: it reads like a laptop and writes nothing.

Try what it allows:

<AllowExplorer />

Look at **pull request**: it writes only its merge ref. A fork could name its branch `main`, so no pull request ever writes a branch.

<Quiz q="A release workflow, release.yml, asks the cache server for a result. What happens?">
  It is refused: `ALLOW` names only `ci.yml`. Add a second entry, separated by a space, to let it
  in.
</Quiz>

<Takeaway>write an `ALLOW` line and predict what each CI run may read and write.</Takeaway>

## Run all three with Docker Compose

Save this next to a `.env` file holding your settings:

```yaml title="compose.yaml"
services:
  dte:
    image: ghcr.io/vznjs/vx-dte-server
    environment: [ALLOW=${DTE_ALLOW:-}, AUDIENCE=${DTE_AUDIENCE:-}]
    ports: ['${DTE_PORT:-8080}:8080']
    restart: unless-stopped
  cache:
    image: ghcr.io/vznjs/vx-cache-server
    environment: [ALLOW=${CACHE_ALLOW:-}, AUDIENCE=${CACHE_AUDIENCE:-}, READ_ACCESS=${CACHE_READ_ACCESS:-}, S3_BUCKET, S3_ENDPOINT, S3_REGION, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY, S3_SESSION_TOKEN, MAX_CHECK_HASHES, MAX_UPLOAD_BYTES]
    ports: ['${CACHE_PORT:-8081}:8080']
    restart: unless-stopped
  history:
    image: ghcr.io/vznjs/vx-history-server
    environment: [ALLOW=${HISTORY_ALLOW:-}, AUDIENCE=${HISTORY_AUDIENCE:-}, READ_ACCESS=${HISTORY_READ_ACCESS:-}, TIMING_DAYS]
    volumes: ['history:/data']
    ports: ['${HISTORY_PORT:-8082}:8080']
    restart: unless-stopped
volumes:
  history:
```

```ini title=".env"
DTE_ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml'
DTE_AUDIENCE=https://dte.example.com
CACHE_ALLOW=https://token.actions.githubusercontent.com:acme/app:ci.yml
CACHE_AUDIENCE=https://cache.example.com
S3_BUCKET=vx-cache
S3_ENDPOINT=https://s3.us-east-1.amazonaws.com
HISTORY_ALLOW=https://token.actions.githubusercontent.com:acme/app:ci.yml
HISTORY_AUDIENCE=https://history.example.com
```

```sh
docker compose up -d                 # all three
docker compose up -d cache history   # only the ones you need
```

Each server says it is up in one green line:

<Aside type="caution">
  Put HTTPS in front of each server. A CI token is a bearer token: whoever reads it can use it until
  it expires.
</Aside>

<Takeaway>start any mix of the three servers with one command.</Takeaway>

<Deeper level="patterns" title="Common setups">

### GitLab CI

The workflow is the CI file. A CI file kept in another project is named as GitLab names it:

```sh
ALLOW='https://gitlab.com:acme/web:.gitlab-ci.yml https://gitlab.com:acme/api:.gitlab-ci.yml@acme/ci'
```

A run writes only when its token's `source_project_path` and `job_project_path` name the project itself. A fork's merge request, or a child pipeline of one, writes nothing.

A merge request pipeline must name its source project, which GitLab does from 19.5.

<Takeaway>serve GitLab projects, including ones whose CI file lives elsewhere.</Takeaway>

### Several workflows and repositories

List each one, separated by spaces. Each repository reads and writes only its own data:

```sh
ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml https://token.actions.githubusercontent.com:acme/site:ci.yml'
```

<Takeaway>share one server between workflows and repositories, each kept apart.</Takeaway>

### Let laptops read

`READ_ACCESS=public` lets a request with no token, such as a laptop's, read a repository `ALLOW` names. It never writes.

The cache and history servers read it; the distributed task execution server does not.

<Takeaway>give every laptop CI's results without handing out a token.</Takeaway>

### A merge queue

A GitHub merge queue run (`merge_group`) writes `main` before its code lands. Its ref is `refs/heads/gh-readonly-queue/main/pr-<n>-<sha>`.

A plain push to a branch of that name writes only that branch.

Code you queue is code you trust. Run security checks on the pull request, before it is queued.

<Takeaway>use a merge queue and still keep `main`'s results trusted.</Takeaway>

</Deeper>

<Deeper level="details" title="Every shared setting">

### `ALLOW`, `AUDIENCE`, `READ_ACCESS`

| Setting | Default | What it does | Example |
| --- | --- | --- | --- |
| `ALLOW` | required | who takes part: space-separated `issuer:owner/repo:workflow` entries | `https://gitlab.com:acme/web:.gitlab-ci.yml` |
| `AUDIENCE` | Workers: the URL the server is reached at. Bun and Docker: required | the `aud` every CI token must name, read as its origin | `https://cache.example.com` |
| `READ_ACCESS` | unset: every request needs a token | `public`: a request with no token reads a repository `ALLOW` names. Cache and history servers only | `public` |

On Workers, leave `AUDIENCE` unset. On Bun and Docker, set it: there the URL is the request's `Host` header, which a client picks.

### Docker Compose settings

Each setting gets its service's prefix in `.env`, so one file holds all three:

| Service | Port | Settings it reads |
| --- | --- | --- |
| `dte` | 8080 (`DTE_PORT`) | `DTE_ALLOW`, `DTE_AUDIENCE` |
| `cache` | 8081 (`CACHE_PORT`) | `CACHE_ALLOW`, `CACHE_AUDIENCE`, `CACHE_READ_ACCESS`, `S3_*`, `MAX_*` |
| `history` | 8082 (`HISTORY_PORT`) | `HISTORY_ALLOW`, `HISTORY_AUDIENCE`, `HISTORY_READ_ACCESS`, `TIMING_DAYS` |

The history server keeps its SQLite file in the `history` volume.

### What each run may do

| Run | Reads | Writes |
| --- | --- | --- |
| push to a branch | that branch, then the default branch | that branch |
| `pull_request` | its merge ref, its branch, the branch it merges into, the default branch | its merge ref, `refs/pull/<n>/merge` |
| `merge_group` | the branch it merges into | that branch |
| `pull_request_target`, `issue_comment`, `workflow_run` | as its pull request | nothing |
| another workflow or repository | nothing | nothing |
| no token, `READ_ACCESS=public` | the repositories `ALLOW` names | nothing |

### What the servers see

Every request names its issuer and repository, as `vxCache({ issuer, repository })` and `vxHistory({ issuer, repository })` declare them. A token of another repository is refused.

The cache server sees each of them, and each branch, only as the first 128 bits of its SHA-256 in hex. The history server sees them as they are ([What it keeps](history/#what-it-keeps)).

A renamed repository starts with an empty cache.

### When a server refuses to start

The Bun server and its image refuse to start without `ALLOW` or `AUDIENCE`, and name what is missing:

```ansi title="no ALLOW"
[38;2;239;68;68m✗[0m [1mvx-cache-server[0m  set ALLOW
[2musage: vx-cache-server [--port 8080] [--host 0.0.0.0][0m
```

```ansi title="an ALLOW entry with no issuer or workflow"
[38;2;239;68;68m✗[0m [1mvx-dte-server[0m  ALLOW: acme/app is not issuer:owner/repo:workflow
```

A Worker with `ALLOW` empty starts, and refuses every request: `ALLOW is empty: set it to the CI workflows this server serves`.
