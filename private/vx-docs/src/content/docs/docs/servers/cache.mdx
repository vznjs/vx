<Concept term="Remote cache">
  A cache on a server instead of one machine's disk. vx asks its own `.vx/cache` first, then the
  remote one.
</Concept>

`@vzn/vx-cache-server` keeps results in one bucket, Cloudflare R2 or any S3 bucket. No database, no state on the server. [Remote cache](../../remote-cache/) walks the whole setup on Cloudflare.

## Deploy it

<Tabs syncKey="server-host">
<TabItem label="Cloudflare Workers">

Results go in R2.

```sh
mkdir ~/vx-cache-server && cd ~/vx-cache-server
bun add @vzn/vx-cache-server
```

```jsonc title="wrangler.jsonc"
{
  "name": "vx-cache-server",
  "main": "node_modules/@vzn/vx-cache-server/src/worker.ts",
  "compatibility_date": "2026-10-01",
  "vars": { "ALLOW": "https://token.actions.githubusercontent.com:acme/app:ci.yml" },
  "r2_buckets": [{ "binding": "BLOBS", "bucket_name": "vx-cache" }]
}
```

```sh
bunx wrangler login
bunx wrangler deploy
```

The first deploy creates the R2 bucket `vx-cache`. Every setting below is a var in `wrangler.jsonc`.

</TabItem>
<TabItem label="Bun">

Results go in any S3-compatible bucket:

```sh
ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml' \
AUDIENCE=https://cache.example.com \
S3_BUCKET=vx-cache S3_ENDPOINT=https://s3.example.com \
S3_ACCESS_KEY_ID=… S3_SECRET_ACCESS_KEY=… \
bunx @vzn/vx-cache-server --port 8080
```

```ansi
[38;2;34;197;94m✓[0m [1mvx-cache-server[0m  listening on [38;2;6;182;212mhttp://0.0.0.0:8080/[0m
```

The green line means it is up. Run as many as you like over one bucket, behind a load balancer.

</TabItem>
<TabItem label="Docker">

```sh
docker run -p 8080:8080 -e ALLOW='…' -e AUDIENCE=https://cache.example.com -e S3_BUCKET=… -e S3_ENDPOINT=… \
  -e S3_ACCESS_KEY_ID=… -e S3_SECRET_ACCESS_KEY=… ghcr.io/vznjs/vx-cache-server
```

Or run it beside the other two with [Docker Compose](../#run-all-three-with-docker-compose): the `cache` service, on port 8081.

</TabItem>
</Tabs>

Check it answers:

```sh
curl http://localhost:8080/v1/capabilities   # Workers: your workers.dev URL
```

```json
{"code":"bad_request","message":"vx-issuer and vx-repository: the issuer's and the repository's hashes (PROTOCOL.md § Keys)"}
```

That refusal is good news: the server is up and has an `ALLOW`. Put HTTPS in front of it.

<Takeaway>run your own remote cache on Cloudflare, Bun or Docker.</Takeaway>

## Point vx at it

<Steps>

1. Back in your workspace, add the plugins at its root:

   ```sh
   bun add -d @vzn/vx-cache @vzn/vx-ci
   ```

2. Name the server in `.vx/workspace.ts`:

   ```ts title=".vx/workspace.ts" ins={4,10-14}
   import { defineWorkspace } from '@vzn/vx/config'
   import { github } from '@vzn/vx-ci'
   import { bun } from '@vzn/vx-lockfile'
   import { vxCache } from '@vzn/vx-cache'

   export default defineWorkspace({
     plugins: [
       bun(),
       github(),
       vxCache({
         url: 'https://cache.example.com',
         issuer: 'https://token.actions.githubusercontent.com',
         repository: 'acme/app',
       }),
     ],
     // keep your pipelines as they are
   })
   ```

3. Let each CI job ask for its token:

   <Tabs syncKey="ci">
   <TabItem label="GitHub Actions">

   ```yaml title=".github/workflows/ci.yml"
   permissions:
     contents: read
     id-token: write
   ```

   </TabItem>
   <TabItem label="GitLab CI">

   ```yaml title=".gitlab-ci.yml"
   vx:
     id_tokens:
       VX_CACHE_TOKEN:
         aud: https://cache.example.com
   ```

   </TabItem>
   </Tabs>

4. Run `vx lock`, commit and push.

</Steps>

`github()` (or `gitlab()`) tells the cache which branch a run is on. Without it, a CI run reads only its own branch and the default branch.

<Takeaway>connect your CI to the cache server and share results between runners.</Takeaway>

## Which results a run gets

A run reads the closest branch first, then falls back:

<Diagram {...cacheReadOrder} />

A pull request reads its merge ref, then its own branch, then the branch it merges into. It writes only its merge ref. [Servers](../#say-who-takes-part-allow) shows every kind of run.

<Quiz q="A push to main stored @demo/ui#build. Pull request #7 has not touched @demo/ui. Does it build @demo/ui?">
  No. Its merge ref and `feat-x` miss, then `main` holds the same key: a hit.
</Quiz>

<Takeaway>predict which branch's result a pull request reuses.</Takeaway>

## Expire old results

The server never deletes anything. Give the bucket a lifecycle rule that does. On R2, one day:

```sh
bunx wrangler r2 bucket lifecycle add vx-cache all '' --expire-days 1
```

On S3, put the same rule in the bucket's lifecycle configuration. A run that misses an expired result runs the task and stores it again.

<Takeaway>keep the bucket small without touching the server.</Takeaway>

<Deeper level="patterns" title="Common setups">

### A proxy in front, such as Cloudflare Access

Pass its service token in `headers`:

```ts title=".vx/workspace.ts"
vxCache({
  url: 'https://cache.example.com',
  issuer: 'https://token.actions.githubusercontent.com',
  repository: 'acme/app',
  headers: {
    'CF-Access-Client-Id': process.env.CF_ACCESS_CLIENT_ID,
    'CF-Access-Client-Secret': process.env.CF_ACCESS_CLIENT_SECRET,
  },
})
```

An unset value is left out. The `authorization` header stays the CI token's. Workers of a [Distributed task execution](../../distributed-task-execution/) run send the headers too, so give their job the same secrets.

<Takeaway>put the cache server behind your own access proxy.</Takeaway>

### Laptops read CI's results

Set `READ_ACCESS=public` on the server. A laptop has no token, so it reads and never uploads. Any other server refuses its first read: vx says so once and goes on with the local cache.

<Takeaway>let every developer start from what CI built.</Takeaway>

### The URL from the environment

Leave `url` out and set `VX_CACHE_URL`. With Distributed task execution, the run lends its token to its workers, so they read and write where the run does.

<Takeaway>keep one config for several cache servers.</Takeaway>

### Prune one branch

Delete its folder in the bucket: `<issuer>/<repository>/<ref>/`. Each name is the first 32 hex digits of that value's SHA-256:

```sh
h() { printf %s "$1" | sha256sum | cut -c1-32; }
echo "$(h https://token.actions.githubusercontent.com)/$(h acme/app)/$(h refs/heads/main)/"
```

<Takeaway>drop one branch's results by hand.</Takeaway>

</Deeper>

<Deeper level="details" title="Every option and how it stores results">

### Server settings

| Setting | Default | What it does | Example |
| --- | --- | --- | --- |
| `ALLOW` | required | who takes part ([`ALLOW`](../#say-who-takes-part-allow)) | `https://token.actions.githubusercontent.com:acme/app:ci.yml` |
| `AUDIENCE` | Workers: the URL it is reached at. Bun and Docker: required | the `aud` a CI token must name, read as its origin | `https://cache.example.com` |
| `READ_ACCESS` | unset: every request needs a token | `public`: a request with no token reads a repository `ALLOW` names | `public` |
| `S3_BUCKET` | Bun and Docker: required | the bucket | `vx-cache` |
| `S3_ENDPOINT` | Bun's S3 default | the bucket's endpoint | `https://s3.example.com` |
| `S3_REGION` | Bun's S3 default | the bucket's region | `eu-west-1` |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | required | the bucket's credentials | |
| `S3_SESSION_TOKEN` | none | a temporary credential's session token | |
| `MAX_CHECK_HASHES` | 500 (6 on Workers) | lookups one check may make, results × branches | `100` |
| `MAX_UPLOAD_BYTES` | 100 MB | the largest result it takes | `500000000` |
| `EXPIRY_DAYS` | unset | Workers: your bucket's expiry, so a repeat check skips R2 | `1` |
| `BLOBS` | | Workers: the R2 bucket binding | `vx-cache` |
| `--port` | 8080 | Bun: the port it listens on | `--port 9000` |
| `--host` | `0.0.0.0` | Bun: the address it listens on | `--host 127.0.0.1` |

vx learns the limits from the server's answers. A check over them is sent again in parts. A result over the upload limit is not uploaded, with a warning.

On Workers each lookup is one subrequest, so a higher `MAX_CHECK_HASHES` must fit your Cloudflare plan.

A bad value stops the Bun server before it listens:

```ansi title="MAX_UPLOAD_BYTES=abc"
[38;2;239;68;68m✗[0m [1mvx-cache-server[0m  MAX_UPLOAD_BYTES: not a whole number above 0: abc
```

### `vxCache()` options

Every option of the plugin (`url`, `issuer`, `repository`, `timeoutMs`, `uploadTimeoutMs`, `retries`, `headers`) is on [Remote cache](../../remote-cache/#vxcache-options).

### How it stores results

<Diagram {...cacheBucketPath} />

A result's name is `<issuer>/<repository>/<branch>/<key>`. The first three are hashed: the first 32 hex digits of their SHA-256.

So the bucket's listing shows no host, repository or branch name. One repository never reads another's results.

A result is never rewritten: a second upload of the same key keeps the first bytes.

On Workers, a download goes through Cloudflare's cache. After R2 serves a result once, that data center answers it without R2.

Whether a result exists is always asked of R2, so every data center agrees.

With `EXPIRY_DAYS` set, an answer R2 gives leaves an "exists" mark in that data center until R2 may drop the result. A repeat check there skips R2.

A miss, an upload, and a download R2 misses always ask R2.

### API

Turbo's routes under `/v1`, each read naming the branches it reads ([PROTOCOL.md](https://github.com/vznjs/vx/blob/main/packages/vx-cache-server/PROTOCOL.md)):

| Route | Does |
| --- | --- |
| `GET /v1/artifacts/<hash>` | one result's bytes, from the first of the branches in `vx-scope` holding it |
| `HEAD /v1/artifacts/<hash>` | whether one of those branches holds it, and its size |
| `PUT /v1/artifacts/<hash>` | one result's bytes, to the token's branch |
| `POST /v1/artifacts` | `{ hashes, scopes }`: each hash's size and the first branch holding it |
| `GET /v1/capabilities` | the limits |

A branch on the wire is its ref, percent-encoded (`refs%2Fheads%2Fmain`). Any other spelling is refused with `400`. Any server that speaks the protocol can stand in for this one.

To mount it in your own server, `createCacheServer({ blobs, authorize, limits? })` returns a `fetch` handler over your bucket. The [README](https://github.com/vznjs/vx/tree/main/packages/vx-cache-server#api) lists the whole API.
