[Distributed task execution](../../distributed-task-execution/) (DTE)
needs a relay. `@vzn/vx-dte-server` is that relay. You host your own, on
Cloudflare, Bun or Docker.

CI runners accept no incoming connection, so the run and its workers all
connect out to the relay, and it passes their messages on.

It stores nothing and keeps no secret. It cannot read what it passes
on: the run and its workers encrypt it. Files never go through it; they
go through your [remote cache](../../remote-cache/).

## 1. Deploy the relay

<Tabs syncKey="relay-host">
<TabItem label="Cloudflare (button)">

[Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/vznjs/vx/tree/main/packages/vx-dte-server)

The button copies the relay into a new repository of yours and deploys
it. It asks for one var, `ALLOW` (step 2). The relay's URL is the
Worker's, such as `https://vx-dte-server.acme.workers.dev`.

</TabItem>

mkdir vx-dte-server && cd vx-dte-server

    "bindings": [{ "name": "RELAY", "class_name": "RelayRun" }]

  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["RelayRun"] }]

Fill `ALLOW` (step 2), then:

```sh
bunx wrangler login
bunx wrangler deploy
```

</TabItem>
<TabItem label="Bun">

## 2. Say who may use it: `ALLOW`

`ALLOW` lists the workflows whose jobs may join a run, one entry per
workflow, as `issuer:owner/repo:workflow`, separated by spaces.

List the workflow that runs `vx run` and the workers' workflow.
`vx dte init` prints the line for you. Every other job is refused.

```jsonc title="wrangler.jsonc"
"vars": {
  "ALLOW": "https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml"
}
```

| CI | One entry |
| --- | --- |
| GitHub Actions | `https://token.actions.githubusercontent.com:acme/app:ci.yml` |
| GitLab CI | `https://gitlab.com:group/project:.gitlab-ci.yml` |

On Bun and Docker, `ALLOW` is an environment variable of the same
form. GitLab names a project by its full path, `group/subgroup/project`.

<Aside type="caution" title="A plain var, not a secret">
  `ALLOW` names repositories, nothing secret. Keep it in your
  `wrangler.jsonc`: each deploy sets vars from that file, so a var set
  only in the Cloudflare dashboard is lost on the next deploy.
</Aside>

## 3. Check it answers

A request with no token is refused, and says why:

```sh
curl https://relay.example.com/v1/sessions/$(uuidgen)/socket
```

```json
{"error":"no bearer token"}
```

A Cloudflare relay with an empty `ALLOW` says
`this relay's ALLOW is empty: it admits no run` instead.

## 4. Name it in `dte()`

```ts title=".vx/workspace.ts"
dte({
  relay: 'https://relay.example.com',
  workers: { small: { max: 8, cpu: 4, memory: '16GB' } },
  adapter: github(),
})
```

Each job proves who it is with its CI token for the relay's URL.

On GitHub Actions both workflows need `permissions: { id-token: write }`,
which `vx dte init` writes. On GitLab, the run's job and the workers'
job each ask for a token:

```yaml title=".gitlab-ci.yml"
vx:
  id_tokens:
    VX_DTE_TOKEN:
      aud: https://relay.example.com
```

[Distributed task execution](../../distributed-task-execution/) walks through the rest.

## Settings

| Setting | Cloudflare | Bun and Docker | What it sets |
| --- | --- | --- | --- |
| who may take part | `ALLOW` var | `ALLOW` | `issuer:owner/repo:workflow` entries |
| audience | `AUDIENCE` var, unset: the relay's URL | `AUDIENCE` | the `aud` every token must name |
| listen | | `--port` (8080), `--host` (`0.0.0.0`) | where it listens |

Set `AUDIENCE` only when your tokens name a URL other than the one the
relay is reached at.

## What to know

- A run belongs to the repository that started it. A worker of another
  repository cannot join it, even one `ALLOW` lists.
- On Cloudflare each run is one Durable Object, and the relay fits the
  free plan: 20 websocket messages count as one Durable Object request,
  against 100,000 a day.
- A deploy, or a restart on Bun or Docker, forgets the runs in flight.
  The run and its workers connect again, and the work goes on.
- A job whose connection drops may connect again within 10 s. A run ends
  when its `vx run` job leaves, or drops and does not come back in time.
- On Bun, 10 000 connections over 100 runs take 41 MB more than an idle
  relay (measured 2026-10-24, 4 cores).

## API

The wire is [Switchboard v1](../../../switchboard/), an open protocol.
Any server that speaks it can stand in for this relay.

| Part | Value |
| --- | --- |
| connection | one websocket per job, `GET /v1/sessions/<session>/socket` |
| subprotocol | `switchboard.v1` |
| auth | the job's CI token, as a bearer token |

To mount the relay in a server of your own:

- `createRelay()` returns a `fetch` handler;
- `serveRelay()` serves it on `Bun.serve`;
- `createVerifier()` checks the CI tokens against `parseAllow(ALLOW)`.

The [README](https://github.com/vznjs/vx/tree/main/packages/vx-dte-server#api)
lists the whole API.
