The Distributed task execution server, or DTE server, is the relay where one `vx run` meets its workers on other CI machines. You host it:

```sh
bunx @vzn/vx-dte-server --port 8080
```

<Levels />

<Diagram {...dteRun} />

<Concept term="Relay">
  A small server that passes messages between your run and its workers. It reads nothing it passes:
  every message is encrypted end to end. CI machines all dial out to it.
</Concept>

The relay stores nothing, keeps no secret and cannot read what it passes: the run and its workers encrypt it. Files never go through it; they go through your [remote cache](../../remote-cache/).

## Deploy the relay

<Tabs syncKey="relay-host">
<TabItem label="Cloudflare (button)">

[Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/vznjs/vx/tree/main/packages/vx-dte-server)

The button copies the relay into a new repository of yours and deploys it. It asks for one var, `ALLOW`. The relay's URL is the Worker's, such as `https://vx-dte-server.acme.workers.dev`.

</TabItem>
<TabItem label="Cloudflare (wrangler)">

```sh
mkdir ~/vx-dte-server && cd ~/vx-dte-server
bun add @vzn/vx-dte-server
```

```jsonc title="wrangler.jsonc"
{
  "name": "vx-dte-server",
  "main": "node_modules/@vzn/vx-dte-server/src/worker.ts",
  "compatibility_date": "2026-10-01",
  "vars": {
    "ALLOW": "https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml"
  },
  "durable_objects": {
    "bindings": [{ "name": "RELAY", "class_name": "RelayRun" }]
  },
  "migrations": [{ "tag": "v1", "new_sqlite_classes": ["RelayRun"] }]
}
```

```sh
bunx wrangler login
bunx wrangler deploy
```

</TabItem>
<TabItem label="Bun">

```sh
ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml' \
AUDIENCE=https://relay.example.com \
bunx @vzn/vx-dte-server --port 8080
```

```ansi
[38;2;34;197;94m✓[0m [1mvx-dte-server[0m  listening on [38;2;6;182;212mhttp://0.0.0.0:8080[0m
```

The green line means it is up. Put it behind HTTPS.

</TabItem>
<TabItem label="Docker">

```sh
docker run -p 8080:8080 \
  -e ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml' \
  -e AUDIENCE=https://relay.example.com \
  ghcr.io/vznjs/vx-dte-server
```

Or run it beside the other two with [Docker Compose](../#run-all-three-with-docker-compose): the `dte` service, on port 8080, with `DTE_ALLOW` and `DTE_AUDIENCE`.

</TabItem>
</Tabs>

<Takeaway>host your own relay on Cloudflare, Bun or Docker.</Takeaway>

## Say who may use it

`ALLOW` lists two workflows: the one that runs `vx run`, and the workers' one. `vx dte init` prints the line for you.

```sh
ALLOW='https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml'
```

Every other job is refused. [Servers](../#say-who-takes-part-allow) explains each entry.

<Aside type="caution" title="A plain var, not a secret">
  `ALLOW` names repositories, nothing secret. Keep it in `wrangler.jsonc`: a var set only in the
  Cloudflare dashboard is lost on the next deploy.
</Aside>

<Quiz q="A worker of acme/site, which ALLOW also lists, tries to join a run of acme/app. Is it let in?">
  No. A run belongs to the repository that started it. A worker of another repository never joins
  it.
</Quiz>

<Takeaway>let exactly your two workflows meet at the relay.</Takeaway>

## Check it, then name it in `dte()`

<Walkthrough title="From a refusal to a run">
<Frame title="1. Ask with no token">

```sh
curl https://relay.example.com/v1/sessions/$(bun -e 'console.log(crypto.randomUUID())')/socket
```

```json
{"error":"no bearer token"}
```

A refusal that says why: the relay is up.

On Cloudflare, an empty `ALLOW` answers `this relay's ALLOW is empty: it admits no run` instead. The Bun relay does not start without one.

</Frame>
<Frame title="2. Name the relay">

```ts title=".vx/workspace.ts" ins={2}
dte({
  relay: 'https://relay.example.com',
  workers: {
    linux: {
      machines: {
        cpu4: {
          max: 8,
          cpu: 4,
          memory: '16GB',
        },
      },
    },
  },
  adapter: github(),
})
```

</Frame>
<Frame title="3. Give each job a token">

On GitHub Actions both workflows need `permissions: { id-token: write }`, which `vx dte init` writes. On GitLab, each job asks:

```yaml title=".gitlab-ci.yml"
vx:
  id_tokens:
    VX_DTE_TOKEN:
      aud: https://relay.example.com
```

</Frame>
<Frame title="4. Push: workers take tasks">

```ansi title="the end of the run"

```

Read the **workers** line: worker `linux.cpu4#1` joined through the relay and ran 2 tasks.

</Frame>
</Walkthrough>

<Deeper level="patterns" title="Common setups">

### Test a relay on one machine

`--no-auth` turns off the token check. It listens on loopback only, so nothing outside your machine reaches it:

```sh
bunx @vzn/vx-dte-server --no-auth --port 8080
```

```ansi
[38;2;34;197;94m✓[0m [1mvx-dte-server[0m  listening on [38;2;6;182;212mhttp://127.0.0.1:8080[0m
```

To try Distributed task execution with no relay to host, use `local()`: it [starts one on your machine](../../distributed-task-execution/try-on-your-machine/).

<Takeaway>run the relay locally with no CI tokens.</Takeaway>

### A deploy in the middle of a run

A deploy, or a restart on Bun or Docker, forgets the runs in flight. The run and its workers connect again, and the work goes on.

<Takeaway>update the relay any time, even while runs use it.</Takeaway>

### Cloudflare's free plan

Each run is one Durable Object. 20 websocket messages count as one request, against 100,000 a day, so the relay fits the free plan.

<Takeaway>host the relay at no cost.</Takeaway>

</Deeper>

<Deeper level="details" title="Every setting and the wire">

### Settings

| Setting | Default | What it does | Example |
| --- | --- | --- | --- |
| `ALLOW` | required | who takes part: space-separated `issuer:owner/repo:workflow` | `https://gitlab.com:group/project:.gitlab-ci.yml` |
| `AUDIENCE` | Cloudflare: the relay's URL. Bun and Docker: required | the `aud` every CI token must name, with or without a trailing slash | `https://relay.example.com` |
| `RELAY` | Cloudflare: required | Cloudflare: the Durable Object binding, class `RelayRun` | `{ "name": "RELAY", "class_name": "RelayRun" }` |
| `--port` | 8080 | Bun: the port it listens on | `--port 9000` |
| `--host` | `0.0.0.0`; `127.0.0.1` with `--no-auth` | Bun: the address it listens on | `--host ::1` |
| `--no-auth` | off | Bun: no token check, loopback only | `--no-auth` |

On Cloudflare, set `AUDIENCE` only when your tokens name a URL other than the one the relay is reached at. GitLab names a project by its full path, `group/subgroup/project`.

The Bun relay names what is missing and stops:

```ansi
[38;2;239;68;68m✗[0m [1mvx-dte-server[0m  missing ALLOW and AUDIENCE (or --no-auth)
[2musage: vx-dte-server [--port 8080] [--host 0.0.0.0][0m
```

```ansi title="--no-auth --host 0.0.0.0"
[38;2;239;68;68m✗[0m [1mvx-dte-server[0m  --no-auth listens on loopback only
```

### Connections

- A job whose connection drops may connect again within 10 s.
- A run ends when its `vx run` job leaves, or drops and does not come back in time.
- On Bun, 10 000 connections over 100 runs take 41 MB more than an idle relay (measured 2026-10-24, 4 cores).

### The wire

[Switchboard v1](../../../switchboard/), an open protocol. Any server that speaks it can stand in for this relay.

| Part | Value |
| --- | --- |
| connection | one websocket per job, `GET /v1/sessions/<session>/socket` |
| subprotocol | `switchboard.v1` |
| auth | the job's CI token, as a bearer token |

To mount the relay in your own server:

| Function | Does |
| --- | --- |
| `createRelay()` | returns a `fetch` handler |
| `serveRelay()` | serves it on `Bun.serve` |
| `createVerifier()` | checks CI tokens against `parseAllow(ALLOW)` |

The [README](https://github.com/vznjs/vx/tree/main/packages/vx-dte-server#api) lists the whole API.

</Deeper>
