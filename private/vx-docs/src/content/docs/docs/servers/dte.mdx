import { Aside, Steps, Tabs, TabItem } from '@astrojs/starlight/components'

`@vzn/vx-dte-server` is the relay a [distributed run](../../distributed-runs/)
needs: CI runners take no inbound connection, so the run and its workers
all dial out to it, and it passes their messages on. You host your own.
It runs on Cloudflare's free plan, or on Bun or Docker anywhere your CI
can reach. It keeps no secret and stores no file.

<Aside title="Not on npm yet">
  Until `@vzn/vx-dte` and `@vzn/vx-dte-server` are on npm, run them from a
  checkout of the vx repository.
  Run vx from the same checkout: `bun install` there, then
  `bun /path/to/vx/packages/vx/src/bin.ts run …` in your repository. A
  plugin from main does not load into the vx on npm.
</Aside>

<Steps>

1. **Deploy the relay.**

   [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/vznjs/vx/tree/main/packages/vx-dte-server)

   The button copies the relay into a new repository of yours and deploys
   it. It asks for one var, `ALLOW` (step 2). The relay's URL is the
   Worker's, such as `https://vx-dte-server.<you>.workers.dev`.

   </TabItem>
   <TabItem label="Cloudflare (wrangler)">

   From `packages/vx-dte-server` in a checkout of the vx repository, with
   `ALLOW` filled in `wrangler.jsonc`'s `vars` first:

   ```sh
   bun install
   bunx wrangler login
   bunx wrangler deploy
   ```

   </TabItem>
   <TabItem label="Bun">

   From a checkout of the vx repository:

   ```sh
   bun packages/vx-dte-server/src/bun.ts \
     --allow https://token.actions.githubusercontent.com:acme/app:ci.yml \
     --allow https://token.actions.githubusercontent.com:acme/app:vx-worker.yml \
     --audience https://relay.example.com --port 8080
   ```

   `--audience` is the relay's public URL. Put it behind HTTPS.

   </TabItem>
   <TabItem label="Docker">

   ```sh
   docker build -t vx-dte-server packages/vx-dte-server
   docker run -p 8080:8080 vx-dte-server \
     --allow https://token.actions.githubusercontent.com:acme/app:ci.yml \
     --allow https://token.actions.githubusercontent.com:acme/app:vx-worker.yml \
     --audience https://relay.example.com
   ```

   Or run it with the other two servers using
   [Docker Compose](../#all-three-with-docker-compose): the `dte`
   service, on port 8080, with `DTE_ALLOW` and `DTE_AUDIENCE`.

   </TabItem>
   </Tabs>

2. **Say who may use it: `ALLOW`.** One entry per workflow,
   `issuer:owner/repo:workflow`, space separated. List both the
   workflow that runs `vx run` and the workers' workflow; every other
   token is refused.

   ```jsonc title="wrangler.jsonc"
   "vars": {
     "ALLOW": "https://token.actions.githubusercontent.com:acme/app:ci.yml https://token.actions.githubusercontent.com:acme/app:vx-worker.yml"
   }
   ```

   - GitHub Actions: `https://token.actions.githubusercontent.com:acme/app:ci.yml`
   - GitLab: `https://gitlab.com:group/project:.gitlab-ci.yml`

   On Bun and Docker each entry is one `--allow`. GitLab names a project
   by its full path, `group/subgroup/project`.

   <Aside type="caution" title="A plain var, not a secret">
     `ALLOW` names repositories, nothing secret. Keep it in your copy's
     `wrangler.jsonc`: each deploy sets vars from that file, so one set
     only in the dashboard is lost on the next deploy.
   </Aside>

3. **Check it answers.** A request with no token is refused by name:

   ```sh
   curl https://relay.example.com/v1/sessions/$(uuidgen)/socket
   ```

   ```text
   {"error":"no bearer token"}
   ```

   A Cloudflare relay with an empty `ALLOW` says so instead:
   `this relay's ALLOW is empty: it admits no run`.

4. **Name it in `dte()`.**

   ```ts title=".vx/workspace.ts"
   dte({
     relay: 'https://relay.example.com',
     workers: { small: { max: 8, cpu: 4, memory: '16GB' } },
     adapter: github(),
   })
   ```

   Each side proves itself with its job's OIDC token for the relay's URL,
   so no secret is stored. On GitHub Actions both workflows need
   `permissions: { id-token: write }`; on GitLab the orchestrator and
   worker jobs ask for one: `id_tokens: { VX_DTE_TOKEN: { aud: https://relay.example.com } }`.

</Steps>

## What to know

- The relay carries orders and status, never files: outputs go through
  your [remote cache](../../remote-cache/).
- On Cloudflare each run is one Durable Object, and the relay fits the
  free plan: websocket messages count 20 to one Durable Object request,
  against 100,000 a day, and it writes no row. A deploy, or a restart
  on Bun and Docker, forgets the runs in flight: vx-dte joins each again
  and the work goes on.
- The wire is [Switchboard v1](../../../switchboard/), an open protocol: any
  server that speaks it can stand in for this relay.
- `AUDIENCE` (Cloudflare) is unset by default: tokens must name the URL
  the relay is reached at. Set it only when they name another one.
- A run is bound to the issuer and repository that started it
  (`repository_id` on GitHub, `project_id` on GitLab): a worker of another repository cannot
  join it, even one `ALLOW` admits.
- A participant whose socket drops may dial back within 10 s. A run ends
  when the orchestrator leaves, or drops and does not dial back in time.
- On Bun, 10 000 sockets over 100 runs take 41 MB over an idle relay
  (measured 2026-10-24, 4 cores).

## Settings

| Setting | Cloudflare | Bun and Docker | What it sets |
| --- | --- | --- | --- |
| who may take part | `ALLOW` var | `--allow`, repeated | `issuer:owner/repo:workflow` entries |
| audience | `AUDIENCE` var, unset: the relay's URL | `--audience` | the `aud` every token must name |
| listen | | `--port` (8080), `--host` (`0.0.0.0`) | where it listens |

## Point vx at it: `dte()`

`dte({ relay, workers, adapter })` from `@vzn/vx-dte` sends the run's
tasks to workers your CI starts. The adapter starts them: `github()`,
`gitlab()`, `docker()`, or `local()` (workers in git worktrees, to try it
on one machine). `vx dte init` writes the run's workflow and the
workers' (`ci.yml` and `vx-worker.yml` on GitHub). The
[distributed runs page](../../distributed-runs/) walks through a run.

## API

The routes are [Switchboard v1](../../../switchboard/): one websocket per
participant, `GET /v1/sessions/<session>/socket`, with the subprotocol
`switchboard.v1` and the job's OIDC token as a bearer token. To mount the
relay in a server of your own, `createRelay()` returns a `fetch` handler,
`serveRelay()` serves it on `Bun.serve`, and `createVerifier()` checks the
CI tokens against `parseAllow(ALLOW)`. The
[README](https://github.com/vznjs/vx/tree/main/packages/vx-dte-server#api)
lists the whole API.
