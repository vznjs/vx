One CI job is too slow for your build? Hand its tasks to more machines. You still start one job and get one result.

```sh
vx run build test lint --all
```

<Levels />

<DteSpread />

Press the buttons to replay real runs. Each bar is a task on the worker that ran it. A task the cache already has never needs a worker.

<Concept term="Worker">
  A machine that joins your run, takes tasks, runs them and hands back what they made. With an
  adapter, vx starts workers for you and stops them when the work runs out.
</Concept>

<Quiz q="Every task changed and you allow 3 workers. Why does the third one run nothing?">
  By the time it was ready, what was left was the outlined path: `@demo/web#test` waits for
  `@demo/ui#build`, and no extra machine shortens that.

  The run's own `best` line says so: 2 machines end as soon.
</Quiz>

<Takeaway>predict which tasks need a worker, and why more workers is not always faster.</Takeaway>

## What happens in one run

<Walkthrough title="One run of build test lint, step by step">
<Frame title="1. Your CI job plans">

`vx run` works out which tasks must run. A task the cache has is restored right there. The rest is work, and work needs workers.

</Frame>
<Frame title="2. Workers join through the relay">

<Diagram {...dteRun} />

Workers dial out to the [relay](../servers/dte/), since a CI machine takes no incoming call. The relay passes orders and status. Files go through the [remote cache](../remote-cache/).

</Frame>
<Frame title="3. Each worker runs tasks">

A worker checks out your commit, runs each task it gets, and saves the outputs to the cache. Your CI job restores them, as if the task ran there.

</Frame>

### One task on another machine, or a bigger one

`exec.worker: 'ubuntu'` sends a task to the `ubuntu` worker type ([how](run-a-task-on-its-own-machine/)). A second machine size gets the tasks that filled the first ([how](add-bigger-machines/)).

### macOS workers

A machine with a `platform` takes the tasks whose `exec.platforms` name it:

```ts title=".vx/workspace.ts"
mac: {
  machines: {
    m1: {
      max: 2,
      cpu: 3,
      memory: '7GB',
      platform: 'darwin-arm64',
    },
  },
},
```

`vx dte init` runs it on `macos-latest`.

### GitLab

`gitlab()` triggers a pipeline of your `.gitlab-ci.yml` for each wave of workers, with the job's own `CI_JOB_TOKEN`. `vx dte init` writes the file.

```ts title=".vx/workspace.ts"
dte({
  relay: 'https://relay.example.com',
  workers: {
    linux: {
      machines: {
        small: { max: 4, cpu: 2, memory: '8GB' },
      },
    },
  },
  adapter: gitlab({
    tags: {
      'linux.small': ['saas-linux-small-amd64'],
    },
  }),
}),
```

<Aside type="caution" title="GitLab refuses triggers by default">
  Set Settings > CI/CD > Variables > "Minimum role to use pipeline variables" to **Developer**, or
  every trigger fails.
</Aside>

### Workers you start yourself

With no `adapter`, vx starts nothing. Name the relay, then share one random run id and key:

```ts title=".vx/workspace.ts"
dte({
  relay: 'https://relay.example.com',
  workers: {
    linux: {
      machines: {
        cpu4: { cpu: 4, memory: '16GB' },
      },
    },
  },
}),
```

```sh
export VX_DTE_RUN=$(bun -e 'console.log(crypto.randomUUID())')
export VX_DTE_SECRET=$(openssl rand -base64 32)
vx run build --all   # on the machine that starts the run
vx dte worker        # on each worker, with the same two variables
```

`VX_DTE_RUN` must be a random UUID, so no one can guess the run.

A worker started before its run says the relay has no live run. A run with no worker yet says it is waiting for one to join, and shows no time left until one does.

<Takeaway>run only what changed, on the OS and size each task needs, on any CI.</Takeaway>

</Deeper>

<Deeper level="details" title="Every option of dte()">

```ts
dte({ workers, adapter, relay, token, unmeasured, headers })
```

| Option | What it does | Default |
| --- | --- | --- |
| `workers` | the worker types, in order of preference. Each is `{ machines }` | none: only workers that join on their own |
| `adapter` | how workers start: `github()`, `gitlab()`, `local()`, `docker()` | none: vx starts no worker |
| `relay` | the relay's base URL, `http(s)`, without `/v1`. `VX_DTE_RELAY` beats it | the adapter's own (`local()`, `docker()`) |
| `token` | the relay's bearer token. Asked again a minute before it expires | `VX_DTE_TOKEN`, else on GitHub Actions an OIDC token |
| `unmeasured` | `{ cpu, memory }`: what a task with no history uses. On a worker it takes any free core | 2 cores, 4 GB when vx picks workers to ask for |
| `headers` | headers on every call to the relay, for a proxy in front of it | none |

An unknown key is refused. With an `adapter`, at least one machine needs `max` above 0. The same options, with every plugin's, are on [Plugins](../plugins/).

**Each machine** in `workers.<type>.machines.<name>`, named `<type>.<name>` in the output (`linux.cpu4`):

| Field | What it does | Default |
| --- | --- | --- |
| `cpu` | its cores, which vx plans by until the worker reports its own | required |
| `memory` | bytes, or `'16GB'`, `'512MiB'` | required |
| `max` | how many may be in the run at once; one lost or failed to start is replaced | no cap |
| `platform` | `linux-x64`, `linux-arm64`, `darwin-x64` or `darwin-arm64`; a worker of another is refused | this machine's, not checked |
| `runsOn` | the CI runner label `vx dte init` writes for it | a GitHub runner of its platform, such as `ubuntu-latest` |

Names use letters, digits, `_` and `-`.

**Adapters:**

| Adapter | Starts each worker as | Options |
| --- | --- | --- |
| `github()` | a job of `vx-worker.yml`, dispatched by the run (up to 256) | `workflow`: the worker file in `.github/workflows` (default `vx-worker.yml`); `env`: variables every worker gets, no secrets |
| `gitlab()` | a job of a pipeline of `.gitlab-ci.yml` (up to 200) | `tags`: runner tags by machine, `{ 'linux.small': ['…'] }` |
| `local()` | a process in its own git worktree | `prepare`: a shell line each worktree runs first, such as `bun install` |
| `docker()` | a container held to the machine's `cpu` and `memory` | `image` (required): one with Bun and git; `prepare` |

`github()` needs `GITHUB_TOKEN` with `actions: write`, and `id-token: write` for its workers.

**Environment variables:**

| Variable | Read by | Means |
| --- | --- | --- |
| `VX_DTE_RUN` | run, worker | the run's id, a random UUID (`bun -e 'console.log(crypto.randomUUID())'`). Set, it turns distribution on. GitHub and GitLab name the run themselves |
| `VX_DTE_RELAY` | run, worker | the relay URL; beats `relay` |
| `VX_DTE_SECRET` | run, worker | the run's shared key. Needed with no adapter and no GitHub |
| `VX_DTE_TOKEN` | run, worker | the relay's bearer token, when `token` is unset |
| `VX_DTE_WORKER` | worker | its name, set by the adapter that started it |

**Task fields** that decide where a task runs (see [Tasks](../tasks/)):

| Field | On workers |
| --- | --- |
| `exec.worker` | runs only on that worker type. An unknown type stops the run before any task starts |
| `exec.platforms` | runs only on a machine of one of these platforms |
| `exec.remote: false` | still runs on a worker: no task runs on your CI job |
| `exec.sandbox` | the same sandbox, built on the worker |
| `exec.timeout` | counts from the task's start on its worker, not from the wait |

</Deeper>

<Deeper level="details" title="Rules for where a task runs">

### What runs where

- Every task runs on a worker, even one that waits for keyboard input. Only cache hits restore on your CI job.
- A task goes to a worker only when one of its cores is free and its memory fits.
- Of equal choices, a task goes to the busiest worker, so workers fill and the rest leave.
- A task no worker can take, such as one whose `exec.platforms` no machine offers, stops the run before any task starts.
- A task that reads what an uncached task left on another kind of machine stops the run before any task starts. Cache the upstream, or run both alike.
- A server a task depends on (a persistent task) starts on that task's worker, and stops when no task there needs it.
- A worker that is idle, and that the rest of the run cannot keep busy, leaves.
- A worker stopped with Ctrl-C leaves the run; its tasks run again on another worker.
- A task that reads a file git does not track fails, naming the file: no worker has it.

</Deeper>

<Deeper level="details" title="How it stays private">

- The relay reads nothing. The run and each worker agree on keys made for that session only ([Noise](https://noiseprotocol.org/noise.html)), through the relay.
- On GitHub Actions, each side proves it is a job of your repository with its CI token (OIDC). No secret is stored anywhere.
- Elsewhere, the run and each worker share `VX_DTE_SECRET`. A side without it cannot finish the handshake.
- A message the relay changes drops its worker; one it replays is dropped.
- Files never cross the relay: they go through your remote cache.

</Deeper>
