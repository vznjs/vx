Teach vx something new from one file. This plugin gives every project with a `vite.config.ts` a `test` task, so no config has to list it:

```ts
// plugins/vitest.ts
import path from 'node:path'
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function vitest(): VxPlugin {
  return definePlugin(import.meta, {
    async project(config, ctx) {
      if (!(await Bun.file(path.join(ctx.dir, 'vite.config.ts')).exists())) return
      config.tasks ??= {}
      config.tasks['test'] ??= {
        exec: { command: 'vitest run' },
        inputs: { files: ['src/**', 'vite.config.ts'] },
        outputs: { files: [] },
        cache: true,
      }
    },
  })
}
```

  A function that returns `definePlugin(import.meta, hooks)`. You list it in `.vx/workspace.ts`,
  and vx calls its hooks in every run. Its name is the name of the package it lives in.
</Concept>

2. **Fill the hooks you need.** A hook you leave out costs nothing.

## The hooks

<Concept term="Hook">
  One function on your plugin that vx calls at a fixed point of a run. Each hook changes one thing:
  the tasks, a key, the order, where a task runs, where results go.
</Concept>

A run passes the hooks in this order, with `setup` and `teardown` around it. Fill the one that owns what you want to change:

<Diagram {...pluginStages} />

| Stage | Hook | Use it to |
| --- | --- | --- |
| 1 | `config(ws, ctx)` | change the workspace config before vx reads it |
| 2 | `discover(ctx)` | make a directory a project, and say what it depends on |
| 3 | `project(config, ctx)` | add, remove or rewrite a project's tasks |
| 4 | `graph(nodes, ctx)` | add or drop the edges between tasks |
| 5 | `key(task, ctx)` | add what your inputs cannot see to the cache key |
| 6 | `fingerprint` | key a root file yourself, such as a lockfile |
| 7 | `measures(nodes)` | time work that is no task, such as a worker's start |
| 8 | `schedule(nodes, ctx)` | pick which ready task starts first |
| 9 | `admit(task, ctx)` | hold a ready task back until something finishes |
| 10 | `executor(ctx)` | run a task's command somewhere else |
| 11 | `cache(ctx)` | keep results in your own remote cache |
| 12 | `telemetry(ctx)` | send each run's records somewhere; it never changes the run |
| 13 | `output(ctx)` | draw the terminal yourself |
| start | `setup(ctx)` | connect, read a token, subscribe to events, before the first task |
| CLI | `commands` | add a verb to `vx` |
| end | `teardown()` | flush and close when the run ends |

Plugins are asked in the order you list them. Whatever every plugin declines, vx does itself on this machine.

<Quiz q="You want each e2e suite to run on a bigger machine. Which hook do you fill?">
  `executor`. It decides where a task's command runs. Its `accepts` can take only the tasks named
  `e2e` and decline the rest, which then run on this machine.
</Quiz>

<Takeaway>pick the one hook that makes the change you want.</Takeaway>

<Deeper level="details" title="The whole plugin type">

Every hook is optional. `name` is set for you from the nearest `package.json` with a name.

```ts
import type { VxPlugin } from '@vzn/vx'

interface VxPlugin {
  readonly name: string // your package's name: definePlugin reads it
  config?(workspace, ctx): void
  discover?(ctx): { dir; name?; deps?; reach? }[] // projects and their edges
  project?(config, ctx): void
  graph?(nodes, ctx): void
  key?(task, ctx): Record<string, string>
  fingerprint?: { files; affected(change, ctx); extraFiles?; digests? }
  measures?(nodes): Map<string, string>
  schedule?(nodes, ctx): Map<string, number>
  admit?(task, ctx): boolean
  executor?(ctx): TaskExecutor | undefined
  cache?(ctx): RemoteCacheLayer | undefined
  telemetry?(ctx): TelemetrySink | TelemetrySink[] | undefined
  output?(ctx): Logger | undefined // draw the run yourself
  commands?: { [verb]: { description: string; run(argv, ctx): number | Promise<number> } }
  setup?(ctx): void | Promise<void>
  teardown?(run?: RunReport): void | Promise<void>
}
```

Any hook but `admit`, `measures`, `fingerprint` and `commands` may return a promise. Most `ctx` objects share three fields:

| Field | What it is |
| --- | --- |
| `ctx.workspaceRoot` | the workspace's root directory, absolute |
| `ctx.cacheDir` | where vx keeps its cache (not on `config`'s, which may change it) |
| `ctx.warn(message)` | print one warning in the run's output |

Every type is on the [`@vzn/vx` API](../../api/) page.

</Deeper>

## Workspace and projects

`config` edits the workspace config before vx reads it. Here, CI gets two workers:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function ciConcurrency(): VxPlugin {
  return definePlugin(import.meta, {
    config(workspace) {
      if (process.env.CI) workspace.run = { ...workspace.run, concurrency: 2 }
    },
  })
}
```

vx checks your edit as it checks a config you wrote. An edit a user could not write is refused.

<Takeaway>change workspace settings by where the run is, without touching `.vx/workspace.ts`.</Takeaway>

<Deeper level="patterns" title="Add projects, edges and tasks">

### Make a directory a project

`discover` makes a directory with no `vx.config.ts` a project. Its tasks come from a `project` hook:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function scriptsProject(): VxPlugin {
  return definePlugin(import.meta, {
    discover: () => [{ dir: 'scripts', name: 'scripts' }],
  })
}
```

### Say what a project depends on

vx reads no dependencies from a `package.json`. A `discover` entry names them:

- `deps` orders `^build` and is followed by `--filter app...` and `--affected`.
- `reach` is followed by `--filter` and `--affected` and orders nothing.

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function webEdges(): VxPlugin {
  return definePlugin(import.meta, {
    discover: () => [{ dir: 'apps/web', deps: ['packages/ui'], reach: ['packages/config'] }],
  })
}
```

With no plugin returning `deps`, a `^build` is refused.

### Run e2e after every build

`graph` sees every task the run holds. Add to `node.deps` to make one wait for another:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function e2eLast(): VxPlugin {
  return definePlugin(import.meta, {
    graph(nodes) {
      const builds = [...nodes.keys()].filter((id) => id.endsWith('#build'))
      for (const node of nodes.values()) {
        if (node.taskName !== 'e2e') continue
        for (const id of builds) if (!node.deps.includes(id)) node.deps.push(id)
      }
    },
  })
}
```

<Aside type="caution" title="Changed a discover or project hook?">
  Both run under `vx lock` only. A run reads what the lock recorded and calls neither, so run `vx
  lock` after you change one.
</Aside>

<Takeaway>add projects, the edges between them and tasks no config lists.</Takeaway>

</Deeper>

<Deeper level="details" title="Every field of these hooks">

**`config(workspace, ctx)`** gets the workspace config to edit in place. `plugins` is fixed by then: an edit to it is refused.

| `ctx` field | What it does |
| --- | --- |
| `workspaceRoot`, `warn` | as above |
| `setBranch(facts)` | tell vx what CI knows of the branch. A later plugin's field wins |

| `facts` field | What it sets |
| --- | --- |
| `scope` | the cache scope plugin entries are keyed by (`VX_CACHE_SCOPE` beats it; it beats git) |
| `base` | the commit a bare `--affected` compares with, such as a pull request's base |
| `trusted` | `true`: no scope, whatever git says (a merge queue) |
| `refs` | the refs a remote cache reads, in order. Unset: git's |

**`discover(ctx)`** returns one entry per directory:

| Entry field | What it does |
| --- | --- |
| `dir` | absolute, or relative to the workspace root. Outside the root is refused |
| `name` | the project's name when its config names none. A config's name wins. Unset: its path |
| `deps` | directories it builds after: `^task` order, `--filter` and `--affected` |
| `reach` | directories a change reaches it through: `--filter` and `--affected`, no order |

`deps` and `reach` from every plugin are joined. A target that is no project is refused, as are two projects with one name.

| `ctx` field | What it is |
| --- | --- |
| `projects` | the projects found so far, read-only: the lock's, then earlier plugins' |
| `cacheDir` | where a plugin may keep what it read |
| `worktreeChanges()` | what `git status` lists, relative to the root; `null` outside git |

**`project(config, ctx)`** gets each project's checked config to edit. A project only `discover` added arrives as `{ tasks: {} }`. Its `name` is fixed.

| `ctx` field | What it is |
| --- | --- |
| `name`, `dir` | the project's name and absolute directory |
| `projects` | every project, frozen. One array per run: memoise on it, since `vx watch` keeps your plugin across runs |
| `lock` | always `true`: the hook runs only under `vx lock`, the place to report what your mapping could not say |

**`graph(nodes, ctx)`** gets the task graph after `dependsOn` is expanded. Edit `node.deps` or `node.requested`. A dep on a task not in the graph, or a cycle, is refused with your plugin's name.

| `ctx` field | What it is |
| --- | --- |
| `requested` | the task ids the user asked for. Under `--affected`, every candidate |

</Deeper>

## Keys and order

`key` adds what your inputs cannot see to a task's cache key. This one keys every task on `.tool-versions`:

```ts title="plugins/tool-versions.ts"
import { readFileSync } from 'node:fs'
import path from 'node:path'
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function toolVersions(): VxPlugin {
  const file = '.tool-versions'
  return definePlugin(import.meta, {
    key: (_task, ctx) => ({ [file]: readFileSync(path.join(ctx.workspaceRoot, file), 'utf8') }),
    fingerprint: { files: [file], affected: () => undefined },
  })
}
```

<Deeper level="patterns" title="Hold back, rank and time tasks">

### One e2e suite at a time

`admit` holds a ready task back until something finishes. Here, two e2e suites never share the database:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function oneDatabase(): VxPlugin {
  return definePlugin(import.meta, {
    admit(task, ctx) {
      if (!task.id.endsWith('#e2e')) return true
      return !ctx.running.some((r) => r.id.endsWith('#e2e'))
    },
  })
}
```

### Start the slow tasks first

`schedule` returns a weight per task id. Among ready tasks, the higher weight starts first:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function e2eFirst(): VxPlugin {
  return definePlugin(import.meta, {
    schedule(nodes) {
      return new Map([...nodes.keys()].map((id) => [id, id.endsWith('#e2e') ? 1 : 0]))
    },
  })
}
```

### Learn the order from history

`@vzn/vx-history` ranks tasks by how long they took before:

```ts
import { defineWorkspace } from '@vzn/vx/config'
import { vxHistory } from '@vzn/vx-history'

export default defineWorkspace({ plugins: [vxHistory()] })
```

On CI it shares timings through a [history server](../servers/history/). Without one, `vxHistory({ file: '.vx-timings.json' })` keeps them in a file.

### Key on a tool's major version

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function nodeMajor(): VxPlugin {
  const major = process.versions.node.split('.')[0]!
  return definePlugin(import.meta, { key: () => ({ 'node-major': major }) })
}
```

[`@vzn/vx-lockfile`](../../docs/lockfiles/) keys each project on its own dependencies with `key` and `fingerprint`.

<Takeaway>keep two tasks apart, start the long ones first and key on a tool's version.</Takeaway>

</Deeper>

<Deeper level="details" title="Every field of these hooks">

**`key(task, ctx)`** returns `{ name: value }`, or `undefined` to add nothing. vx asks once per task per run, before any key. A value must be the same each time, or the task never hits. The task is read-only.

| `ctx` field | What it does |
| --- | --- |
| `locked(file)` | what `vx lock` recorded of a file in your `fingerprint`: `{ extras, digest(projectDir) }`. A run keys from it and never parses the file |

**`fingerprint`** is an object, not a function:

| Field | What it does |
| --- | --- |
| `files` | bare file names at the workspace root your plugin reads. One plugin per file |
| `affected(change, ctx)` | the project names a change touches. `change` has `file`, `before` and `after` bytes (`null` where absent) and `extras`. `undefined`: every project |
| `extraFiles(file, bytes, ctx)` | optional: files that file names and your key also reads, such as a patch. A change to one asks `affected` |
| `digests(file, ctx)` | optional: `{ hash, projects, extras? }`, each project's digest of the file. `vx lock` records them in `.vx/dependencies.lock` |

Its `ctx` has `projects`: every project's `name` and `dir`.

**`schedule(nodes, ctx)`** returns a map of task id to weight, or `undefined` to keep vx's order. vx asks once, after local hits are known, only when a task will start. A later plugin's weight wins.

| `ctx` field | What it does |
| --- | --- |
| `localCache` | the run's local cache: `localHistory(ctx.localCache)` reads its run history |
| `branch` | the run's branch, or `null` |
| `refs` | the refs the run reads, in order |
| `measures` | every plugin's `measures`, id to definition hash |
| `cache` | your plugin's own entries (see [Setup and teardown](#setup-and-teardown)) |
| `refine(weights)` | replace your weights mid-run, for data that arrives late. Takes a map or a promise of one |
| `refining()` | settles once every promised `refine` has landed or failed |
| `onRefine(listener)` | called each time another plugin refines |
| `flaky(taskIds)` | name tasks known as flaky: a failing one gets one retry |

**`admit(task, ctx)`** returns `true` to start the task now, `false` to hold it until something finishes.

vx asks often, so keep it cheap and synchronous. Hits, pooled tasks and groups are never asked. With several plugins, all must admit.

| `ctx` field | What it is |
| --- | --- |
| `running` | the tasks holding a worker here now, read-only |
| `concurrency` | the run's worker count |

**`measures(nodes)`** names work your plugin times that is no task: a map of `<plugin>#<name>` to a definition hash. vx asks before `schedule`, and only when some plugin has a `schedule` hook: with none, nothing reads them.

Report each one from `setup` with `ctx.measure({ id, def, durationMs, cores? })`. `def` is its definition hash. History keeps the last of each id.

</Deeper>

## Setup and teardown

`setup` runs once, before the first task. `ctx.on` subscribes to the run's events. `teardown` runs at the end, even after Ctrl-C:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

export function taskLog(): VxPlugin {
  const lines: string[] = []
  return definePlugin(import.meta, {
    setup(ctx) {
      ctx.on('onTaskComplete', (task, outcome) => {
        lines.push(`${task.id} ${outcome.status}`)
      })
    },
    teardown() {
      console.log(lines.join('\n'))
    },
  })
}
```

A throw in `setup` stops the run before any task starts. A throw in `teardown` leaves the run's result as it was. Release in `teardown` what `setup` holds: a function `setup` returns is refused, not called.

<Takeaway>do something before the first task, on every task and after the last one.</Takeaway>

<Deeper level="patterns" title="Tokens, your own entries and the run's report">

### Read a token from the keychain

`ctx.secret({ key, prompt })` reads a token from the OS keychain:

- Missing, with a terminal (not on CI): it asks, hides the input and saves the answer.
- Missing otherwise: it rejects, and `isSecretUnavailable(err)` is true.

Check your env var first. `ctx.forgetSecret({ key })` drops a token your server refused.

```ts
import { definePlugin, isSecretUnavailable, type VxPlugin } from '@vzn/vx'

export function acme(): VxPlugin {
  let token: string | undefined
  return definePlugin(import.meta, {
    async setup(ctx) {
      token =
        process.env.ACME_TOKEN ||
        (await ctx.secret({ key: 'acme', prompt: 'Acme token: ' }).catch((err: unknown) => {
          if (!isSecretUnavailable(err)) throw err
          ctx.warn(`acme: no token (${err.reason}); set ACME_TOKEN`)
          return undefined
        }))
    },
    teardown() {
      token = undefined
    },
  })
}
```

`err.reason` is `not-found` (no prompt given), `no-terminal` (CI, no TTY), `declined` (an empty answer) or `store-unavailable` (no keychain).

### Keep your own small entries

`ctx.cache` stores your plugin's entries in the local cache and every remote. An entry is written once and holds at most 1 MiB. A failure reads as an empty answer.

### Read the run's report

`teardown(run)` gets the run's report: every task with its status, key, and the log and outputs vx kept in the remote. `ctx.cache.getRun(name)` reads them back.

After Ctrl-C, `teardown` gets no report: the run did not end.

<Takeaway>ask for a token once, remember small facts across runs and read what a run left behind.</Takeaway>

</Deeper>

<Deeper level="details" title="Every field of setup and teardown">

**`setup(ctx)`**, after the key stage and before `schedule`, the executors, the sinks and the first task:

| `ctx` field | What it does |
| --- | --- |
| `workspaceRoot`, `cacheDir`, `warn` | as above |
| `ci` | `true` on CI (`CI` set, or a provider vx detects) |
| `branch` | the run's branch: `run.branch`, else git's, else the CI provider's |
| `on(event, handler)` | subscribe to a run event (below). A throw switches your handlers off with one warning |
| `measure(measure)` | report a measure your `measures` hook declared |
| `cache` | your plugin's entries (below) |
| `secret({ key, prompt? })` | a token from the keychain, else the terminal's answer, saved. Once per run per key |
| `forgetSecret({ key })` | delete the entry, so the next run asks again. Never throws |

| Event | Handler gets |
| --- | --- |
| `onRunStart` | the run's start info |
| `onTaskStart` | the task |
| `onTaskStdout`, `onTaskStderr` | the task and a chunk of its output |
| `onTaskComplete` | the task and its outcome |
| `onMeasure` | a measure any plugin reported |
| `onRunStatus` | a status line |
| `onRunEnd` | nothing |

What a handler gets is read-only, so it can never turn a failed task into a pass.

| `ctx.cache` method | What it does |
| --- | --- |
| `get(key, scoped?)` | the bytes from the first layer holding them, or `null`. `scoped: false` reads the base branch's |
| `put(key, bytes)` | store in every layer the policy writes. Empty bytes store nothing |
| `has(key, scoped?)` | whether some layer holds it; `null` when none could answer |
| `hasMany(keys, scoped?)` | the keys some layer holds, one probe per layer; `null` when a remote cannot batch |
| `getRun(name)` | a log or outputs tar the run's report names, from the first readable remote |

**`teardown(run?)`** runs in the order plugins are listed, `cache` plugins last. A finished run passes its report:

| Report field | What it is |
| --- | --- |
| `runId` | the id the run's history rows and telemetry carry |
| `commit` | `HEAD`'s commit, `null` outside git |
| `ciRun` | the CI provider, run URL, pipeline, job and attempt |
| `ok` | whether the run passed |
| `tasks` | each task: `id`, `status`, `durationMs`, `key?`, `log?`, `outputs?` |

vx keeps `log` and `outputs` only when a remote takes the run's writes (CI by default).

</Deeper>

## Draw the terminal

`output` returns a `Logger` that gets every line vx would print. Decline off a terminal, so pipes, CI and agents read what they always did:

```ts
import { definePlugin, type VxPlugin } from '@vzn/vx'

  })

```

## Where a task runs

`executor` returns a `TaskExecutor`: a `name`, an optional `accepts`, and `execute`, which runs one command.

<Diagram {...executorChoice} />

This one runs every `e2e` task under `nice`. Look at three lines: `accepts` picks the tasks, `detached` gives the shell its own process group, and `req.signal` stops it:

```ts
import { definePlugin, type ExecuteResult, type VxPlugin } from '@vzn/vx'

export function nice(): VxPlugin {
  return definePlugin(import.meta, {
    executor: () => ({
      name: 'nice',
      accepts: (task) => task.taskId.endsWith('#e2e'),
      async execute(req): Promise<ExecuteResult> {
        const started = performance.now()
        const child = Bun.spawn(['nice', 'sh', '-c', req.command, 'sh', ...req.forwardArgs], {
          cwd: req.cwd,
          env: { ...req.env, ...req.envDefine },
          stdout: 'pipe',
          stderr: 'pipe',
          detached: true, // its own process group, so a stop reaches what the shell starts
        })
        const stop = () => process.kill(-child.pid, 'SIGTERM')
        req.signal?.addEventListener('abort', stop, { once: true })
        const drain = async (from: ReadableStream<Uint8Array>, to: (s: string) => void) => {
          const text = new TextDecoder()
          let all = ''
          for await (const bytes of from) {
            const s = text.decode(bytes, { stream: true })
            to(s)
            all += s
          }
          return all
        }
        const [stdout, stderr] = await Promise.all([
          drain(child.stdout, req.onStdout),
          drain(child.stderr, req.onStderr),
        ])
        const exitCode = await child.exited
        return { exitCode, durationMs: performance.now() - started, stdout, stderr, violations: [] }
      },
    }),
  })
}
```

Stop on `req.signal` (Ctrl-C or `exec.timeout`), and stop the shell's children too: vx cannot reach them.

<Takeaway>run chosen tasks anywhere you can start a command.</Takeaway>

<Deeper level="patterns" title="Sandboxed tasks, giving a task back, many machines">

### Sandboxed tasks

A task with `exec.sandbox` is offered only to an executor whose `capabilities` say `sandbox: true` and that enforces `req.sandbox`. Otherwise vx runs it here, in its own sandbox.

### Give a task back

A `remote` executor rejects with `executorFallback(reason)`, from `@vzn/vx`, to hand a task back. vx runs it on this machine and prints `reason` once.

From an executor that is not `remote`, the task fails and the error says so.

### Many machines

For [Distributed task execution](../distributed-task-execution/), the executor also fills `distribution`: where each task runs, its footer rows, its machines. Each worker runs its tasks through `workerRuntime()`.

<Takeaway>keep sandboxed tasks safe, and hand back a task yours cannot run.</Takeaway>

</Deeper>

## Your own cache

Return a `RemoteCacheLayer` from the `cache` hook. vx asks the local cache first, then each remote in plugin order:

<Diagram {...cacheOrder} />

A layer needs the three `RemoteCacheLayer` methods, `has`, `get` and `put`:

| Method | Does |
| --- | --- |
| `has(hash)` | `null` when the remote lacks it, else what it knows: `{ size, durationMs }` or `{}` |
| `get(hash)` | `{ body, durationMs }`, `null` for a miss, or `undefined` when your layer is off and asked nothing: a miss that keeps what earlier runs found |
| `put(hash, body, meta)` | stores it; resolves `false` when it sent nothing (no token, writes off), so no upload is counted |
| `hasMany(hashes)` | optional: only when your server answers many keys in one call |
| `missing(hash)` | optional: called before a `put` with a key no remote had, so check nothing first |

An entry never changes: a `put` of a key the remote holds keeps the stored bytes. A remote error is a miss and one warning. vx bounds no call, so give every request a deadline:

```ts
import { definePlugin, defineWorkspace, type RemoteCacheLayer, type VxPlugin } from '@vzn/vx'

const deadline = () => AbortSignal.timeout(30_000) // core bounds no call

class AcmeRemote implements RemoteCacheLayer {
  constructor(readonly endpoint: string) {} // printed in warnings: no credentials in it
  async has(hash: string) {
    const res = await fetch(`${this.endpoint}/${hash}`, { method: 'HEAD', signal: deadline() })
    if (!res.ok) return null
    const size = Number(res.headers.get('content-length'))
    return Number.isFinite(size) ? { size } : {} // what restoring it downloads
  }
  async get(hash: string) {
    const res = await fetch(`${this.endpoint}/${hash}`, { signal: deadline() })
    if (res.status === 404) return null
    if (!res.ok) throw new Error(`HTTP ${res.status}`) // a throw is a miss
    return { body: res, durationMs: undefined } // streamed to disk
  }
  private readonly absent = new Set<string>()
  missing(hash: string) {
    this.absent.add(hash) // the run found it in no remote: no need to ask
  }
  async put(hash: string, body: Blob, meta: { durationMs: number; replace?: true }) {
    // An entry is immutable, and this server would overwrite: ask first,
    // unless the stored bytes did not read back.
    const ask = !meta.replace && !this.absent.has(hash)
    if (ask && (await this.has(hash)) !== null) return false // nothing sent
    const res = await fetch(`${this.endpoint}/${hash}`, { method: 'PUT', body, signal: deadline() })
    if (!res.ok) throw new Error(`HTTP ${res.status}`) // fetch resolves on a 500
  }
}

function acmeCache(): VxPlugin {
  return definePlugin(import.meta, {
    cache() {
      const url = process.env.ACME_CACHE_URL
      if (!url) return undefined // decline: the local cache alone
      return new AcmeRemote(`${url}/artifacts`)
    },
  })
}

export default defineWorkspace({ plugins: [acmeCache()] })
```

<Takeaway>keep your team's results in any store you can reach over the network.</Takeaway>

<Deeper level="patterns" title="Tokens and signed artifacts">

### A remote that needs a token

Add `open`. vx calls it once per run, before the first task; if it throws, the run goes on without that remote. `ctx.secret` works there.

An optional `lend` hands this run's own access, never a stored secret, to a machine that runs its tasks, such as a `@vzn/vx-dte` worker.

### Signed artifacts

A wrapper can make a shared cache trust its writers, not its store: it hashes each download and fails it unless a trusted key signed it.

A body failed with `CorruptArtifactError` is a miss whose rebuild is sent over the bad copy (`put` gets `replace`). Only main's CI holds the private key:

```ts
// signed-cache.ts
import { createHash, createPrivateKey, createPublicKey, sign, verify } from 'node:crypto'
import { CorruptArtifactError, definePlugin, type RemoteCacheLayer, type VxPlugin } from '@vzn/vx'

/** `remote`, but a download no trusted key signed is a miss, and uploads are signed. */
function signed(remote: RemoteCacheLayer, trustedPem: string, signingPem?: string): RemoteCacheLayer {
  const trusted = createPublicKey(trustedPem)
  const signer = signingPem ? createPrivateKey(signingPem) : undefined
  // The key is signed too, so a valid artifact cannot be replayed under another.
  const message = (hash: string, digest: string) => Buffer.from(`${hash}\0${digest}`)
  return {
    has: (hash) => remote.has(hash),
    async get(hash) {
      const [got, sig] = await Promise.all([remote.get(hash), remote.get(`${hash}.sig`)])
      // undefined: a remote that did not answer, which keeps the hits it lists
      if (got === undefined || sig === undefined) return undefined
      if (got === null || sig === null) return null
      const signature = Buffer.from(await sig.body.arrayBuffer())
      const sha = createHash('sha256')
      const source = got.body instanceof Blob ? got.body.stream() : got.body.body!
      const body = source.pipeThrough(
        new TransformStream<Uint8Array, Uint8Array>({
          transform(chunk, out) {
            sha.update(chunk)
            out.enqueue(chunk)
          },
          flush(out) {
            const ok = verify(null, message(hash, sha.digest('hex')), trusted, signature)
            // Bad bytes there, not a cut: the rebuild's save replaces them.
            if (!ok) out.error(new CorruptArtifactError(hash, 'no trusted signature'))
          },
        }),
      )
      return { body: new Response(body), durationMs: got.durationMs }
    },
    async put(hash, body, meta) {
      if (signer === undefined) return // every reader would refuse it
      const digest = createHash('sha256').update(await body.bytes()).digest('hex')
      await remote.put(hash, body, meta)
      await remote.put(`${hash}.sig`, new Blob([sign(null, message(hash, digest), signer)]), meta)
    },
  }
}

export function signedCache(remote: RemoteCacheLayer, trustedPem: string): VxPlugin {
  return definePlugin(import.meta, {
    cache: () => signed(remote, trustedPem, process.env.CACHE_SIGNING_KEY),
  })
}
```

Declare `signedCache(new AcmeRemote(url), PUBLIC_KEY_PEM)` and set `CACHE_SIGNING_KEY` only in main's CI. Make the key pair with:

```sh
openssl genpkey -algorithm ed25519 -out key.pem
openssl pkey -in key.pem -pubout
```

`has()` checks no signature, so `--dry` can predict a hit the run then misses.

<Takeaway>let only your trusted CI write results every machine will restore.</Takeaway>

</Deeper>

<Deeper level="details" title="Every field of a remote cache">

| Layer field | What it does |
| --- | --- |
| `endpoint` | optional: where the artifacts live, named in warnings. Credentials, query and fragment are dropped before printing |
| `off` | optional: `true` once a failure turned the layer off for the run, said once |
| `open(ctx)` | optional: get ready, once per run. `ctx` has `ci`, `warn`, `secret` and `forgetSecret`. `--dry` and `vx show` never call it |
| `lend()` | optional: `{ token, expiresAt? }`, this run's access for a machine running its tasks |

The `cache(ctx)` hook gets:

| `ctx` field | What it is |
| --- | --- |
| `workspaceRoot`, `cacheDir`, `warn` | as above |
| `scope` | the run's cache scope (`'acme/web:feat-x'`), or `undefined` |
| `refs` | the refs the run reads, in order: its branch, the branch it merges into, the default branch |
| `lent()` | the token a run lent your remote, on a machine running its tasks; `undefined` elsewhere. Read it per request |

`get`'s `body` is read once into the local cache: a `fetch` Response, `new Response(stream)` or `new Blob([bytes])`. A body that errors before its end stores nothing.

</Deeper>

## What core refuses

<Compare leftTitle="Your plugin can" rightTitle="Your plugin cannot">
<div slot="left">

- add, change and remove tasks before the key is taken
- run a task elsewhere, store results elsewhere
- watch every event of the run

</div>
<div slot="right">

- turn a failed task into a pass
- change a command after its key is taken
- pick its own name

</div>
</Compare>

vx refuses, naming your plugin:

- A `cache` or `executor` hook that breaks its contract: the three `RemoteCacheLayer` methods, or `execute` and a `name`.
- A `name` on the hooks object: the name is the package's.
- A `config` or `project` edit vx would refuse from a user.
- A verb that names a core verb, or that two packages both declare.

What a plugin observes is read-only. A write to it throws.

That covers what a `ctx.on` handler, a bus subscriber or a `Logger` gets, telemetry records and the run report.

It covers `ctx.projects` in `discover` and `project`, the task `key` and `admit` get, the nodes `schedule` gets, and an executor's `outputs`, `envDefine` and `forwardArgs`.

It covers a task's config once the `graph` stage ends. A project config a `project` hook kept is no longer the run's once that project's hooks have run.

<Deeper level="details" title="What a throw costs">

| Throws | What vx does |
| --- | --- |
| `telemetry` hook or sink, `ctx.on` handler, `admit`, `output` hook or `Logger` | switches it off for the run, with one warning |
| `measures` | leaves its measures out, with one warning. Asked only when a plugin has `schedule` |
| `teardown` | leaves the run's result as it was |
| a verb | fails in one line |
| a remote cache call | a miss |
| `execute` | fails its task |

</Deeper>

A throw in any other hook stops the run, or `vx lock`, with one line naming your plugin and the hook.

`setup` and `teardown` return nothing. A value they return, such as a function to call later, counts as a throw: vx never calls it.

<Quiz q="Your telemetry sink throws on every record. Does the build fail?">
  No. vx switches that sink off for the run and prints one warning. Observing never breaks a run.
</Quiz>

<Takeaway>know what vx protects, so a bug in your plugin never hides a failed task.</Takeaway>
