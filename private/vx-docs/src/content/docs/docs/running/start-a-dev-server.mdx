---
title: Start a dev server before your tests
description: Mark a server task persistent with readyWhen, and the tasks that depend on it start once it is ready.
---

import { Tabs, TabItem } from '@astrojs/starlight/components'
import Timeline from '../../../../components/running/Timeline.astro'

Mark the server `persistent` and name the line it prints when ready. Tests
that depend on it wait for that line.

```ts title="packages/web/vx.config.ts" mark={4}
tasks: {
  dev: {
    exec: { command: 'vite', persistent: { readyWhen: 'Local:' }, timeout: '30s' },
  },
  e2e: {
    dependsOn: ['dev'],
    exec: { command: 'playwright test' },
  },
},
```

Then one command does it all: start `vite`, wait, test, stop the server.

```sh
vx run e2e
```

## The race this wins

A server needs a moment before it answers. Here it takes 300 ms, and the
check is a `curl`. Pick a tab.

## Every setting

| Key | Meaning | Default |
| --- | --- | --- |
| `exec.persistent` | the task keeps running: a server or a watcher | not persistent |
| `persistent.readyWhen` | a regex tested on each output line; the first match means ready | ready at spawn |
| `exec.timeout` | how long to wait for that line before the task fails | no limit |

:::tip[You can run any dev server]
Three keys cover every dev server: keep it running, know when it is up, give up if it never is.
:::

<details>
<summary>Dig deeper: how the server stops</summary>

When every other task is done, vx sends the server `SIGTERM`, then
`SIGKILL` if it is still alive after `run.killGrace` (default `'2s'`).
The server's frame shows what it printed after it was ready.

</details>

<details>
<summary>Dig deeper: what a persistent task cannot do</summary>

It is never cached: there is no exit to save. So `cache` and `exec.retries`
are refused on it. It always runs on your machine, and so do the tasks that
depend on it.

</details>

<details>
<summary>Dig deeper: a task that reads your keyboard</summary>

A watch mode with key presses, or a prompt, needs the terminal itself. Set
`exec.interactive: true`. On a terminal it gets vx's input and output as is.

No other task starts while it runs. It is never cached, and cannot take
`cache`, `exec.sandbox` or `readyWhen`.

</details>
