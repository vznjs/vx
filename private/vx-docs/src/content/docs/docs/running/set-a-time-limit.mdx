---
title: Set a time limit on a task
description: Use exec.timeout or --timeout so a stuck task fails instead of hanging the run.
---

Give a task `exec.timeout`, and vx stops it once that time is up.

```ts title="packages/web/vx.config.ts" del={3} ins={4}
tasks: {
  e2e: {
    exec: { command: 'playwright test' },
    exec: { command: 'playwright test', timeout: '10m' },
  },
},
```

## A test suite that never ends

One test waits for a page that never loads. Pick a tab.

A limit turns "CI hung for six hours" into a red task with a clear reason.
:::

## What a timeout looks like

To try it, pass `--timeout` to one run. Here the task sleeps five seconds:

```sh
vx run @demo/web#e2e --timeout 1s
```

```ansi
[2m┌─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;147;197;253me2e[0m [2m>[0m $ sleep 5
[vx] timed out after 1000ms — killed (SIGTERM)
[2m└─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;147;197;253me2e[0m [2m──[0m [2m(1.01s)[0m [1m[38;2;239;68;68mfailed (timed out, exit 143)[0m
```

Look at the last word: `failed (timed out)`. vx exits `1`, and a task that
timed out is never cached.

## Three places to set it

| Where | Setting | Applies to |
| --- | --- | --- |
| a task in `vx.config.ts` | `exec: { timeout: '10m' }` | that task |
| command line | `--timeout 10m` | every task in this run |
| `.vx/workspace.ts` | `run: { timeout: '30m' }` | every task in every run |

The most specific wins: a task's own `exec.timeout` beats `--timeout`, and
`--timeout` beats `run.timeout`.

```ts title=".vx/workspace.ts" mark={4}
import type { WorkspaceConfig } from '@vzn/vx/config'

export default {
  run: { timeout: '30m' },
} satisfies WorkspaceConfig
```

A duration always has its unit: `'500ms'`, `'30s'`, `'10m'`, `'1h'`, `'1d'`.

:::tip[You can set a ceiling]
One workspace line puts a ceiling on every task. Slow tasks raise their own.
:::

<details>
<summary>Dig deeper: how vx stops it</summary>

vx sends `SIGTERM` to the task's whole process tree. Anything still
alive after `run.killGrace` (default `'2s'`) gets `SIGKILL`. Raise
`killGrace` for a tool that needs time to clean up.

</details>

<details>
<summary>Dig deeper: on a dev server</summary>

On a [`persistent`](../start-a-dev-server/) task, `exec.timeout` limits the
wait for its ready line, not its whole life.

</details>

<details>
<summary>Dig deeper: with retries</summary>

A timeout counts as a failure, so `exec.retries` tries again. See [Stop at the first failure](../stop-at-the-first-failure/).

</details>
