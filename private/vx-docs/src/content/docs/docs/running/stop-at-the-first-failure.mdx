Add `--fail-fast` to end the run the moment one task fails.

```sh
vx run test --all --fail-fast
```

## Two ways to fail

`ui`'s test fails fast. `web`'s test takes a second. Pick a tab and watch.

Both ways exit `1`, and neither caches a failed or aborted task.

:::tip[You choose how to fail]
Default: see every failure in one run. `--fail-fast`: get the first one back sooner.
:::

## What a failure always skips

Without `--fail-fast`, a failed task still skips the tasks that **need** it.
If `ui#build` fails, `web#build` never starts; its row says
`blocked by @demo/ui#build`. Every unrelated task still runs.

## Make it the default

| Where | Setting | Scope |
| --- | --- | --- |
| command line | `--fail-fast` | this run |
| `.vx/workspace.ts` | `run: { failFast: true }` | every run |
| a pipeline in `.vx/workspace.ts` | `failFast: true` | that pipeline |

```ts title=".vx/workspace.ts" mark={5}
import type { WorkspaceConfig } from '@vzn/vx/config'

export default {
  pipelines: {
    pr: { tasks: ['build', 'test'], affected: true, failFast: true },
  },
} satisfies WorkspaceConfig
```

:::tip[You can set it per pipeline]
Your pull request pipeline can stop at the first red task, while local runs show them all.
:::

<details>
<summary>Dig deeper: how vx stops a task</summary>

vx sends `SIGTERM` to the task's whole process tree. A process still
alive after `run.killGrace` (default `'2s'`) gets `SIGKILL`. An aborted
task saves nothing to the cache.

</details>

<details>
<summary>Dig deeper: try again before failing</summary>

A flaky task can get extra attempts: `exec.retries: 2` means up to three
runs. `run.retries` sets it for every task. Only the last attempt counts,
so `--fail-fast` waits until a task is out of attempts.

</details>
