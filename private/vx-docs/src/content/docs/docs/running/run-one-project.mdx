Add `--filter` to run a task in only the projects you name.

```sh
vx run build --filter @demo/web
```

## Pick a filter, see what it picks

The same workspace as before: `web` and `docs` both use `ui`. Bright boxes run.

Six shapes cover every pick: a name, a pattern, a folder, `name...`, `...name`, and `!name`.

## A filter still runs what the task needs

Filter on `web`, and its `^build` still builds `ui` first. `--dry` shows it:

```sh

```

## From inside a project

`cd packages/web && vx run build` does the same as `--filter @demo/web`.
With no filter, vx runs the project you are standing in.

## Every filter form

| Filter | Picks |
| --- | --- |
| `@demo/web` | the project with that name |
| `@demo/*` | every project whose name matches |
| `./packages/web` | the project in that folder |
| `@demo/web...` | that project and everything it uses |
| `...@demo/ui` | that project and everything that uses it |
| `!@demo/docs` | not that project |

Repeat `--filter` to combine them: `--filter @demo/web --filter @demo/docs`.

<details>
<summary>Dig deeper: a filter that matches nothing</summary>

Every filter must match a project. If one matches nothing, vx stops before
running anything and names the closest match:

```sh
vx run build --filter @demo/wbe
```

```ansi
[38;2;239;68;68m✗[0m [1mvx run[0m  [38;2;203;213;225mno projects matched filter(s): "@demo/wbe"[0m

  [2mfix[0m  [1m@demo/web[0m
```

A typo never turns into a green run that did no work.

</details>

<details>
<summary>Dig deeper: skip the dependencies</summary>

To run only the picked tasks, without what they depend on, add
`--exclude-dependencies`. Use it when you know the dependencies are
already built. See [`vx run`](../../../cli/run/).

</details>
