Add `'^build'` to a task's `dependsOn`, and vx builds the packages it uses first.

```ts title="packages/web/vx.config.ts" ins={3}
tasks: {
  build: {
    dependsOn: ['^build'],
    exec: { command: 'vite build' },
  },
},
```

## See the order before you run

```sh
vx run build --dry
```

## Every form of `dependsOn`

| Entry | Runs first | Example |
| --- | --- | --- |
| `'^build'` | `build` in each package this one uses | a library before the app |
| `'codegen'` | `codegen` in this same project | generated types before `vite build` |
| `'@demo/api#build'` | `build` in that one project | a named project |
| `'build.*'` | every task here whose name matches | `build.css`, `build.js` |
| `'^build.*'` | the same match, in each package this one uses | split builds in a library |

A task waits for **every** entry. A cycle, or a `'pkg#task'` that does not
exist, stops `vx lock` with an error. Bare `*` and `!task` are not allowed.

<details>
<summary>Dig deeper: where `^` gets its list</summary>

`^` reads your packages' `dependencies` from `package.json`, through the
lockfile plugin `vx init` adds to `.vx/workspace.ts`, such as `bun()`:

```json title="packages/web/package.json"
{ "name": "@demo/web", "dependencies": { "@demo/ui": "workspace:*" } }
```

Without a lockfile plugin, `vx lock` refuses `^build` and says so.

A package that declares no `build` gets one anyway: a group (a task with
no command) behind `^build`, keyed on all its files. Edit a package used as
plain source, and the packages that use it rebuild.

</details>

<details>
<summary>Dig deeper: order is not inputs</summary>

`dependsOn` says **when** a task runs. `inputs` says **what** decides its
cache key. A task's key also includes the keys of the tasks it depends on,
so an edit in `ui` makes `web` build again. See [Cache a task](../../caching/cache-a-task/).

</details>
