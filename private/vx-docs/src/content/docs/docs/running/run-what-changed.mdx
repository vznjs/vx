Add `--affected` to run a task only in projects your branch changed, plus
every project that uses them.

```sh
vx run build --affected
```

Read the last column: each row says which file pulled it in, and `via` which task.

:::tip[You run only the change]
`--affected` picks **projects** from git. The cache then skips any task whose inputs did not change.
:::

## Compare with another commit

On a branch, vx compares with the commit where it left your base branch
(`main`). To pick the base yourself, name it:

```sh
vx run test --affected=origin/main
vx run test --affected=HEAD~1
```

| Form | Compares with |
| --- | --- |
| `--affected` | where your branch left `main` |
| `--affected=<ref>` | that branch, tag or commit |

:::tip[You can scope a pull request]
One flag on every pull request runs only the slice that branch touched.
:::

<details>
<summary>Dig deeper: on `main` itself</summary>

On the base branch, a bare `--affected` has no default and vx says so. Run
`--all` there: the cache still runs only what changed.

</details>

<details>
<summary>Dig deeper: shallow CI checkouts</summary>

CI's default one-commit checkout is enough. vx fetches the history back to
where the branch started, without file contents.

</details>

<details>
<summary>Dig deeper: in a pipeline</summary>

A [pipeline](../../ci/run-a-pipeline/) takes the same switch as
`affected: true`, or a ref such as `affected: 'origin/main'`.

</details>
