title: Pass an environment variable to a task
description: List a variable in exec.env.passThrough so the task's command can read it.

import { Tabs, TabItem } from '@astrojs/starlight/components'

A task sees only the variables you list. To pass one, add its name to
`exec.env.passThrough`.

```ts title="packages/web/vx.config.ts" ins={5}
tasks: {
  deploy: {
    exec: {
      command: 'echo "deploying to $DEPLOY_ENV"',
      env: { passThrough: ['DEPLOY_ENV'] },
    },
  },
},
```

## Your shell has it. Does the task?

Run the same command both ways. Pick a tab.

```sh

```

:::tip[You control the environment]
A task gets **only** what you list, so a stray variable on your laptop never changes a build.
:::

## When the variable changes the output

`vite build` writes `NODE_ENV` into the bundle. If you only pass it, the
cache cannot tell `production` from `development`. Watch:

<Tabs>
<TabItem label="passThrough only">

```ts ins={2}
bundle: {
  exec: { command: 'vite build', env: { passThrough: ['NODE_ENV'] } },
  inputs: { files: ['src/**'] },
  outputs: { files: ['dist/**'] },
  cache: true,
},
```

`vx lock` warns you right away:

```ansi
[38;2;234;179;8m![0m [1mvx lock[0m  [38;2;203;213;225m@demo/web#bundle: exec.env.passThrough forwards NODE_ENV, which a bundler writes into its output, and the key does not see it — add it to inputs.env[0m
```

Build with `production`, then `development`. A one-line script stands in
for `vite` and prints the mode. The second run keeps `production`:

```ansi
[2m┌─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;129;140;248mbundle[0m [2m>[0m $ mkdir -p out && echo "mode=$NODE_ENV" > out/mode.txt && cat out/mode.txt
mode=production
[2m└─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;129;140;248mbundle[0m [2m──[0m [2m(2ms)[0m [2mup-to-date[0m
```

</TabItem>
<TabItem label="Also in inputs.env">

```ts ins={3}
bundle: {
  exec: { command: 'vite build', env: { passThrough: ['NODE_ENV'] } },
  inputs: { files: ['src/**'], env: ['NODE_ENV'] },
  outputs: { files: ['dist/**'] },
  cache: true,
},
```

A new value is a new cache entry, so `development` builds fresh:

```ansi
[2m┌─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;129;140;248mbundle[0m [2m>[0m $ mkdir -p out && echo "mode=$NODE_ENV" > out/mode.txt && cat out/mode.txt
mode=development
[2m└─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;129;140;248mbundle[0m [2m──[0m [2m(7ms)[0m [2msuccess[0m
```

Switch back to `production` and vx restores that bundle from the cache:

```ansi
[2m┌─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;129;140;248mbundle[0m [2m>[0m $ mkdir -p out && echo "mode=$NODE_ENV" > out/mode.txt && cat out/mode.txt
mode=production
[2m└─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;129;140;248mbundle[0m [2m──[0m [2m(10ms)[0m [2mrestored-local[0m
```

</TabItem>
</Tabs>

:::tip[You can keep the cache honest]
Pass it to **use** it. Add it to `inputs.env` when it **changes what the task writes**.
:::

## Every env setting

| Key | Sets | In the cache key? | Use for |
| --- | --- | --- | --- |
| `exec.env.passThrough` | the variable from your shell | no | tokens, CI flags, `NODE_ENV` |
| `exec.env.define` | a fixed `name: value` | yes | `{ REGION: 'eu' }` |
| `exec.env.secret` | nothing; masks those names as `***` | no | a secret with an unusual name |
| `inputs.env` | nothing; keys the task on the value | yes | any variable that changes the output |

```ts title="packages/web/vx.config.ts"
exec: {
  command: 'echo "deploying to $DEPLOY_ENV ($REGION)"',
  env: {
    passThrough: ['DEPLOY_ENV', 'DEPLOY_KEY'],
    define: { REGION: 'eu' },
    secret: ['DEPLOY_AUTH'],
  },
},
```

<details>
<summary>Dig deeper: secrets stay hidden</summary>

A name holding `TOKEN`, `SECRET`, `KEY`, `PASSWORD`, `PASSWD`,
`PASSPHRASE` or `CREDENTIAL`, or ending `_PASS`, is masked on its own:

```ansi
[2m┌─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;244;114;182mdeploy[0m [2m>[0m $ echo "deploying to $DEPLOY_ENV with $DEPLOY_KEY"
deploying to staging with ***
[2m└─[0m [1m[38;2;244;114;182m@demo/web[0m[2m#[0m[1m[38;2;244;114;182mdeploy[0m [2m──[0m [2m(17ms)[0m [2msuccess[0m
```

List any other name in `exec.env.secret`. vx masks values of 6 characters
or more; `run.secrets.minLength` in `.vx/workspace.ts` changes that. Keep
secrets in `passThrough` only, never `inputs.env` or `define`.

</details>
