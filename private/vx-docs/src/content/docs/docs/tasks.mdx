`@demo/web` has the quickstart's `build`; `@demo/ui` has no tasks yet. By
the end of this page they lint, build in order, and skip work already done.

```ts title="packages/ui/vx.config.ts"
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    lint: {
      exec: { command: 'oxlint src' },
    },
  },
})
```

<Levels />

<Concept term="Task">
  One command in one project, with a name. vx decides when it runs, and
  whether it needs to run at all.
</Concept>

## 1. Run a command

The task's name is `lint`; `exec.command` is what runs, from the project's
folder. Install `oxlint` at the root, run `vx lock`, then run `lint` in every
project that has it:

```sh
bun add -d oxlint
vx lock
```

```ansi
[2m$[0m vx run lint --all

[4m  [0m[1;4;38;2;167;139;250mTasks[0m[4m     [0m[4;38;2;148;163;184mstatus  cache       time   task[0m[4m[0m
```

<Takeaway>run any command through vx: a linter, a test runner, a script.</Takeaway>

<Deeper level="patterns" title="Many steps, and a label">

`exec.command` is one shell line. Join steps with `&&`:
`'vite build && cp README.md dist/'`. One command per task keeps each
step cacheable on its own, so two steps that cache apart are two tasks.

`description` is a one-line label for `vx run`'s picker and `--dry`:
`description: 'bundle the app into dist/'`.

</Deeper>

## 2. Put tasks in order

`web` imports `ui`, so `ui` must build first. `dependsOn` says so:

```ts title="packages/web/vx.config.ts" mark={6}
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    build: {
      dependsOn: ['^build'],
      exec: { command: 'vite build' },
    },
  },
})
```

The `^` means "`build` in **every project I import**". vx reads who
imports whom from your lockfile, through a [lockfile plugin](../lockfiles/).

`@demo/ui` needs a `build` to wait for. Add one beside its `lint`, then run `vx lock`:

```ts title="packages/ui/vx.config.ts" ins={8-10}
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    lint: {
      exec: { command: 'oxlint src' },
    },
    build: {
      exec: { command: 'vite build' },
    },
  },
})
```

```ansi
[2m$[0m vx run build --all
```

`@demo/ui#build` ran first and held back `@demo/web#build` until it was
done. Tasks with nothing between them run at the same time.

Try each kind of entry on `web#build` here:

<DependsOn />

| Entry | Waits for |
| --- | --- |
| `'lint'` | `lint` in this project |
| `'^build'` | `build` in every project this one imports |
| `'api#build'` | `build` in the `api` project |
| `'gen-*'` | every task in this project whose name matches |
| `'^gen-*'` | matching tasks in every project this one imports |

<Quiz q="web imports ui. Which entry on web#test runs ui#build first?">
  `'^build'`. Plain `'build'` would wait for `web#build` instead.
</Quiz>

<Aside type="caution" title="Refused before anything runs">
  A task-name pattern is allowed: `dependsOn: ['build.*']`, or `'^build.*'`.
  Bare wildcards and negation (`*`, `!task`) are refused, as are cycles and
  a missing `'api#build'`.
</Aside>

<Takeaway>build a library before the app that imports it, every time.</Takeaway>

## 3. Skip work already done

Add three fields and vx skips a build whose files did not change:

```ts title="packages/ui/vx.config.ts" ins={3-5}
build: {
  exec: { command: 'vite build' },
  inputs: { files: ['src/**', 'vite.config.ts'] },
  outputs: { files: ['dist/index.js'] },
  cache: true,
},
```

| Field | Says |
| --- | --- |
| `inputs.files` | the files that change the result |
| `outputs.files` | the files the command makes |
| `cache` | `true` to save and reuse them |

vx hashes the inputs into a **key**. A key it has seen restores the
outputs instead of running:

run finds both keys:

### Outputs that must exist

Declared outputs are a promise. When the command ends:

- a plain path, like `dist/index.js`, **must exist**;
- a path with a trailing slash, like `dist/`, must be a folder;
- a wildcard, like `coverage/**`, may match nothing;
- but **at least one** declared output must exist.

<OutputRule />

If `vite build` writes `dist/index.js` but you declared `dist/ui.js`, the
task fails and nothing is saved:

<Deeper level="details" title="Everything a key can read">

| Field | What it adds to the key |
| --- | --- |
| `inputs.files` <Badge text="required" /> | project files, as globs; `!` excludes; `[]` for none |
| `inputs.workspaceFiles` | files outside the project, from the workspace root (a root `tsconfig.json`) |
| `inputs.env` | the values of these variables (does not pass them to the command) |
| `inputs.tasks` | which upstream tasks' keys count; default all (`['*', '^*']`), `[]` for none, `'!name'` drops one |
| `inputs.runtime` | the output of commands run in the project at hash time (`'node -v'`) |
| `inputs.workspaceRuntime` | the same, run once at the root for the whole run |
| `inputs.stability.strategy` | what a write to an input mid-run means: `'immutable'` (default) never saves, `'mutable'` allows a rewrite to the same bytes, `'unchecked'` skips the check |
| `inputs.stability.severity` | `'warn'` (default) keeps the run green, `'error'` fails the task |

An upstream task's key counts, never its files. That is why `inputs.files`
leaves out a file another task generates: list that task in `dependsOn`
instead.

| Field | Does |
| --- | --- |
| `outputs.files` <Badge text="required" /> | project files the task makes; plain paths must exist, and at least one entry must match; `[]` when it makes none |
| `outputs.workspaceFiles` | files it makes outside the project, from the workspace root |
| `outputs.clean` | `false` keeps old outputs for the command (an incremental build); default `true` removes them first |

`exec.remote` and `exec.worker` are the two `exec` fields left out of the
key: where a task runs says nothing about what it makes.

Every other field is in the key, so editing even `description` re-runs
the task once. More in [Caching](../caching/).

A task can read and write outside its project, named from the workspace
root. Here a test reads the shared config and writes coverage at the root:

```ts title="packages/web/vx.config.ts" mark={9,11}
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    test: {
      exec: { command: 'vitest run --coverage --coverage.reportsDirectory=../../coverage/web' },
      inputs: {
        files: ['src/**', 'vitest.config.ts'],
        workspaceFiles: ['tsconfig.base.json'],
      },
      outputs: { files: [], workspaceFiles: ['coverage/web/**'] },
      cache: true,
    },
  },
})
```

## 4. Give the command its variables

A task sees **no** variable from your shell unless you pass it:

```ts title="packages/web/vx.config.ts" mark={4-8}
build: {
  exec: {
    command: 'vite build',
    env: {
      define: { NODE_ENV: 'production' },
      passThrough: ['CI', 'VITE_API_URL', 'SENTRY_AUTH_TOKEN'],
      secret: ['SENTRY_AUTH_TOKEN'],
    },
  },
  inputs: { files: ['src/**', 'index.html', 'vite.config.*'], env: ['VITE_API_URL'] },
},
```

| Field | The command sees | In the key |
| --- | --- | --- |
| `exec.env.define` | this exact value | yes |
| `exec.env.passThrough` | your shell's value | no |
| `exec.env.secret` | nothing new; a name it also gets is shown as `***` | no |
| `inputs.env` | nothing (so `VITE_API_URL` is in `passThrough` too) | yes |

<Aside type="note">
  Names with `TOKEN`, `SECRET`, `KEY` or `PASSWORD` are masked anyway.
  Full rules in [Environment variables](../environment-variables/).
</Aside>

<Takeaway>hand a build its API URL and a secret, and know which change re-runs it.</Takeaway>

## 6. Servers, prompts and other machines

Some commands never exit, read the keyboard, or need a certain machine.
Each has one field:

```ts title="packages/web/vx.config.ts"
dev: {
  dependsOn: ['^build'],
  exec: { command: 'vite', persistent: { readyWhen: 'Local:' } },
},
```

vx starts `vite`, waits for the line holding `Local:`, then starts what
waits on `dev`. It stops the server when the rest of the run ends.

| Field | For | More |
| --- | --- | --- |
| `exec.persistent` | a server or watcher; `readyWhen` is a regex for the ready line | [Dev servers](../dev-servers/) |
| `exec.interactive` | a prompt, a REPL, a TUI; runs alone, never cached | |
| `exec.platforms` | only these machines: `linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`; skipped elsewhere | |
| `exec.sandbox` | only the files and network you allow | [Sandboxing](../sandboxing/) |
| `exec.remote` | `false` keeps it on this machine; `'only'` never runs it here | [Remote execution](../remote-execution/) |
| `exec.worker` | the worker type to run on, such as `'ubuntu'` | [Distributed task execution](../distributed-task-execution/) |

<Takeaway>start a dev server after its libraries build, and keep a macOS-only task off Linux.</Takeaway>

## 7. Name a set of tasks

<Concept term="Group">
  A task with no `exec`. It runs nothing itself, only what it depends on.
</Concept>

In a project with `lint`, `build` and `test` tasks:

```ts title="packages/web/vx.config.ts"
ci: { dependsOn: ['lint', 'build', 'test'] },
```

`vx run ci` runs all three, each after what it needs:

<Diagram {...taskGraph} />

A group with `inputs` gets a key too, so tasks that depend on it re-run
when those files change.

<Aside type="note" title="A project with no build">
  A project with no `build` task gets one: a group keyed on all its files.
  So `^build` still re-runs `web` when `ui`'s source changes.
</Aside>

<Takeaway>run your whole check with one name.</Takeaway>

<Deeper level="details" title="Every task field">

Click any field to read what it does:

<ConfigExplorer area="task" />

| Field | Does |
| --- | --- |
| `description`<br/><small>string</small> | label in the picker and `--dry`. Default: none |
| `dependsOn`<br/><small>string[]</small> | tasks that finish first ([section 2](#2-put-tasks-in-order)). Default: `[]` |
| `exec`<br/><small>object</small> | what runs; no `exec` makes a group. Default: none |
| `exec.env`<br/><small>object</small> | the variables the command sees ([section 4](#4-give-the-command-its-variables)). Default: none |
| `exec.command`<br/><small>string</small> | the shell command, run in the project folder. Default: required |
| `exec.env.define`<br/><small>record</small> | set values, in the key. Default: none |
| `exec.env.passThrough`<br/><small>string[]</small> | variables passed from your shell. Default: none |
| `exec.env.secret`<br/><small>string[]</small> | masks these values in output; pass them too. Default: none |
| `exec.timeout`<br/><small>`'30s'`, `'10m'`…</small> | stop after this long. Default: no limit |
| `exec.retries`<br/><small>number</small> | extra attempts after a failure. Default: `0` |
| `exec.persistent`<br/><small>object</small> | a server or watcher: `{}`, or `{ readyWhen }`. Default: not persistent |
| `exec.persistent.readyWhen`<br/><small>regex string</small> | the line that means ready. Default: ready at start |
| `exec.interactive`<br/><small>boolean</small> | reads the terminal; runs alone. Default: `false` |
| `exec.platforms`<br/><small>string[]</small> | machines it runs on. Default: anywhere |
| `exec.sandbox`<br/><small>object</small> | confine reads, writes, network ([Sandboxing](../sandboxing/)). Default: none |
| `exec.remote`<br/><small>`true`, `false`, `'only'`</small> | may run on a remote machine. Default: `true` |
| `exec.worker`<br/><small>string</small> | worker type for distributed task execution. Default: first that fits |
| `inputs.files`<br/><small>string[]</small> | project files in the key; `[]` for none. Required once `inputs` is set |
| `inputs.workspaceFiles`<br/><small>string[]</small> | root-relative files in the key. Default: none |
| `inputs.env`<br/><small>string[]</small> | variable values in the key. Default: none |
| `inputs.tasks`<br/><small>string[]</small> | upstream keys in the key. Default: `['*', '^*']` |
| `inputs.runtime`<br/><small>string[]</small> | command output in the key. Default: none |
| `inputs.workspaceRuntime`<br/><small>string[]</small> | root command output in the key, once per run. Default: none |
| `inputs.stability.strategy`<br/><small>`'immutable'`, `'mutable'`, `'unchecked'`</small> | input written mid-run. Default: `'immutable'` |
| `inputs.stability.severity`<br/><small>`'warn'`, `'error'`</small> | what that write does to the run. Default: `'warn'` |
| `outputs.files`<br/><small>string[]</small> | files saved and restored; `[]` for none. Required once `outputs` is set |
| `outputs.workspaceFiles`<br/><small>string[]</small> | root-relative outputs. Default: none |
| `outputs.clean`<br/><small>boolean</small> | remove old outputs before a miss runs. Default: `true` |
| `cache`<br/><small>boolean</small> | save and reuse; needs `exec`, `inputs` and `outputs`, which a task without `cache` may leave out. Default: `false` |

One task with every field set, to copy from:

```ts title="packages/web/vx.config.ts"
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    lint: { exec: { command: 'oxlint src' } },
    e2e: {
      description: 'browser tests against the preview build',
      dependsOn: ['lint', '^build'],
      exec: {
        command: 'playwright test',
        env: { define: { CI: '1' }, passThrough: ['HOME'], secret: ['SENTRY_AUTH_TOKEN'] },
        timeout: '10m',
        retries: 1,
        platforms: ['linux-x64', 'darwin-arm64'],
        remote: false,
        worker: 'ubuntu',
        sandbox: {
          allow: { read: ['.'], write: ['test-results'], network: ['localhost:4173'] },
          deny: { network: ['*.analytics.example.com'] },
          ignore: { read: ['/etc/ssl/**'] },
        },
      },
      inputs: {
        files: ['src/**', 'e2e/**'],
        workspaceFiles: ['tsconfig.base.json'],
        env: ['BASE_URL'],
        tasks: ['*', '^*'],
        runtime: ['playwright --version'],
        workspaceRuntime: ['node -v'],
        stability: { strategy: 'immutable', severity: 'warn' },
      },
      outputs: { files: ['test-results/**'], workspaceFiles: ['reports/web-e2e/**'], clean: true },
      cache: true,
    },
  },
})
```

`exec.persistent` and `exec.interactive` are left out: a cached task can
use neither.

`exec.sandbox` has its own fields (`allow`, `deny`, `ignore`, `hermetic`,
`weakerWhenNested`, `weakerNetworkIsolation`): see [Sandboxing](../sandboxing/).

Beside `tasks`, a project's `vx.config.ts` takes two fields:

| Field | Does |
| --- | --- |
| `name`<br/><small>string</small> | the name filters and `dependsOn` use. Default: the `package.json` name, else the folder path |
| `tags`<br/><small>string[]</small> | labels for `--filter tag:<name>`; in no key. Default: none |

Workspace-wide defaults for `timeout`, `retries` and `outputs.clean`
live in [Workspace](../workspace/).

<Deeper level="details" title="When it goes wrong">

`vx lock` checks every config before it writes the lock. A mistake stops it and points at the line:

```ansi title="vx lock"
[38;2;239;68;68m✗[0m [1mvx lock[0m  [38;2;203;213;225mlock not written[0m

  [1mpackages/web/vx.config.ts:7:7[0m
  [38;2;203;213;225mtasks.build.outputs must be an object (fields: clean, files, workspaceFiles), not an array[0m

    5 |       exec: { command: 'vite build' },
    6 |       inputs: { files: ['src/**', 'vite.config.ts'] },
  > 7 |       outputs: ['dist/**'],
      |       ^

  [2mfix[0m  [1muse `{ files: [...] }`[0m
```

Paste what vx printed, or open a code:

<ErrorFinder codes={['VX_E_CONFIG', 'VX_E_CYCLE', 'VX_E_DEPENDS_ON', 'VX_E_OUTPUT_OVERLAP', 'VX_E_INPUT_IS_OUTPUT', 'VX_E_NESTED_INPUT', 'VX_E_NESTED_OUTPUT', 'VX_E_DEPENDENCY_RULE']} />

- **`… has unknown field "<key>"`.** A typo, or a Turbo or Nx key. The message lists the fields vx allows.
- **`dependsOn cycle`.** Two tasks wait for each other: remove one `dependsOn` from the loop it prints.
- **`dependsOn …, but` `no project is named …` / `… declares no task …`.** Use the name it suggests or one of the projects it lists, add that task to that package, or remove the entry.
- **`timed out after …`.** The task ran past its time limit: raise `exec.timeout` or `--timeout` ([Handle failures and hangs](#5-handle-failures-and-hangs)).

- **`inputs matched no files`.** The globs find nothing. Paths are
  relative to the project's folder: fix them.
- **`outputs matched no files`.** The command never wrote what
  `outputs.files` names: see [Skip work already done](#3-skip-work-already-done).

<Takeaway>fix any config `vx lock` refuses, from the line it points at.</Takeaway>

</Deeper>
