```sh

```


Four parts, top to bottom:

| Part | Tells you |
| --- | --- |
| **Why** | both runs, each with its result and key |
| `verdict` | the answer in one line: what moved |
| **What changed** | each moved part, with its value before and after |
| **What to do** | whether this is expected, and how to fix it if not |

The keys differ and the verdict names the file. That run was **expected**: you edited an input.

<Takeaway>find the one file that made a task run.</Takeaway>

## Spot each kind of change

<Takeaway>tell a file, a variable and a config change apart at a glance.</Takeaway>

<Deeper level="patterns" title="Common cases">

### A task runs every time

The verdict starts `never cached`. The task, or one it depends on, has no `inputs`, so each run makes a new key. Add `inputs` to the task the verdict names.

### A task skipped when it should have run

`vx why` says the key did not move, so the file you changed is not an input. Add it to `inputs.files` and run `vx lock`.

<Aside type="tip" title="Find the missing input for good">
  Add [`exec.sandbox`](../../sandboxing/) to the task. A read outside its inputs fails the task and
  names the file.
</Aside>

### Ask about an older run

`vx last --list` lists recent runs. Pass one's id to compare that run with the one before it:

```sh
vx why @demo/ui#build --run 01a209c0-fc0b-7616-8c58-7e50479c4225
```

### Read it from a script or an agent

`--format json` prints the same answer as one object:

```sh
vx why @demo/web#build --format json
```

```json
{
  "taskId": "@demo/web#build",
  "diff": {
    "entries": [
      { "kind": "upstream", "name": "@demo/ui#build", "change": "changed", "before": "235118720ed1a79b", "after": "693d3b58e7193bca" }
    ],
    "unchangedCount": 7
  },
  "roots": [
    {
      "entries": [{ "kind": "file", "name": "packages/ui/src/index.ts", "change": "changed" }]
    }
  ]
}
```

Trimmed: the full object also holds both runs' keys, times and results, and each root's path of tasks.

<Takeaway>fix a task that never caches or one that never runs, and script the answer.</Takeaway>

</Deeper>

<Deeper level="details" title="Every option and kind">

```sh
vx why (TASK | PKG#TASK) [--run RUNID] [--format pretty|json] [--cache-dir <path>]
```

| Option | Default | What it does |
| --- | --- | --- |
| `TASK` or `PKG#TASK` | required | the task to explain; `build` alone means the project in the folder you are in |
| `--run <id>` | the latest run | explain that run instead |
| `--format` | `pretty` | `json` for one object |
| `--cache-dir <path>` | the workspace's | read the cache a run with the same flag used |

| `kind` | Moved because |
| --- | --- |
| `file` | a file in `inputs.files` or `inputs.workspaceFiles` changed, appeared or went |
| `linked` | a symlink among the inputs points somewhere else |
| `env` | a variable in `inputs.env` changed |
| `runtime` | a command in `inputs.runtime` printed something else |
| `ws-runtime` | a command in `inputs.workspaceRuntime` printed something else |
| `upstream` | a task it depends on got a new key |
| `config` | the task's config changed, or a file the config imports |
| `forward` | the arguments after `--` changed |
| `plugin` | a plugin's part of the key moved, such as the package's dependencies in the lockfile |
| `platform` | the task ran on another platform |
| `format` | vx itself changed: a new vx version keys every task anew once |

`vx why` reads the run history in `.vx/cache`. `vx cache clean` empties it, so `vx why` has nothing to compare until two more runs.

Every verdict line vx prints: [Caching](../../caching/#find-why-a-task-ran-again). The command in full: [`vx why`](../../../cli/why/).

</Deeper>
