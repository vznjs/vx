List two machine sizes. vx learns which tasks need the big one, and starts it only for them.

```ts
cpu4: { max: 8, cpu: 4, memory: '16GB' },
cpu16: { max: 2, cpu: 16, memory: '64GB' },
```

<Concept term="Machine size">
  One kind of machine a worker type can start, such as `cpu4` or `cpu16`. A worker's name says both:
  `linux.cpu16#1` is worker 1 of the `cpu16` size of the `linux` type.
</Concept>

## Declare two sizes

```ts title=".vx/workspace.ts" ins={10-15}
dte({
  workers: {
    linux: {
      machines: {
        cpu4: {
          max: 8,
          cpu: 4,
          memory: '16GB',
        },
        cpu16: {
          max: 2,
          cpu: 16,
          memory: '64GB',
          runsOn: 'ubuntu-latest-16-cores',
        },
      },
    },
  },
  adapter: github(),
}),
```

Read the new size as: up to **2** machines of **16** cores and **64GB**, on the `ubuntu-latest-16-cores` runner.

<Aside type="caution" title="Say what the runner really has">
  vx plans by `cpu` and `memory` until a worker reports its machine. A runner with less shows in
  red on the workers line, such as `declared 16c/64G · actual 4c/14G`, and tasks get fewer
  cores than planned.
</Aside>

<Takeaway>offer a big machine without paying for it on every task.</Takeaway>

## Send each size to its runner

Run `vx dte init --force`: it writes both workflows again. `vx-worker.yml` now maps each size to its runner:

```yaml title=".github/workflows/vx-worker.yml"
    runs-on: ${{ fromJSON('{"linux.cpu4":"ubuntu-latest","linux.cpu16":"ubuntu-latest-16-cores"}')[inputs.size] }}
```

Look at the two keys: `linux.cpu4` and `linux.cpu16`, one per size.

<Takeaway>run each size on the CI runner you pay for.</Takeaway>

## How vx picks the size

1. A task with no history runs on any free core. To decide how many machines to start, vx counts it as 2 cores and 4GB.
2. vx records the cores and memory it used.
3. A task that used about all of its machine runs on a **bigger** size next time.

<Quiz q="A vite build used every core of a cpu4 machine in its last run. Where does it run next?">
  On `cpu16`. A task that filled its machine only goes to a bigger one. A lint task that used one
  core keeps sharing a `cpu4`.
</Quiz>

<Deeper level="patterns" title="Common setups">

### Some tasks on macOS

Add a type whose machine names its platform. `vx dte init` runs it on `macos-latest`:

```ts title=".vx/workspace.ts"
mac: {
  machines: {
    m1: {
      max: 2,
      cpu: 3,
      memory: '7GB',
      platform: 'darwin-arm64',
    },
  },
},
```

A task with `exec.platforms: ['darwin-arm64']` runs only there.

### No cap on a size

Leave out `max` and a run starts as many as its work needs:

```ts
cpu4: { cpu: 4, memory: '16GB' },
```

### Count new tasks bigger

`unmeasured` changes the 2 cores and 4GB of step 1. Raise it if most of your tasks are heavy:

```ts
dte({ unmeasured: { cpu: 4, memory: '8GB' }, /* … */ }),
```

<Takeaway>add macOS, lift a cap and tune how new tasks are counted.</Takeaway>

</Deeper>

<Deeper level="details" title="Every option">

#### A machine size

| Field | What it does | Default | Example |
| --- | --- | --- | --- |
| `cpu` | Its cores. vx counts on them until the worker reports its real machine. Required. | none | `4` |
| `memory` | Its memory, in bytes or as text. Required. | none | `'16GB'`, `'512MiB'` |
| `max` | How many may be in the run at once. One lost or failed to start is replaced. | no cap | `8` |
| `platform` | `linux-x64`, `linux-arm64`, `darwin-x64` or `darwin-arm64`. A worker that joins on another is refused. | this machine's, not checked | `'darwin-arm64'` |
| `runsOn` | The CI runner label `vx dte init` writes for it. | the platform's GitHub-hosted runner | `'ubuntu-latest-16-cores'` |

Names of types and sizes use letters, digits, `_` and `-`. A field vx does not know, such as `maxx`, is refused.

#### How a run sizes itself

- Only work counts: a task that missed the cache, or waits on one that did, and every uncached task.
- A task with history books its average cores (a whole core at least) and its peak memory.
- A task that used 90% or more of its machine's cores or memory takes a whole bigger machine next time.
- Change a size's cores, memory, platform or runner, and vx forgets what it measured for that size.
- A worker that is idle, with nothing left it could take, leaves.

All of `dte()`'s options: [Spread a CI run over several machines](../spread-ci-over-machines/#dteoptions).

</Deeper>
