<Concept term="Worker">
  A machine (or here, a process) that takes tasks from your run, runs them and hands back the
  result. Your run still prints one result.
</Concept>

## Add `local()`

Give `dte()` one group of workers, here named `linux`. `local()` starts each worker as a process in its own **git worktree**: a second checkout of your workspace, made by git.

```ts title=".vx/workspace.ts" ins={2,8-11}
import { defineWorkspace } from '@vzn/vx/config'
import { dte, local } from '@vzn/vx-dte'
import { bun } from '@vzn/vx-lockfile'

export default defineWorkspace({
  plugins: [
    bun(),
    dte({
      workers: { linux: { machines: { cpu4: { max: 2, cpu: 4, memory: '8GB' } } } },
      adapter: local({ prepare: 'bun install' }),
    }),
  ],
})
```

Read it as: up to **2** workers (`max`), each counted as **4** cores and **8GB**. `prepare` installs packages in each worktree.

```sh
bun add -d @vzn/vx-dte
vx lock
```

<Takeaway>declare workers in five lines, with no CI and nothing to host.</Takeaway>

## Watch a run spread

Workers see what git tracks, your edits included. So `git add` new files first, then name the run with `VX_DTE_RUN`:

```sh
git add -A
VX_DTE_RUN=$(uuidgen) vx run build --all
```

<Deeper level="patterns" title="Common setups">

### A new file the task reads

A worker builds from what git tracks. A file git does not know fails the task and names it:

```ansi
[38;2;239;68;68m[vx] @demo/ui#build: plugin '@vzn/vx-dte' (executor 'dte') failed in execute: @demo/ui#build keys packages/ui/src/notes.ts, which git does not track, so no worker has it: git add it (and commit it for workers on CI), or leave it out of the task's inputs[0m
```

Fix: `git add packages/ui/src/notes.ts`, then run again.

### A slow install

`prepare` runs once per worktree, before its worker starts. Point it at what your workspace needs:

```ts
adapter: local({ prepare: 'bun install --frozen-lockfile' }),
```

### More workers at once

Raise `max`. Each worker is a full process, so stay near your core count:

```ts mark={1}
workers: { linux: { machines: { cpu4: { max: 4, cpu: 4, memory: '8GB' } } } },
```

<Takeaway>fix an untracked file, a custom install and the worker count.</Takeaway>

</Deeper>

<Deeper level="details" title="Every option">

#### `local(options?)`

| Option | What it does | Default | Example |
| --- | --- | --- | --- |
| `prepare` | A shell line each worktree runs before its worker starts. A non-zero exit fails that worker and prints why. | none | `'bun install'` |

#### What turns it on

| Name | What it does |
| --- | --- |
| `VX_DTE_RUN` | Names the run and turns distribution on. Any unique value; `uuidgen` makes one. Unset, `vx run` stays on this machine. |

#### What a worker sees

- A worktree of your tracked files as the run saw them at its start, uncommitted edits included.
- The bytes git stores, with git's filters undone: line endings, `ident`, LFS. A task whose input differs on disk, such as a CRLF checkout, fails and names the file.
- A relay on this machine that `local()` starts and stops with the run. Nothing to deploy.
- The same cache as the run, so outputs come home at once.

`dte()`'s own options (`workers`, `relay`, `unmeasured` and the rest): [Spread a CI run over several machines](../spread-ci-over-machines/#dteoptions).

</Deeper>
