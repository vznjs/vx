Give end-to-end tests machines of their own, while every other task shares the usual ones.

```ts
exec: { command: 'playwright test', worker: 'e2e' }
```

<Levels />

<Diagram {...dteWorkerTypes} />

<Concept term="Worker type">
  A named group of machines in `dte({ workers })`, such as `linux` or `e2e`. A task can ask for one
  by name.
</Concept>

## Declare a second type

Add `e2e` next to `linux`. Order matters: tasks that name no type go to the **first** one that fits.

```ts title=".vx/workspace.ts" ins={4}
dte({
  workers: {
    linux: { machines: { cpu4: { max: 8, cpu: 4, memory: '8GB' } } },
    e2e: { machines: { cpu4: { max: 2, cpu: 4, memory: '8GB' } } },
  },
  adapter: github(),
}),
```

<Takeaway>keep a separate pool of machines for one kind of work.</Takeaway>

## Name it on the task

```ts title="apps/web/vx.config.ts" mark={3}
e2e: {
  dependsOn: ['build'],
  exec: { command: 'playwright test', worker: 'e2e' },
  inputs: { files: ['src/**', 'tests/**'] },
},
```

Run `vx lock`, then `vx dte init` to add the new machines to `vx-worker.yml`. Now run it:

<Quiz q="You add a lint task with no exec.worker. Which machines run it?">
  `linux`: it is listed first and fits. `e2e` only gets tasks that name it, or that no type before
  it can take.
</Quiz>

<Deeper level="patterns" title="Common setups">

### Playwright on Ubuntu, the rest on Alpine

Each type can run on different CI runners, with their own images and tools:

```ts title=".vx/workspace.ts"
workers: {
  alpine: { machines: { cpu4: { max: 8, cpu: 4, memory: '16GB', runsOn: 'alpine-4-cores' } } },
  ubuntu: { machines: { cpu4: { max: 2, cpu: 4, memory: '16GB' } } },
},
```

```ts title="apps/web/vx.config.ts"
e2e: { exec: { command: 'playwright test', worker: 'ubuntu' } },
```

### A catch-all type last

Put a big type last. It gets only what the types before it cannot take:

```ts
workers: {
  linux: { machines: { cpu4: { max: 8, cpu: 4, memory: '16GB' } } },
  big: { machines: { cpu16: { max: 1, cpu: 16, memory: '64GB', runsOn: 'ubuntu-latest-16-cores' } } },
},
```

<Takeaway>split work by tools or by size with nothing but types and their order.</Takeaway>

</Deeper>

<Deeper level="details" title="Every rule">

#### `exec.worker`

| Fact | `exec.worker` |
| --- | --- |
| What it does | Runs the task only on machines of that worker type. |
| Default | none: the first type in `workers` that fits the task. |
| Value | a type's name from `dte({ workers })`. |
| In the cache key | no: moving a task to another type never changes its key. |
| On your machine | ignored: a run without workers runs it here. |

#### Where a task goes

- A task that names no type goes to the first type with a machine of its platform.
- A task with [`exec.platforms`](../../tasks/) runs only on a worker of one of them.
- A task no worker can take stops the run before any task starts, and names it.
- A task that reads what an uncached task leaves on its worker, where `exec.worker` or `exec.platforms` rule out the reader's machine, stops the run too. Cache the upstream task, or run both alike.
