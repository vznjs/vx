## Unreleased

<Deeper level="details" title="In the next release">

### Record an aborted task's runs row in the contract

A runs row and RunRecord.status may be 'aborted'.

### `WorkerRuntime.probe` takes the task's own PATH

`WorkerRuntime.probe` takes an optional fourth argument, path; answerRuntime an optional definedPath.

### Runs read the lock only, never a config

A run reads only the lock. A vx.config, or a package.json name, added since `vx lock` is not refused: the run ignores it until you run `vx lock`.

`turbo()` and `nx()` read no turbo.json or nx.json on a run. turbo.json `concurrency` and nx.json `parallel` and `defaultBase` reach a run only through the `.vx/workspace.ts` that `bunx @vzn/vx-migrate` writes.

Turbo's `futureFlags.githubActionsRemoteBaseRefFallback` is not read.

`PreparedRun.unlockedConfig` is gone.

### A task with empty inputs needs exec

A task with no `exec` and empty `inputs` is refused. Add `exec`, or drop `inputs` to make it a group.

The `cache`, `outputs` and `inputs.stability` refusals of such a task name `exec`.

### Both locks have new versions, and vx lock refuses more

`.vx/projects.lock` is version 10 and `.vx/dependencies.lock` version 7: each project's lines sit together, so branches that edit different projects merge cleanly. Run `vx lock` once and commit both locks.

`vx lock` refuses:

- `exec.persistent.readyWhen: ''`, which matched any line. Omit `readyWhen` to be ready once the task starts.
- a name listed twice in `inputs.env`, `exec.env.passThrough`, `exec.env.secret` or `tags`. Keep one of each.
- a dependency rule whose only list is `deny: []`. Delete the rule.
- an `inputs.files` or `outputs.files` glob that reaches into a nested project past its fixed folder, such as a root `packages/**/*.log`. Let the member's task own them, or take them back with `!packages/a/**`.
- a project named with a leading `-`, which `vx run -web#build` read as a flag. Rename the project.

A run refuses an `inputs.files` link into another project (`VX_E_NESTED_INPUT`) unless a task it depends on there declares the target in `inputs.files` or `outputs`.

Declare it there, or take the link back (`!src/a`) and name its files in `inputs.workspaceFiles`.

A plugin's `setup` that returns a value fails, and a `teardown` that returns one is warned. Close it in `teardown` and return nothing.

ui.Column's object form has an optional `align`: a plugin that reads `column.align` handles `undefined`.

`defineProject` types require `exec` beside a literal empty `inputs` list. `Cache.orphanStats()` also returns `missing` and `missingBytes`. `AffectedReason.kind` gains `'always'`.

## v0.0.660

### Locks, lock problems, dry runs and edited configs

`.vx/projects.lock` is version 9 and `.vx/dependencies.lock` version 6. Run `vx lock` once to rewrite both.

`vx lock --check --format json` lists each problem as `{ code, message }`, not as a string.

`vx run --dry=json` → `vx run --dry --format json`; `--dry=pretty` → `--dry`; pipeline `dry: 'json'` → `dry: true, format: 'json'`.

After editing a `vx.config.ts`, run `vx lock` before `vx run`, `vx show`, `vx why` or `vx pipeline`: the run refuses with `VX_E_LOCK`, naming the file, instead of running the config the lock holds.

### Sandboxed tasks do not read credential stores

A sandboxed task does not read browser profiles, `~/.config/sops/age`, `~/.config/rclone`, `~/.my.cnf`, `~/.password-store` or `~/.sentryclirc`.

A task that needs one names it in `exec.sandbox.allow.read`.

Variables whose names hold `PASSPHRASE` or end in `_PASS` are masked in output.

### Run history starts empty once

The local index schema is v58: it resets once, so the run history starts empty.

Nothing to do. `vx last` and `vx why` show only runs made after the upgrade. A piped run prints the Tasks header once.

### A --force run replaces the entry its key held

A `--force` run replaces the local entry under its key. A custom cache layer drops `kept()` and `stampWritten()`: vx does not call them.

### A --filter that matches nothing refuses the run

A `--filter` that matches no project, an exclusion too, refuses the run even when another filter matched. Fix or remove it in your CI scripts and pipelines.

### Fail a task whose declared output path matched nothing

A declared output that matches no files fails the task instead of warning.

An output named by path (`dist/index.js`, `dist`) must exist. A wildcard (`dist/**`) may match nothing, as long as one output matched.

Run your tasks once after upgrading. A task that fails with `outputs matched no files (<glob>)` needs that glob fixed to match what the command writes, or removed from `outputs.files`.

### Replace --continue with --fail-fast

`--continue` is gone: use `--fail-fast`. Rename each one you use:

- `--continue` → `--fail-fast`
- `run.continue` → `run.failFast`
- `VX_RUN_CONTINUE` → `VX_RUN_FAIL_FAST`
- pipeline key `continue` → `failFast`
- `RunOptions.continueMode` → `failFast`

Replace each use:

- `--continue=never` or `run.continue: 'never'`: use `--fail-fast` or `run.failFast: true`. Tasks still running are killed.
- `--continue`, `--continue=always`: remove it. A failed task's dependents never run.
- `--continue=deps-ok`: remove it. That is the default.

### Drop the lock merge driver, name it .vx/projects.lock

`vx lock` writes `.vx/projects.lock`, not `.vx/projects.lock.jsonl`, and `vx lock --merge` is gone.

Delete the old lock, the old attributes file and the merge driver, then lock again:

```sh
git rm .vx/projects.lock.jsonl .vx/.gitattributes
git config --remove-section merge.vx-lock
vx lock
git add .vx
```

`vx lock` writes `.vx/.gitattributes` only when none exists, so the old one goes first. After a merge conflict in a lock, run `vx lock` and commit.

### Forwarded args reach one task, CI prints failed tasks only

Args after `--` go to one task in one project. A run with `--affected`, several tasks, or a filter that picks the task in two projects is refused.

Run each task on its own: `vx run test --filter ui -- --watch`.

On CI a run prints only failed tasks. To see every task, pass `--output-logs full` or set `VX_RUN_OUTPUT_LOGS=full`.

### Refuse two tasks whose outputs can share a path

`vx lock` refuses two tasks whose output globs can match one path, such as `*.js` beside `*b*`. Narrow one glob so the two tasks write no common path.

### Replace --continue with --fail-fast: the JavaScript API

`RunOptions.continueMode` is `failFast`.

Artifacts stored under the old names are not read. `blobName()` is async: `await` it.

## v0.0.655

### Everyday workspaces never cache a wrong build

`CACHE_VERSION` is `vx-cache-v56` and the index schema is `v56`. Caches start empty once, so every cached task misses once after you upgrade.

Run `vx lock` again after you upgrade. `vx-lockfile` digests changed, so `vx lock --check` fails on the old lock.

### Drop core's root and config entry shims

@vzn/vx does not ship index.ts or config/index.ts; a vx binary from 0.0.484 or older cannot load it.

<Deeper level="details" title="For plugin authors and server hosts">

### Group executor capabilities and distribution

`TaskExecutor` keys moved into two groups. Any other executor key refuses the run.

- `remote`, `sandbox`, `servers`, `runtime`, `exclusive`, `timeouts`, `platforms`, `capacity` → under `capabilities`
- `workers`, `demand`, `running`, `unneeded`, `footer`, `machines`, `idealMs`, `advice`, `profile` → under `distribution`

`@vzn/vx` does not export `localFloor`, `LocalFloor`, `sandboxRequestFor`, `sweepPlaceholders`, `SandboxRequest` or `BoundedCapture`.

It also drops `answerRuntime`, `packageManagerPath` and `sampleTrees`.

A worker calls `workerRuntime({ root })` and uses `prepare(task)` → `run()` / `sweep()`, `probe`, `packageManager` and `sample`.

### `foldScriptHooks` is not exported

`@vzn/vx` does not export `foldScriptHooks`.

For migrator authors:

- `ApplyMigrationArgs` drops `unmapped`: pass `emptyReason` and `example`.
- `MigrationMember`'s `packageJson` → `esModule`
- Core runs no formatter unless the migrator passes `written`.

### Lockfile plugins name importers links

LockfileClaim's `importers` option and hook are `links`, and `LockfileImporter` is not exported from @vzn/vx.

### Group TaskOutcome by concern, a union by status

`TaskOutcome` fields moved into groups. Update each read:

- `storedDurationMs`, `storedCpuMs`, `storedPeakRssBytes` → `cache.stored.{durationMs, cpuMs, peakRssBytes}`
- `restored`, `saved`, `inputFiles`, `artifactBytes`, `outputBytes` → `cache.*`
- `inputChanges`, `unkeyed`, `driftedInput`, `keylessBy` → `cache.*`
- `cacheOff` → `cache.off`; `outputs: 'deferred'` → `cache.deferred: true`
- `queuedMs`, `admissionHeldMs`, `fetchMs`, `saveMs` → `timing.*`
- `wallclockStartNs`, `wallclockEndNs` → `timing.startNs`, `timing.endNs`
- `cpuMs`, `peakRssBytes`, `peakCores`, `avgRssBytes` → `usage.*`
- `where`, `carried` → `placement.*`
- `whereCores`, `whereMemoryBytes`, `cpuShare` → `placement.cores`, `placement.memoryBytes`, `placement.cpuShare`
- `attempts` → `attempts.count`
- `failedAttempts`, `attemptOutputs`, `flaky` → `attempts.failed`, `attempts.outputs`, `attempts.flaky`
- `sandboxViolations`, `sandboxViolationLines`, `sandboxFix` → `sandbox.violations`, `sandbox.lines`, `sandbox.fix`

A skipped outcome has no `exitCode`. Read `exitCodeOf(outcome)` for the exit code a record writes.

A skipped outcome keeps `hash` only when `--fail-fast` stopped it after its key was computed.

The groups and status variants are exported as types.

`RunOptions` loses `staged`, `discovered`, `selectedByDiff`, `selectedOutright`, `affectedReasons` and `remoteRequested`.

It also loses `remoteReadOnlyByDefault`, `summaryTable`, `holdPersistent`, `watch`, `keep` and `commandWindows`.

vx's CLI passes those internally; `run()` and `planRun()` do not read them. Drop them from your calls.

### Cache does not record runs

`Cache` loses `recordRun`, `recordRuns`, `recordMeasures`, `recordRunBundle` and `recordRemoteErrors`. No public replacement: core records each run itself.

`CacheLayer` and `LayeredCache` lose `recordRunBundle`. A custom layer's `recordRunBundle` is not called.

On `Cache`, call these through `cache.memo.<name>` (`StoreMemo`):

- `hashFile`, `hashBytes`, `hashFiles`
- `knownBlobSizes`, `rememberBlobSizes`, `holdBlobSizes`, `storeHeldBlobSizes`
- `blobVerdict`, `rememberBlobVerdict`
- `loadOutputFilesBatch`, `isOutputsCurrent`, `recordOutputDirs`, `recordOutputStamps`
- `loadOutputDirsBatch`, `outputDirsCurrent`
- `foldMemo()` → `cache.memo.folds`

`CacheLayer` and `LayeredCache` lose `hashFile`, `loadOutputFilesBatch`, `isOutputsCurrent`, `recordOutputDirs`, `recordOutputStamps`, `loadOutputDirsBatch` and `outputDirsCurrent`.

A layer hands those out as `layer.memo` (`TaskMemo`).

### Check tokens with @vzn/vx-devtools

The relay does not export `parseAllow`, `TokenError`, `Allowed`, `repositoryClaimOf` or `workflowClaimOf`. Use `parseAllow`, `Refusal` and `Admits` from `@vzn/vx-devtools`.

Refusal texts changed. Update any script or alert that matches them:

- `this relay's ALLOW` → `this server's ALLOW`
- `repository <r>` names the token field, lowercased: `repository` or `project_path`.
- `workflow <w>` → `job_workflow_ref <w>` or `ci_config_ref_uri <w>`
- The audience hint ends `or set the server's AUDIENCE`.
- The issuer is checked before the header's `alg`.
- A signature no held key made reads `bad signature`.

The image bundles `@vzn/vx-devtools`, so build it from the repo root.

### Time worker warm-ups as tasks in history

PLUGIN_HOOKS gains measures, before schedule.
