vx runs the tasks of a JavaScript monorepo in the right order, many at once, and never does the same work twice.

```sh
bunx @vzn/vx init
vx run build --all
```

<Levels />

## Three ideas run everything

Each project lists its tasks in a `vx.config.ts`:

```ts title="packages/web/vx.config.ts" mark={6,8,9,10}
import { defineProject } from '@vzn/vx/config'

export default defineProject({
  tasks: {
    build: {
      dependsOn: ['^build'],
      exec: { command: 'vite build' },
      inputs: { files: ['src/**', 'index.html', 'vite.config.ts'] },
      outputs: { files: ['dist/**'] },
      cache: true,
    },
  },
})
```

<Concept term="Task">
  One command for one project (`vite build`), with the files it reads (`inputs`) and writes
  (`outputs`).
</Concept>

<Concept term="Dependencies first">
  `^build` means: build every package this one uses before this one. That is why ui ran before web.
</Concept>

<Concept term="Cache">
  vx remembers each task's outputs under a key made from its inputs. Same inputs: vx skips the task
  or copies the outputs back.
</Concept>

<Quiz q="You edit a file in packages/web/src. Which builds run?">
  Only `@demo/web#build`. ui does not read web's files, so its key stays the same and it is up to
  date.
</Quiz>

<Deeper level="details" title="What vx never does">

- **Guess.** Nothing is inferred. A task is cached only when it lists what it reads and writes.
- **Wrap other runners.** A task calls the tool itself (`vite build`, `vitest run`, `oxlint`), never a package script.
- **Need an account.** Everything runs on your machines and your CI. There is no cloud.

vx runs on [Bun](https://bun.com) 1.4.4 or later, on macOS and Linux (glibc).

</Deeper>

<Takeaway>read any `vx.config.ts` and say what it does.</Takeaway>
