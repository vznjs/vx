Bump a dependency of one project. vx rebuilds that project and leaves the rest alone.

```ts title=".vx/workspace.ts" mark={2,4}
import { defineWorkspace } from '@vzn/vx/config'
import { bun } from '@vzn/vx-lockfile'

export default defineWorkspace({ plugins: [bun()] })
```

<Levels />

<Concept term="Lockfile">
  The file your package manager writes on install (`bun.lock`, `pnpm-lock.yaml`,
  `package-lock.json`, `yarn.lock`). It records the exact version of every dependency.
</Concept>

## Add the plugin

Pick your package manager. Each plugin reads its own lockfile.

<Tabs syncKey="pm">
  <TabItem label="Bun">
    ```ts title=".vx/workspace.ts"
    import { defineWorkspace } from '@vzn/vx/config'
    import { bun } from '@vzn/vx-lockfile'

    export default defineWorkspace({ plugins: [bun()] })
    ```
  </TabItem>
  <TabItem label="pnpm">
    ```ts title=".vx/workspace.ts"
    import { defineWorkspace } from '@vzn/vx/config'
    import { pnpm } from '@vzn/vx-lockfile'

    export default defineWorkspace({ plugins: [pnpm()] })
    ```
  </TabItem>
  <TabItem label="npm">
    ```ts title=".vx/workspace.ts"
    import { defineWorkspace } from '@vzn/vx/config'
    import { npm } from '@vzn/vx-lockfile'

    export default defineWorkspace({ plugins: [npm()] })
    ```
  </TabItem>
  <TabItem label="Yarn">
    ```ts title=".vx/workspace.ts"
    import { defineWorkspace } from '@vzn/vx/config'
    import { yarn } from '@vzn/vx-lockfile'

    export default defineWorkspace({ plugins: [yarn()] })
    ```
  </TabItem>
</Tabs>

Then run `vx lock` and commit what it writes.

<Aside type="caution" title="No plugin, no lockfile in the key">
  Without a plugin, no lockfile is in any key. An install then re-runs **nothing**, and a cached
  build can come back built against the old versions.
</Aside>

<Takeaway>make every install count: your lockfile is in every task's key.</Takeaway>

## One install, only what it reached

<Diagram {...lockfileSlices} />

The plugin cuts the lockfile into one slice per project: the packages that project reaches.
A slice goes into the keys of that project's tasks only.

```ansi title="bump ms in @demo/web"
[2m$[0m vx run build --all --output-logs hash-only

[38;2;34;197;94mup-to-date[0m [38;2;192;132;252m@demo/ui[0m[2m#[0m[38;2;244;114;182mbuild[0m [2m7332bcf54e63d75c[0m
[38;2;34;197;94msuccess[0m [38;2;244;114;182m@demo/web[0m[2m#[0m[38;2;244;114;182mbuild[0m [2m71a8fb022989b08b[0m
```

```ansi title="bump clsx in @demo/ui"
[2m$[0m vx run build --all --output-logs hash-only

[38;2;34;197;94msuccess[0m [38;2;192;132;252m@demo/ui[0m[2m#[0m[38;2;244;114;182mbuild[0m [2m48e5676c2d17350c[0m
[38;2;34;197;94msuccess[0m [38;2;244;114;182m@demo/web[0m[2m#[0m[38;2;244;114;182mbuild[0m [2m3c0c3098859278d0[0m
```

Read the first word of each line. After the `clsx` bump, both say **success**. `@demo/web` builds
on `@demo/ui`, so a new `@demo/ui` key gives it a new key.

<Aside type="tip" title="One line per task">
  `--output-logs hash-only` prints each task's status, name and key, and hides the tool's output.
</Aside>

<Quiz q="@demo/ui adds a devDependency it only uses in tests. Does @demo/web#build run again?">
  Yes. The dependency is in `@demo/ui`'s slice, so `@demo/ui#build` gets a new key, and
  `@demo/web#build` follows it: it builds on `@demo/ui`.
</Quiz>

<Takeaway>predict which projects an install re-runs: the ones whose dependencies it changed, and the projects built on them.</Takeaway>

## Link projects to each other

The lockfile lists every project by its package name and what it depends on. The plugin hands both
to vx, so `dependsOn: ['^build']` ("build my dependencies first") knows `@demo/ui` comes first.

Without a plugin, projects go by their folder (`packages/ui`), and `vx lock` refuses a `^`:

```ansi title="no plugin in .vx/workspace.ts"
[2m$[0m vx lock

[38;2;239;68;68m✗[0m [1mvx lock[0m  [38;2;203;213;225mlock not written[0m

  [38;2;203;213;225mpackages/ui#build: ^build needs project edges; add pnpm()/bun()/npm()/yarn() from @vzn/vx-lockfile to plugins in .vx/workspace.ts and install so its lockfile exists, or a plugin that returns [0m[1m`deps`[0m
[38;2;239;68;68m✗[0m [1mvx lock[0m  [38;2;203;213;225malso refused[0m

  [38;2;203;213;225mpackages/web#build: ^build needs project edges; add pnpm()/bun()/npm()/yarn() from @vzn/vx-lockfile to plugins in .vx/workspace.ts and install so its lockfile exists, or a plugin that returns [0m[1m`deps`[0m
```

<Takeaway>use `^build`: the lockfile tells vx that `@demo/ui` builds before `@demo/web`.</Takeaway>

## Run only what an install affected

`--affected` runs the projects a change touched. With a plugin, a lockfile change counts too: only the
projects whose slice moved are affected.

```ansi title="after the ms bump in @demo/web, before the commit"
[2m$[0m vx show --affected=HEAD

[4m[58;2;110;118;129m  [1m[38;2;167;139;250mProjects[0m[4m[58;2;110;118;129m [2m1[0m[4m[58;2;110;118;129m                                                                                                            [0m
  [2mproject    dir           tasks[0m
  [38;2;244;114;182m@demo/web[0m  [38;2;203;213;225mpackages/web[0m  [38;2;203;213;225m1 task[0m
```

One project: `@demo/web`. Its slice moved; `@demo/ui`'s did not.

<Takeaway>run CI on a dependency bump without rebuilding the whole workspace.</Takeaway>

<Deeper level="patterns" title="Common setups">

### One key for the whole lockfile

`scope` takes `'project'` (the default: each key holds its project's slice) or `'workspace'`.
`'workspace'` puts the whole lockfile into every key, so any install re-runs everything.

```ts title=".vx/workspace.ts" mark={4}
import { defineWorkspace } from '@vzn/vx/config'
import { bun } from '@vzn/vx-lockfile'

export default defineWorkspace({ plugins: [bun({ scope: 'workspace' })] })
```

The same `ms` bump in `@demo/web` now re-runs both projects:

```ansi title="scope: 'workspace'"
[2m$[0m vx run build --all --output-logs hash-only

[38;2;34;197;94msuccess[0m [38;2;192;132;252m@demo/ui[0m[2m#[0m[38;2;244;114;182mbuild[0m [2m6068b4831dff8b0f[0m
[38;2;34;197;94msuccess[0m [38;2;244;114;182m@demo/web[0m[2m#[0m[38;2;244;114;182mbuild[0m [2mc586d60cd9f95027[0m
```

### A tool every project uses

Put shared tools (`vite`, `vitest`, `oxlint`) in the root `package.json`. Their bins run from the
root `node_modules/.bin`, which is on every task's `PATH`.

```json title="package.json" ins={4}
{
  "workspaces": ["packages/*"],
  "devDependencies": {
    "vite": "8.3.8"
  }
}
```

So every key holds the root's dependencies. Bumping `vite` here re-runs every project.

### A workspace project the root depends on

A workspace project in the root's dependencies counts only for the root. A project that loads it
names it in its **own** `package.json`.

```json title="packages/web/package.json" ins={3}
{
  "dependencies": {
    "@demo/ui": "workspace:*"
  }
}
```

Without that line, `@demo/web` does not build after `@demo/ui`, its key leaves `@demo/ui` out, and
`--affected` skips it.

<Aside type="caution" title="Undeclared imports">
  An import you never declared in `package.json` is in no project's key. Declare every
  dependency a project loads.
</Aside>

<Takeaway>keep each key true: shared tools at the root, links in each `package.json`.</Takeaway>

</Deeper>

<Deeper level="details" title="Every option and what goes into a key">

### Options

All four plugins take one option, `scope`, shown [above](#one-key-for-the-whole-lockfile). Its values
and default are in [every plugin option](../../docs/plugins/#pnpm-bun-npm-yarn).

### Which lockfiles each plugin reads

- `pnpm()`: `pnpm-lock.yaml`, lockfile versions 5, 6, 9 and 13
- `bun()`: `bun.lock` (the text lockfile)
- `npm()`: `npm-shrinkwrap.json` or `package-lock.json`, versions 2 and 3
- `yarn()`: `yarn.lock`, berry (yarn 2 and later) and yarn 1

### What each plugin adds to a key

| Plugin   | A project's key includes                                                              | Install-wide, for every project |
| -------- | ------------------------------------------------------------------------------------- | ------------------------------- |
| `pnpm()` | every package it reaches, by name, version and resolved peers, with integrity and any patch; under `nodeLinker: hoisted`, every peer variant of each | every top-level field but `importers`, `packages`, `snapshots`, `patchedDependencies`, `catalogs`, `overrides`, `ignoredOptionalDependencies` and `packageExtensionsChecksum` (`settings`, `onlyBuiltDependencies`, …) |
| `bun()`  | the same, through Bun's hoisted layout; a peer reaches every installed copy of its name | every top-level field but `workspaces`, `packages`, `catalog`, `catalogs`, `overrides` and `patchedDependencies` (`trustedDependencies`, …) |
| `npm()`  | the same, from the lockfile's versions                                                | the `lockfileVersion`; root `overrides` reach a project through the entries they force |
| `yarn()` | the same, from a berry lockfile, each entry with every field but its dependency lists; a yarn 1 lockfile records no workspaces, so every project's key includes the whole file | `__metadata`'s `version` and `cacheKey`, and the root workspace's entry (its `dependenciesMeta`) through the root's slice |

Every project's key also holds the root's own dependencies.

### Install settings in every key

Each plugin also adds a project's manifest (`package.json`, or under `pnpm()` a `package.json5` or
`package.yaml`) to its tasks' inputs, and its manager's install settings to every key:

| Plugin | Install settings in the key |
| --- | --- |
| `pnpm()` | `pnpm-workspace.yaml` except `patchedDependencies`, `overrides` and the catalogs (the lockfile records their effect per project), `.npmrc`, the root manifest's `pnpm` field |
| `bun()` | `bunfig.toml`, `.npmrc` |
| `npm()` | `.npmrc` |
| `yarn()` | `.yarnrc.yml`, `.yarnrc` and `.npmrc` (yarn 1), the root `package.json`'s `workspaces.nohoist`, `installConfig`, `resolutions` and dependency ranges |

### Edge rules

- **yarn 1** records no workspaces, so `yarn()` reads which project depends on which from the
  workspaces' `package.json` files.
- **pnpm `excludeLinksFromLockfile`** leaves every `link:` dependency out of the lockfile.
  `pnpm()` reads those from `package.json`, and every key holds every project's dependencies.
- **A patch a `postinstall` script applies** (`patch-package`) is in no lockfile. Name the patch
  files in the task's `inputs.workspaceFiles`, which reads from the workspace root, and run the
  install after a pull that changes one: vx cannot see which patch `node_modules` holds.

  ```js title="packages/web/vx.config.mjs"
  inputs: { files: ['src/**'], workspaceFiles: ['patches/**'] },
  ```

  An edit to a patch then re-runs the task; `vx why` names it:

  ```ansi
  verdict   cache key changed: file patches/x+1.0.0.patch
  ```
- **An unreadable lockfile** stops the run and names the install to re-run.
- **A lockfile changed since `vx lock`** stops the run: `run vx lock`.
- **A lockfile older than a `package.json`** (a dependency added, no install yet) stops `vx lock`
  until you install.
- **`vx why`** names the part `plugin @vzn/vx-lockfile/<manager>`, for example `plugin @vzn/vx-lockfile/pnpm`.

See [`@vzn/vx-lockfile`](../../plugins/vx-lockfile/) for the plugin's own page.
