Real open-source workspaces, built by vx and by the tool they ship with. Try the same on yours:

```sh
bunx @vzn/vx init --native
```

<Levels />

Each workspace is timed three ways. Step through them first:

<Walkthrough title="Three runs, three questions">
<Frame title="1. Cold build: how long does a full build take?">

Outputs and both caches are deleted. Every task runs. The number is the **total time**, since a real workspace has no ideal run to subtract.

</Frame>
<Frame title="2. Restore: how fast does a cache hit come back?">

Build outputs are deleted; the cache is kept. Every task is a hit, so the tool puts `dist/` back from its cache.

</Frame>
<Frame title="3. Nothing changed: what does the tool cost on its own?">

Nothing is deleted. Every task is a hit with its outputs already in place, so the whole run is the tool's own work.

</Frame>
</Walkthrough>

<Concept term="Cache hit">
  A task whose inputs have not changed since a stored run. The tool skips it and uses the stored
  outputs instead.
</Concept>

<Quiz q="Which row tells you the most about the tool itself, not your build?">
  **Nothing changed.** No task does any work there, so every millisecond is the tool's own.
</Quiz>

<Deeper level="details" title="Why line endings matter in this workspace">

vueuse sets `* text=auto eol=lf`. There Turborepo trusts git's index, and [a conformance case](../../conformance/inputs/#olfjum) shows it replaying stale output after a same-size line-ending change.

vx trusts the index there only for a file whose stored blob is the same size as the file. A line-ending conversion never leaves that. Every other file is checked on disk.

</Deeper>

<Deeper level="details" title="How these are measured">

**Same work.** Both tools run the same tasks, interleaved, each at its own default worker count. Turborepo runs with its daemon off.

**Best of N.** A cold build is the best of three runs. Restore and nothing changed are the best of up to thirty, because one run of them swings by 15 ms.

**Native config.** Each workspace's vx config follows its `turbo.json`. The config, commit and bench changes live in vx's source under `private/vx-bench/real/`.

**Every week.** A workflow measures them again. How the harness works is in [the benchmarks](../../benchmarks/#real-repos).

The synthetic benchmark, built to be fair to every tool, is on [vx vs Turborepo](../turborepo/) and [vx vs Nx](../nx/).

</Deeper>

## Try it on yours

```sh
bunx @vzn/vx init --native
vx run build --all
```

`--native` writes a `vx.config.ts` per package from your `turbo.json` or Nx graph. Time `vx run build --all` next to the tool you use today.

<Takeaway>measure vx on your own workspace, with your own tasks.</Takeaway>
