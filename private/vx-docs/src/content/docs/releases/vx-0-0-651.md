Everything vx prints now looks the same: one set of panels for a run,
`vx last`, `--dry`, every verb and every plugin. Your dependencies join
your configs in the lock, so a run never parses a lockfile.

This release is breaking. Read the [breaking changes](#breaking-changes) first.

## One look for everything vx prints

Each verb, the run screen and each plugin wrote its own lines, so the
same fact looked different in `vx run`, `vx why` and a plugin's verb.

Now one kit draws every line: panels stacked top to bottom, each a
title rule and its lines, written into the scrollback. Nothing to
press, nothing hidden. `vx last` replays a run as the run printed it:

## Plan a run in the same grid

`vx run --dry` printed its own list, so a plan read differently from
the run it planned.

Now it is a `Plan` panel in the run's grid. Each row says what the run
would do, its usual time and where it would run:

## Dependencies live in the lock

A run parsed your package manager's lockfile to key each task, every
time.

Now `vx lock` also writes `.vx/dependencies.lock.json`: each project's
edges and its dependency digest. Commit it beside
`.vx/projects.lock.json`. A run keys from the record and never parses
the lockfile. After an install, run `vx lock`:

```ansi
$ bun install
$ vx run build --all
[38;2;239;68;68m✗[0m [1mvx run[0m  bun.lock changed since `vx lock`: run `vx lock`
$ vx lock
[38;2;34;197;94m✓[0m [1mvx lock[0m  2 project configs → .vx/projects.lock.json
```

`--affected` reads the base commit's record, so a deleted project
selects only the projects that used it, not every project.
`vx lock --check` fails when the record is missing or stale.

See [vx lock](../../cli/lock/) and [Lockfiles](../../docs/lockfiles/).

## Other noteworthy changes

- A `file:` or `link:` dependency outside the repository is hashed like
  one inside it, so an edit there runs the task again.
- A tracked file rewritten to the same size in the second git recorded
  it is never replayed as a stale hit.
- A refused `vxCache()`, `vxHistory()` or `dte()` URL prints its
  `user:pass@` as `***`.
- The cache server keeps artifacts in `issuer/repo/branch` folders, so
  deleting one prefix prunes one branch.
- A distributed worker whose cache upload fails three times sends a
  fault: the task runs on another worker, and a second fault fails the run.
- On GitLab, `--affected` in a merged results pipeline compares with the
  target branch, and a merge train car with the car ahead.
- A Ctrl-C that lands as a task starts stops that task too.
- A typo gets a hint: a name in another case, a task id given to
  `--filter`, a `dependsOn` naming a task its project lacks.
- The [Conformance](../../conformance/) page scores vx, Turbo, Nx and
  Vite Task on the same cases.

## Breaking changes

Run `vx lock` after upgrading and commit `.vx/`. The first run resets
run history (schema `v51`; artifacts stay).

- A run refuses (`VX_E_LOCK`) when a claimed lockfile changed since `vx lock` or `.vx/dependencies.lock.json` is missing.
- `.vx/projects.lock.json` is version 5.
- Text layout of `vx show`, `vx why`, `vx last`, `vx init`, `vx run --dry` and the run summary changed; `--format json` did not. `vx last --format json` task rows gain `outputBytes`, `blocks` and `queuedMs`.
- The task grid's `waited` column → removed. `Logger.taskStart(node, info?)` → `taskStart(node)`.
- The façade's `ui` → the new kit: `report(title, rows)`, `table(columns, rows)`.
- A `vxCache()` scope on the wire is its ref, not its hash: deploy the cache server and `vxCache()` together. Artifacts stored before are not read again.
- `OidcOptions.fetchJson(url)` → `fetchJson(url, fresh)`.

See also [Upgrading](../../guides/upgrading/).
