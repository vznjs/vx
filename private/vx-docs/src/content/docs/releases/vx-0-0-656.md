On Linux, the vx installed from npm could not find the sandbox's helper.

A write the sandbox refused failed with the tool's own error and no word
from vx, and a task that swallowed the error passed.

This release puts the helper in the binary. Upgrade if you use
`exec.sandbox` on Linux.

**In this release**

- [The sandbox says what it refused](#the-sandbox-says-what-it-refused)

## The sandbox says what it refused

The sandbox watches a task's writes through a small helper program. A
run of vx from source found it beside the sandbox runtime.

The published binary bundles that runtime without the helper's file, so
it ran with no watcher. This is 0.0.655 on a build with no write grant:

```ansi
$ vx run build --all
[2m┌─[0m [1m[38;2;244;114;182mpackages/lib[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m>[0m [1m[38;2;239;68;68mfailed (exit 1)[0m
[2m$ mkdir -p dist && cp src/a.txt dist/[0m
[2m├─[0m [1mOUTPUT[0m [2m────────────────────────────────────────────────────[0m
[38;2;239;68;68mmkdir: cannot create directory 'dist': Read-only file system[0m
[2m└─[0m [1m[38;2;244;114;182mpackages/lib[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m──[0m [2m(51ms)[0m [1m[38;2;239;68;68mfailed (exit 1)[0m
```

Now the helper is inside the binary, which copies it once to
`~/.cache/vx/helpers/`. The same build names the write and the grant:

```ansi
$ vx run build --all
[2m┌─[0m [1m[38;2;244;114;182mpackages/lib[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m>[0m [1m[38;2;239;68;68mfailed (exit 1, 1 sandbox violation)[0m
[2m$ mkdir -p dist && cp src/a.txt dist/[0m
[2m├─[0m [1mOUTPUT[0m [2m────────────────────────────────────────────────────[0m
[38;2;239;68;68mmkdir: cannot create directory 'dist': Read-only file system[0m
[2m├─[0m [1m[38;2;239;68;68mSANDBOX VIOLATIONS (1)[0m [2m────────────────────────────────────[0m
mkdir(/home/user/acme/packages/lib/dist) = a write no grant covers  [/home/user/acme/packages/lib/dist]
[2mfix: exec.sandbox.allow: { write: ['dist/'] }[0m
[2m└─[0m [1m[38;2;244;114;182mpackages/lib[0m[2m#[0m[1m[38;2;244;114;182mbuild[0m [2m──[0m [2m(61ms)[0m [1m[38;2;239;68;68mfailed (exit 1, 1 sandbox violation)[0m
```

A task that hides its refused write (`2>/dev/null; true`) fails again,
so nothing it half did is cached.

Unix sockets are blocked again too: without the helper, a sandboxed task
could reach a socket such as Docker's with no `unixSockets` grant.

See [Sandboxing](../../docs/sandboxing/).

## Other noteworthy changes

- A sandbox that declares no read in its project (`sandbox: {}`) offers `read: ['.']` beside the one file a failed tool named.
- A sandboxed run no longer starts `npm root -g` to look for the helper.

## How to update

```sh frame="terminal"
vx upgrade
```
