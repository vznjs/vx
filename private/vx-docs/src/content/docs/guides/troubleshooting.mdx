## vx printed an error

| vx prints                                          | Fix                                                                     |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| `no .vx/workspace.ts in …` | The file marks the workspace root: run `vx init`, or add `.vx/workspace.ts` at the root. A file above the checkout does not count. |
| `… belongs to another user, so vx does not take its directory as your workspace` | Outside git, vx ignores a `.vx/workspace.ts` another user owns. Run vx in a checkout you own. |
| `not inside a project`                             | Run from a package directory, or pass `--all` or `--filter <pattern>`.  |
| `two projects are named "…": …` | Two directories got one name (a config's `name`, a plugin's, or the path): set another `name` in one's `vx.config.ts`, then `vx lock`. |
| `… locks …, but its … is gone` | A project's `vx.config.ts` was deleted or renamed since `vx lock`: run `vx lock`. A new config waits for it too. |
| `vx requires git: … is not inside a git work tree` | Run `git init` at the workspace root.                                   |
| `vx requires git: failed to spawn 'git'`           | Install git.                                                            |
| `--affected has no base here`                      | Set `baseBranch`, or pass `--affected=<ref>`.                           |
| `--affected has no default on the base branch`     | On `main` itself, run `--all`: the cache skips what did not change. `vx show` drops `--affected`. |
| `… has unknown field "<key>"`                      | A typo, or a Turbo or Nx key: the message lists the fields vx allows.  |
| `dependsOn cycle`                     | Remove one `dependsOn` edge of the loop it prints.                      |
| `dependsOn … but no such project or task is declared`  | Fix the name, or declare that task in that package.                 |
| `no projects declare task(s)`                      | A typo, a config edited since `vx lock`, or no config declares it: `vx show` lists every task. |
| `unknown flag`                                     | `vx run --help` lists the flags.                                        |
| `no projects matched filter(s)`                    | A typo: the message suggests the closest name. `vx show` lists every project. |
| `waiting for another vx run (pid …)`               | One run per workspace at a time: it starts when that one ends. Stop it, or wait. |
| `vx: command not found`                            | vx is not installed: `bunx @vzn/vx init` installs it, or `bun add -g @vzn/vx`. |

A typo in `--filter` names the closest project:

```sh
vx run build --filter @demo/ap
```

```ansi
[38;2;239;68;68m✗[0m [1mvx run[0m  no projects matched filter(s): @demo/ap

  [2mfix[0m  [1m@demo/app[0m
```

## vx did something unexpected

- **Only one package ran.** `vx run build` runs the package you are in
  and what it depends on. Add `--all`.
- **`0 tasks · build has no command in these projects`.** No selected
  package gives `build` a command, so vx ran only its default group.
  Give `build` an `exec.command` in the packages that build.
- **A task runs every time.** It has no `cache` block. `vx-migrate` leaves
  a `TODO(vx-migrate)` where it could not write one. Or a task it depends on declares no
  `inputs`: that task has no key, so nothing behind it hits. Give it
  `inputs`.
- **A task hit after you changed a file.** The file is not in
  `inputs.files`. `vx why <project#task>` shows what the key saw;
  [`exec.sandbox`](../../docs/sandboxing/), with reads granted no wider than
  the inputs, refuses that read and names it.
- **`inputs matched no files`.** The globs name nothing in the
  project, so the key ignores its source. Fix the paths; they are
  relative to the project directory.
- **`cache.outputs matched no files`.** The task wrote elsewhere, so a
  hit restores nothing. Point `outputs.files` at what the task writes;
  a sandboxed task also needs `exec.sandbox.allow.write` for it.
- **`not ready after …: waiting for a line matching`.** A persistent
  task's `readyWhen` has not matched its output yet. Fix the pattern,
  or set `exec.timeout` to bound the wait.
- **A task re-ran and you do not know why.** `vx why <project#task>`
  names the part of the key that changed:

  ```text
  $ vx why @demo/app#build
  @demo/app#build — run 01a1661e-7a89-74f6-918e-d96743474a51
    this run   2026-10-23T00:17:15.943Z · success · executed · key e45df494017b4fe9
    previous   2026-10-23T00:17:15.733Z · success · executed · key 3e6a03475b7efe74
    verdict    cache key changed: file packages/app/src/a.ts

    what changed (1 component, 2 unchanged):
      changed file  packages/app/src/a.ts  d00491fd7e5bb6fa28c517a0bb32b8b506539d4d → 0cfbf08886fca9a91cb753ec8734c84fcbe52c9f

    what to do:
      file  an edit re-runs by design; a file the task does not read belongs out of inputs.files
  ```
- **A variable is empty inside the command.** Past a small essential
  allowlist (`PATH`, `HOME`, `CI` and a few more), vx passes only what
  you list: add it to `exec.env.passThrough`
  ([Environment variables](../../docs/environment-variables/)).
- **`dist/` is empty after `tsc -b`.** With `rootDir: "src"`, tsc
  writes `tsconfig.tsbuildinfo` outside `dist/`. vx empties `dist/`
  before a run, tsc finds the buildinfo, and writes nothing.

  Add `tsconfig.tsbuildinfo` to `outputs.files`, or point
  `tsBuildInfoFile` into `dist/`.
- **The editor cannot resolve `@vzn/vx`.** Add it as a devDependency.
  vx itself runs a config without it.
- **A package has no `vx.config.ts`.** It gets a default `build`: a
  group behind `^build`, keyed on all its files, so editing it re-runs
  the packages that depend on it.
- **A package has nothing to build, but others depend on it.** Its
  default `build` waits on its own dependencies' builds.
  `build: { dependsOn: [] }` waits on nothing, but also drops its files
  from its dependents' keys: use it only when no dependent reads its
  source.

## Platforms

vx runs on Linux with glibc (not Alpine's musl) or macOS, in a git
repository (sha1 or sha256, files or reftable refs). The
release binary needs neither Node nor Bun.

<Tabs>
  <TabItem label="Linux">
    glibc, not Alpine's musl. The sandbox needs `bubblewrap`, `socat` and
    `ripgrep`.

    In a container, run as a user other than root, or set
    `exec.sandbox.weakerWhenNested: true` on each sandboxed task
    ([Sandboxing](../../docs/sandboxing/#requirements--platform-support)).
  </TabItem>
  <TabItem label="macOS">
    The sandbox is the system's own; nothing to install.
  </TabItem>
  <TabItem label="Windows">
    Run vx inside WSL2.
  </TabItem>
  <TabItem label="From source">
    Bun 1.4 or later.
  </TabItem>
</Tabs>

## Known limits

- On macOS the sandbox's report can miss records under load. Enforcement
  holds.
- A cache hit replays the first and last 8 MiB of a task's output.
- A `kill -9` of vx leaves its persistent tasks running, except a server
  that exits when its stdin closes (esbuild `--watch`).
- A process a task detaches into its own session (`setsid … &`) outlives
  Ctrl-C: vx signals the task's process group.
